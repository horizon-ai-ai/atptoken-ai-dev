<h2 id="representative-patterns-honest-not-a-roast">Representative patterns (honest, not a roast)</h2>
<p><strong>OpenRouter-class routing:</strong> excellent for developers who want one wallet across many models. Enterprise gaps usually appear at org hierarchy and project caps—see <a href="/en/blog/openrouter-vs-enterprise-governance">OpenRouter vs governance</a>.</p>
<p><strong>Observability (e.g. Helicone-class):</strong> answers “what happened to quality/latency.” Pair with a budget plane or the bill still surprises.</p>
<p><strong>Self-hosted (e.g. LiteLLM-class):</strong> maximum control, your ops burden. Governance still needs process and data model.</p>
<p><strong>ATP Token (governance plane):</strong> organization → workspace → project → key; allowlists; credits; request logs; multi-format clients. Limits: not a claim to replace every niche model marketplace feature; strength is enterprise control (<a href="/en/docs/overview">overview</a>).</p>
<h2 id="by-team-size-and-use-case">By team size and use case</h2>
<p><strong>Indie / prototype:</strong> routing hub.<br><strong>Product company, multi-squad:</strong> governance or router + strict process.<br><strong>Regulated enterprise:</strong> governance plane first; routing only inside allowlists.</p>
<p><strong>Coding agents:</strong> isolate projects (<a href="/en/blog/coding-agents-cost-control-checklist">coding agents checklist</a>).<br><strong>Multi-vendor production:</strong> gateway with settlement (<a href="/en/blog/enterprise-ai-cost-management-guide">cost management guide</a>).</p>
<h2 id="decision-tree">Decision tree</h2>
<ol>
<li>Single vendor, single team → direct API (<a href="/en/blog/openai-api-vs-enterprise-ai-gateway">vs gateway</a>).  </li>
<li>Many models, few people → routing hub.  </li>
<li>Many people, shared money → governance plane.  </li>
<li>Need evals → add observability, do not drop caps.</li>
</ol>
<h2 id="a-more-modern-approach">A more modern approach</h2>
<p>Stacks converge: routing features appear in gateways; gateways add traces. The durable question is <strong>who can spend, on which model, under which ceiling, with which log</strong>. ATP Token is built for that question inside Horizon AI adoption programs.</p>

<h2 id="faqs">FAQs</h2>
<h3 id="what-is-an-ai-gateway">What is an AI gateway?</h3>
<p>An AI gateway is middleware between applications and model providers that can handle authentication, routing, policy, metering, or observability—depending on the product—while applications keep a stable client interface.</p>
<h3 id="what-types-of-ai-gateways-exist-in-2026">What types of AI gateways exist in 2026?</h3>
<p>Three common clusters: routing hubs optimized for multi-model access and unified top-up; observability layers focused on traces and quality; and governance planes focused on org hierarchy, budgets, allowlists, and audit.</p>
<h3 id="how-do-i-choose-an-enterprise-ai-gateway">How do I choose an enterprise AI gateway?</h3>
<p>Start from failure modes: need project attribution, spending caps, and revoke paths, or mainly model variety. Score hierarchy depth, SDK compatibility, logging, and who owns the budget plane.</p>
<h3 id="is-litellm-the-same-as-an-enterprise-governance-platform">Is LiteLLM the same as an enterprise governance platform?</h3>
<p>Self-hosted routers solve developer access and routing flexibility. Enterprise governance adds organization structure, credit allocation, role-based admin, and finance-ready settlement that many routers leave to you.</p>
<h3 id="can-routing-and-governance-work-together">Can routing and governance work together?</h3>
<p>Yes. Some teams route through a developer hub in R&amp;D and put production on a governance plane. What fails is production traffic on an uncapped shared key with no project owner.</p>
