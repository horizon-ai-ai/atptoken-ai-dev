26:T3200,<p>An LLM gateway is a service that sits between your application and model providers, giving your code one API for many models while it handles keys, routing and failover, request logs and spend limits. This comparison covers six gateways teams shortlist in 2026, using the same checklist for each, with every pricing and feature claim linked to the vendor&#39;s own documentation as of October 2026.</p>
<h2 id="what-an-llm-gateway-does">What an LLM gateway does</h2>
<p>Five jobs, in the order a request meets them:</p>
<ol>
<li>One API for many models. Your code calls one base URL in a familiar format (usually OpenAI&#39;s) and switches models by changing the <code>model</code> field.</li>
<li>Authentication and keys. The gateway issues its own keys and keeps provider credentials out of your apps.</li>
<li>Access rules. It decides whether this key may call this model.</li>
<li>Routing and failover. It picks a provider for the model and retries elsewhere if one fails.</li>
<li>Metering, logs and limits. It records tokens and cost per request and stops traffic when a budget is reached.</li>
</ol>
<p>On ATP Token those stages map to status codes you can test: 401 for a bad key, 403 when the model isn&#39;t allowed for the <a class="doc-term" href="/docs/resources/" data-def="The unit that permissions and billing hang off — keys, allowed models, and credit budget all belong to one.">project</a>, 502 or 503 when providers fail, and 402 when the project&#39;s credits run out (<a href="/docs/how-it-works/">how it works</a>, <a href="/docs/errors/">errors</a>).</p>

<h2 id="how-to-choose-six-questions">How to choose: six questions</h2>
<h3 id="1-where-must-the-gateway-run">1. Where must the gateway run?</h3>
<p>If traffic cannot pass through a third party, the shortlist is self-hosted: the LiteLLM proxy, Helicone&#39;s open-source gateway, or Portkey&#39;s open-source and VPC options. Everything else on this page is hosted.</p>
<h3 id="2-how-do-you-want-to-pay">2. How do you want to pay?</h3>
<p>Three models exist:</p>
<ul>
<li>Provider price plus a fee on <a class="doc-term" href="/docs/topup/" data-def="Adding credits to the wallet. Minimum 5 USD, pay as you go.">top-ups</a>. OpenRouter: 5.5% on card purchases on Standard ($0.80 minimum), 8% on Business (<a href="https://openrouter.ai/docs/faq" target="_blank" rel="noopener noreferrer">FAQ</a>).</li>
<li>Provider list price, no token markup. Vercel AI Gateway; payment processing fees may apply (<a href="https://vercel.com/docs/ai-gateway/pricing" target="_blank" rel="noopener noreferrer">pricing</a>).</li>
<li>Prepaid credits at per-model list rates. ATP Token: 1 credit = USD 0.01, pay-as-you-go credits don&#39;t expire, top-ups from USD 5 (<a href="/docs/credits/" class="doc-term-def" data-def="The billing unit. 1 USD = 100 credits; usage converts at each model's list rate.">credits</a>). Rates per model are on the <a href="/pricing/">pricing page</a>.</li>
</ul>
<p>Self-hosted gateways add no fee, but your provider bills and engineering time are the cost.</p>
<h3 id="3-what-is-a-budget-attached-to-and-is-it-hard">3. What is a budget attached to, and is it hard?</h3>
<p>This is where gateways differ most.</p>
<ul>
<li>OpenRouter: budgets in guardrails per member or key, resetting daily, weekly or monthly; workspace budgets on Enterprise (<a href="https://openrouter.ai/docs/guides/features/guardrails" target="_blank" rel="noopener noreferrer">guardrails</a>).</li>
<li>Vercel: team, project, key and member budgets. Vercel calls them a soft cap: the request that crosses the limit still completes, then requests get 402 (<a href="https://vercel.com/docs/ai-gateway/observability-and-spend/budgets" target="_blank" rel="noopener noreferrer">budgets</a>).</li>
<li>LiteLLM: budgets per key, user, team or customer with reset durations like <code>30d</code>.</li>
<li>ATP Token: credits are allocated down organization → workspace → project, and a project can only spend its allocation. There is no reset period; the project runs until its balance is used, then gets 402 until someone allocates more (<a href="/docs/cb-budget-caps/">budget caps recipe</a>).</li>
</ul>
<p>A reset-period budget suits &quot;no more than $500 a month on this key&quot;. A prepaid allocation suits &quot;this product line has $5,000 for the quarter&quot;.</p>
<h3 id="4-which-sdk-formats-do-your-apps-already-use">4. Which SDK formats do your apps already use?</h3>
<p>Most gateways speak the OpenAI format. If some services use the Anthropic SDK (Claude Code does) or the Google GenAI SDK, check native support: OpenRouter and Vercel document Anthropic Messages; ATP Token accepts the OpenAI, Anthropic and Google GenAI SDKs unchanged (<a href="/docs/sdk-openai/">OpenAI SDK</a>, <a href="/docs/sdk-anthropic/">Anthropic SDK</a>, <a href="/docs/sdk-google/">Google GenAI SDK</a>).</p>
<h3 id="5-which-models-and-modalities">5. Which models and modalities?</h3>
<p>OpenRouter lists 500+ models from 80+ providers. ATP Token has 70+ models from 11 vendors, including video models such as <a href="/models/seedance-2-0/">Seedance 2.0</a> and <a href="/models/kling-v3-pro/">Kling v3 Pro</a> and image models such as <a href="/models/nano-banana-pro/">Nano Banana Pro</a> (<a href="/docs/media/">media models</a>). If you only need a handful of frontier LLMs, catalog size matters less than the other questions.</p>
<h3 id="6-what-does-the-log-keep-and-for-how-long">6. What does the log keep, and for how long?</h3>
<p>Portkey publishes retention per plan: 3 days of logs on the free tier, 30 days on Production. ATP Token keeps request logs for 7 days as a debugging view, with billing events as the billing record (<a href="/docs/console-api-logs/">request logs API</a>). If you review spend monthly, export or summarise weekly.</p>
<h2 id="each-gateway-in-more-detail">Each gateway in more detail</h2>
<h3 id="openrouter">OpenRouter</h3>
<ul>
<li>Fits: the widest hosted catalog and fast model evaluation.</li>
<li>Controls: organizations, workspaces, guardrails with budgets, model and provider allowlists, ZDR rules; per-key credit limits on all plans.</li>
<li>Watch out for: the fee on credit purchases, possible credit expiry after one year, invoicing only on Enterprise. Full breakdown in <a href="/blog/openrouter-vs-enterprise-governance/">OpenRouter alternatives for teams</a>.</li>
</ul>
<h3 id="vercel-ai-gateway">Vercel AI Gateway</h3>
<ul>
<li>Fits: teams on Vercel, or anyone wanting a hosted gateway priced at provider list price.</li>
<li>Controls: four budget scopes, spend alerts at 50/75/100%, request logs, provider and model fallbacks.</li>
<li>Watch out for: soft-cap budgets; spend on your own provider keys isn&#39;t counted against budgets; some controls are paid add-ons.</li>
</ul>
<h3 id="litellm">LiteLLM</h3>
<ul>
<li>Fits: platform teams who want full control and already run infrastructure.</li>
<li>Controls: virtual keys, budgets at several levels, access groups for models.</li>
<li>Watch out for: you operate it. Per-model budgets at user and key level need an Enterprise license.</li>
</ul>
<h3 id="portkey">Portkey</h3>
<ul>
<li>Fits: teams that want a gateway with observability and guardrails in one product.</li>
<li>Controls: budget limits on providers or virtual keys with alert thresholds and weekly or monthly reset, on Enterprise and select Pro plans (<a href="https://portkey.ai/docs/product/ai-gateway/virtual-keys/budget-limits" target="_blank" rel="noopener noreferrer">budget limits</a>). RBAC from the $49 Production plan.</li>
<li>Watch out for: log quotas per plan (10k logs a month free, 100k on Production).</li>
</ul>
<h3 id="helicone">Helicone</h3>
<ul>
<li>Fits: observability-first teams; the gateway is open source and written in Rust.</li>
<li>Controls: request logging with tokens and cost, routing, fallbacks, caching across 100+ models.</li>
<li>Watch out for: check budget and access-control features against your requirements; we did not find them in the gateway overview.</li>
</ul>
<h3 id="atp-token">ATP Token</h3>
<ul>
<li>Fits: companies where several teams share one AI budget and each project should have a funded allocation and a reviewed model list.</li>
<li>Controls: organization → workspace → project hierarchy, project-scoped keys, per-project allowed models, credit allocation as the ceiling, per-request logs, owner/admin/member roles (<a href="/docs/team/">team and roles</a>).</li>
<li>Watch out for: a smaller catalog than OpenRouter; credits are non-refundable; request logs are kept 7 days.</li>
</ul>
<h2 id="running-two-gateways">Running two gateways</h2>
<p>Many teams end up with two: a large-catalog gateway for research and evaluation, and a governed one for production. The rule that keeps this sane is that production keys never live in the research account, and each production service has its own key and budget. See <a href="/blog/one-project-one-key/">one project, one key</a>.</p>
<h2 id="trying-the-comparison-on-atp-token">Trying the comparison on ATP Token</h2>
<ol>
<li>Create a project and enable two or three models you want to compare, for example <a href="/models/claude-sonnet-4-6/">claude-sonnet-4-6</a>, <a href="/models/gemini-3-5-flash/">gemini-3-5-flash</a> and <a href="/models/deepseek-v4-flash/">deepseek-v4-flash</a>.</li>
<li>Allocate a small amount of credits, say 500 (USD 5), as the ceiling for the test.</li>
<li>Point your existing OpenAI, Anthropic or Google GenAI client at the gateway and run the same prompts against each model.</li>
<li>Compare tokens and credits per request in Request logs (<a href="/docs/monitoring/">usage and logs</a>). Side-by-side model pages are at <a href="/compare/gemini-vs-gpt/">/compare</a>.</li>
</ol>
