<h2 id="how-ai-agent-cost-adds-up-a-20-step-example">How AI agent cost adds up: a 20-step example</h2>
<p>Assume an agent that starts each task with an 8,000-token base (system prompt, tool definitions, task). Every step appends about 2,000 tokens of tool results and model output, and every step writes 500 output tokens. Step <em>i</em> therefore reads 8,000 + 2,000 × (i − 1) input tokens.</p>
<p>Input tokens over 20 steps:</p>
<p>Σ = 20 × 8,000 + 2,000 × (0 + 1 + … + 19) = 160,000 + 2,000 × 190 = <strong>540,000 tokens</strong></p>
<p>Output tokens: 20 × 500 = 10,000.</p>
<p>The base is only 30% of that input (160,000 of 540,000). The other 70% is the same tool results being read again on later steps. The last 8 steps alone read 312,000 tokens, more than the first 12 combined (228,000).</p>

<p>The same base context answered in one turn costs 8,000 × $3/M + 500 × $15/M = $0.024 + $0.0075 = $0.0315 on claude-sonnet-4-6. The agent task costs about 56 times as much. That multiple is the agent tax: the rate card did not change, the number of tokens did.</p>
<p>Anthropic publishes one real-world data point: in Claude Code, agent teams use &quot;approximately 7x more tokens than standard sessions&quot; when teammates run in plan mode, because each teammate keeps its own context window (<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code costs</a>).</p>
<h2 id="five-levers-that-cut-the-agent-tax">Five levers that cut the agent tax</h2>
<h3 id="1-cap-steps">1. Cap steps</h3>
<p>Input grows roughly with the square of the step count, so the late steps are the expensive ones. Set a hard maximum and return a clear failure when it is reached. If the same task fits in 12 steps, input drops to 12 × 8,000 + 2,000 × 66 = 228,000 tokens and the task costs $0.77 instead of $1.77.</p>
<h3 id="2-summarise-tool-output-before-it-enters-the-context">2. Summarise tool output before it enters the context</h3>
<p>Replace raw file contents and full API responses with a short summary or the lines that matter. If growth per step falls from 2,000 to 500 tokens, input becomes 160,000 + 500 × 190 = 255,000 tokens: $0.765 + $0.15 = $0.92 per task, 48% less.</p>
<h3 id="3-run-sub-steps-on-a-cheaper-model">3. Run sub-steps on a cheaper model</h3>
<p>Many steps only read a tool result and decide what to call next. Keep the decisions on claude-sonnet-4-6 and route the rest to deepseek-v4-flash. With 6 decision steps and 14 sub-steps, each averaging 27,000 input tokens:</p>
<ul>
<li>Sonnet: 162,000 × $3/M + 3,000 × $15/M = $0.486 + $0.045 = $0.531</li>
<li>Flash: 378,000 × $0.2/M + 7,000 × $0.4/M = $0.0756 + $0.0028 = $0.078</li>
<li>Total: about $0.61 per task, 66% less than all-Sonnet</li>
</ul>
<p>Test quality on your own tasks before switching; the <a href="/compare/deepseek-vs-claude/">DeepSeek vs Claude comparison</a> is a starting point.</p>
<h3 id="4-use-prompt-caching-where-your-provider-supports-it">4. Use prompt caching where your provider supports it</h3>
<p>Most of an agent&#39;s input is a prefix it already sent one step earlier. On Anthropic&#39;s own API, a cache read costs 0.1× the base input rate and a 5-minute cache write costs 1.25× (<a href="https://platform.claude.com/docs/en/about-claude/pricing" target="_blank" rel="noopener noreferrer">Anthropic pricing</a>). In the 20-step example, 494,000 of the 540,000 input tokens are repeats. At Anthropic&#39;s Sonnet 4.6 rates that is 494,000 × $0.30/M + 46,000 × $3.75/M + $0.15 output = $0.148 + $0.173 + $0.15, about $0.47 per task. The cache expires after its lifetime, so a step that waits on a slow tool can miss it. Check how your provider meters cached tokens before counting on this lever.</p>
<h3 id="5-give-each-agent-its-own-budget">5. Give each agent its own budget</h3>
<p>Put each agent in its own <a class="doc-term" href="/docs/resources/" data-def="The unit that permissions and billing hang off — keys, allowed models, and credit budget all belong to one.">project</a> and allocate <a class="doc-term" href="/docs/credits/" data-def="The billing unit. 1 USD = 100 credits; usage converts at each model's list rate.">credits</a> to it. A project can only spend what it was allocated, and requests return <code>402</code> once the balance is used up, so a stuck loop stops at the ceiling instead of at month-end. At 10,000 Sonnet tasks a month, the allocation is 1,770,000 credits (1 credit = USD 0.01). Setup: <a href="/docs/cb-budget-caps/">team with budget caps</a>.</p>
<h2 id="how-to-measure-cost-per-completed-task">How to measure cost per completed task</h2>
<p>The gateway sees requests; only your application knows which requests belong to one task. Every ATP response carries an <code>x-request-id</code> header. Log it next to your own task or session ID, the step number, and whether the task ultimately succeeded.</p>
<p>Then:</p>
<ol>
<li>Pull the rows for those request IDs from Request logs, which show model, status, and input/output tokens per request (<a href="/docs/monitoring/">usage and logs</a>). Retention is 7 days, so export weekly with the <a href="/docs/console-api-logs/">request logs endpoint</a>.</li>
<li>Multiply tokens by the model&#39;s list rate and sum per task.</li>
<li>Divide total cost, including failed and abandoned tasks, by the number of completed tasks.</li>
</ol>
<p>Failed tasks belong in the numerator. An agent that succeeds 80% of the time at $1.77 per attempt costs $1.77 / 0.8 = $2.21 per completed task.</p>
<p>Watch for one pattern in the logs: a <code>200</code> with empty content. On reasoning models this usually means <code>max_tokens</code> was too low for the thinking budget. ATP typically reports zero usage and deducts no credits for it, but an agent that retries without raising <code>max_tokens</code> will repeat the empty call (<a href="/docs/errors/">errors</a>).</p>
