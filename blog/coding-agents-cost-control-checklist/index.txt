<h2 id="how-claude-code-is-billed">How Claude Code is billed</h2>
<p>As of October 2026, Anthropic&#39;s <a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code costs page</a> reports that across enterprise deployments the average is around $13 per developer per active day and $150–250 per developer per month, and that 90% of users stay below $30 per active day. Anthropic recommends a small pilot group to establish your own baseline before a wider rollout.</p>
<p>How that cost reaches you depends on how developers sign in. Pro and Max subscribers have usage included in the subscription. On Team and Enterprise plans, each member draws from a per-seat allowance that resets on a rolling five-hour window and a weekly window, shared with Claude chat; members can continue past it only if an admin turns on usage <a class="doc-term" href="/docs/credits/" data-def="The billing unit. 1 USD = 100 credits; usage converts at each model's list rate.">credits</a>. Through the Claude Console, a cloud provider, or a gateway such as ATP Token, Claude Code is billed per token to the <a class="doc-term" href="/docs/console-setup/" data-def="The top level of an account. Workspaces and projects sit underneath it.">organization</a>.</p>
<p>This article is about the per-token case, where nothing stops a session except a ceiling you set yourself.</p>
<h2 id="claude-code-cost-for-a-25-developer-team-worked-out">Claude Code cost for a 25-developer team, worked out</h2>
<p>Take 25 developers who each use Claude Code on 20 working days a month, at Anthropic&#39;s $13 average:</p>
<p>25 developers × 20 active days × $13 = <strong>$6,500 per month</strong></p>
<p>That is $260 per developer, slightly above Anthropic&#39;s $150–250 monthly band, because 20 active days assumes everyone uses it every working day.</p>

<h2 id="10-controls-for-claude-code-spend">10 controls for Claude Code spend</h2>
<h3 id="1-give-coding-agents-their-own-project">1. Give coding agents their own project</h3>
<p>Create a <a class="doc-term" href="/docs/resources/" data-def="The unit that permissions and billing hang off — keys, allowed models, and credit budget all belong to one.">project</a> only for Claude Code (and other coding agents), separate from the project your production services use. Every key in a project spends from that project&#39;s balance, so an agent that loops all night cannot drain the budget a customer-facing service depends on. The pattern is described in <a href="/blog/one-project-one-key/">one project, one key</a>.</p>
<h3 id="2-issue-one-key-per-developer-inside-it">2. Issue one key per developer inside it</h3>
<p>Keys belong to exactly one project and inherit its allowed models and balance. With one key per person, the Usage page shows credits and tokens by key, which is per-developer spend without extra tooling. Keys start with <code>atp-</code> and the secret is shown once (<a href="/docs/console-keys/" class="doc-term-def" data-def="A key that starts with atp-. It inherits its project's allowed models and credit balance.">managing API keys</a>).</p>
<h3 id="3-treat-the-allocation-as-the-monthly-ceiling">3. Treat the allocation as the monthly ceiling</h3>
<p>Allocate the heavy-tail figure from the table, 780,000 credits, to the project. A project can only spend what it was allocated; once the balance is gone, requests return <code>402</code> until an admin allocates more. If you turn on project auto top-up, set its monthly cap too, or the ceiling stops being one. Setup steps are in <a href="/docs/cb-budget-caps/">team with budget caps</a>.</p>
<h3 id="4-allowlist-claude-sonnet-4-6-put-opus-in-a-separate-project">4. Allowlist claude-sonnet-4-6; put Opus in a separate project</h3>
<p>Enable only <a href="/models/claude-sonnet-4-6/">claude-sonnet-4-6</a> on the main coding project. At ATP list rates it is $3 input and $15 output per million tokens; <a href="/models/claude-opus-4-8/">claude-opus-4-8</a> is $5 and $25, so every token costs about 1.67× more. If someone switches to a model the project does not allow, the gateway rejects the call with <code>403</code> before it reaches any provider. Developers who need Opus for architecture work get a second project with a small allocation, such as 50,000 credits.</p>
<h3 id="5-pin-anthropic_model">5. Pin ANTHROPIC_MODEL</h3>
<p>Set <code>ANTHROPIC_MODEL=&quot;claude-sonnet-4-6&quot;</code> in each developer&#39;s environment or in the <code>env</code> block of <code>~/.claude/settings.json</code>. The <code>--model</code> flag overrides <code>ANTHROPIC_MODEL</code> for a session, so pinning sets the default and the allowlist in control 4 enforces it.</p>
<h3 id="6-make-usage-and-clear-a-habit">6. Make /usage and /clear a habit</h3>
<p>The Session block of <code>/usage</code> shows token usage and a dollar estimate that Claude Code computes locally at list price. The ATP Usage page shows what the project was actually charged. Anthropic&#39;s advice for keeping it low:</p>
<ul>
<li>Run <code>/clear</code> when switching to unrelated work. Stale context is re-sent with every message, and <code>/clear</code> costs nothing.</li>
<li>Lower the effort level with <code>/effort</code> for simple tasks. Thinking tokens are billed as output tokens.</li>
<li>Keep <code>CLAUDE.md</code> short and move specialised instructions into skills that load on demand.</li>
</ul>
<h3 id="7-cap-headless-runs-with-max-budget-usd-and-max-turns">7. Cap headless runs with --max-budget-usd and --max-turns</h3>
<p>For CI jobs and scripts, Claude Code&#39;s <a href="https://code.claude.com/docs/en/cli-reference" target="_blank" rel="noopener noreferrer">CLI reference</a> documents two print-mode flags. <code>--max-budget-usd</code> stops the run once its estimated spend, including subagents, reaches the amount. <code>--max-turns</code> exits after a fixed number of agentic turns.</p>
<pre><code>claude -p --max-budget-usd 5.00 --max-turns 30 &quot;fix the failing tests in src/auth&quot;
</code></pre>
<p>This is a per-run stop on the client side. The project allocation remains the server-side ceiling for the job that retried a flaky test all night.</p>
<h3 id="8-keep-agent-teams-opt-in">8. Keep agent teams opt-in</h3>
<p>Agent teams are disabled by default and switched on with <code>CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1</code>. At roughly 7× the tokens of a standard session in plan mode, one developer running an agent team spends about what seven developers spend in standard sessions. Allow it in a separate project with its own allocation, and ask teams to use Sonnet for teammates and shut them down when the task is done.</p>
<h3 id="9-review-spend-weekly-from-request-logs">9. Review spend weekly from request logs</h3>
<p>Every Monday, open the Usage page sorted by key and by model, then check Request logs for the same week. Each row shows time, scope, model, status, request ID, and input/output tokens. Request-log retention is 7 days, so a weekly review is the longest gap that still sees every request; to keep history, pull the rows with the <a href="/docs/console-api-logs/">request logs endpoint</a>. Look for keys above 2× the team median, models outside the plan, and runs of <code>4xx</code> or <code>5xx</code> statuses.</p>
<h3 id="10-revoke-keys-on-offboarding">10. Revoke keys on offboarding</h3>
<p>When a contractor leaves, revoke their key from the API keys page. A revoked key stops working immediately and stays in the roster for audit, and because each developer has their own key, nobody else&#39;s session breaks.</p>
<p>For the economics behind controls 6 to 8, see <a href="/blog/what-is-the-agent-tax/">what is the agent tax</a>. For which model to allowlist for which job, see the <a href="/guides/best-llm-for-coding/">best LLM for coding guide</a>.</p>
<h2 id="setting-up-claude-code-on-atp-token">Setting up Claude Code on ATP Token</h2>
<h3 id="step-1-create-the-project-and-allocation">Step 1: Create the project and allocation</h3>
<p>In the console, create a workspace and a project named for the team (for example <code>claude-code-platform</code>), enable <code>claude-sonnet-4-6</code> as the only allowed model, and allocate the monthly credits.</p>
<h3 id="step-2-issue-a-key-per-developer">Step 2: Issue a key per developer</h3>
<p>Create one key per person from the project and send each secret through your password manager. It is shown only once.</p>
<h3 id="step-3-point-claude-code-at-the-gateway">Step 3: Point Claude Code at the gateway</h3>
<p>The base URL has no <code>/v1</code>, because Claude Code appends <code>/v1/messages</code> itself. Clear <code>ANTHROPIC_API_KEY</code> so it does not take precedence.</p>
<pre><code>export ANTHROPIC_BASE_URL=&quot;https://api.atptoken.ai&quot;
export ANTHROPIC_AUTH_TOKEN=&quot;atp-...&quot;
export ANTHROPIC_API_KEY=&quot;&quot;
export ANTHROPIC_MODEL=&quot;claude-sonnet-4-6&quot;   # any model from GET /v1/models
claude
</code></pre>
<p>The same values can go under the <code>env</code> block of <code>~/.claude/settings.json</code>.</p>
<h3 id="step-4-verify">Step 4: Verify</h3>
<p>Run one prompt, then open the console. The call appears under Request logs and the credits appear on the Usage page. Full steps: <a href="/docs/cb-claude-code/">run Claude Code on ATP</a>.</p>
