<h2 id="openrouter-pricing-as-of-october-2026">OpenRouter pricing (as of October 2026)</h2>
<p>OpenRouter does not add a markup to token prices. It says it passes through the price of the underlying provider and charges when you buy credits (<a href="https://openrouter.ai/docs/faq" target="_blank" rel="noopener noreferrer">FAQ</a>):</p>
<ul>
<li>Standard (pay-as-you-go): 5.5% fee on card purchases, minimum $0.80. Crypto: 5%.</li>
<li>Business: 8%. Enterprise: negotiated.</li>
<li>Bring your own provider key (BYOK): no fee on the first $25,000 of list-price inference per month on Standard and Business, 5% after that.</li>
</ul>
<p>Two quick examples. Buying $1,000 of credits by card on Standard costs $1,055. Buying $10 costs $10.80, because the $0.80 minimum is higher than 5.5%.</p>
<p>Two terms matter for finance teams. OpenRouter reserves the right to expire unused credits one year after purchase, and refunds for unused credits must be requested within 24 hours. Invoicing is listed only on the Enterprise plan.</p>
<h2 id="what-openrouter-already-does-for-teams">What OpenRouter already does for teams</h2>
<p>Some comparisons, including an earlier version of this article, describe OpenRouter as a developer wallet without team controls. That is out of date.</p>
<ul>
<li><a class="doc-term" href="/docs/console-setup/" data-def="The top level of an account. Workspaces and projects sit underneath it.">Organizations</a> share central credits; only admins buy credits and change billing, provider and privacy settings.</li>
<li><a href="https://openrouter.ai/docs/guides/features/workspaces" target="_blank" rel="noopener noreferrer">Workspaces</a> separate API keys, routing defaults, guardrails and observability, for example staging and production.</li>
<li><a href="https://openrouter.ai/docs/guides/features/guardrails" target="_blank" rel="noopener noreferrer">Guardrails</a> attach to a member or a key and can combine a USD budget that resets daily, weekly or monthly, a model allowlist, a provider allowlist, zero-data-retention rules and prompt-injection or PII filters. When several apply, the strictest wins.</li>
<li>Every API key can have its own credit limit, on any plan.</li>
<li>Activity logs and export are available on all plans, grouped by model, key or member.</li>
<li>Claude Code can point at OpenRouter&#39;s Anthropic-compatible endpoint (<a href="https://openrouter.ai/docs/guides/guides/claude-code-integration" target="_blank" rel="noopener noreferrer">setup guide</a>).</li>
</ul>
<p>If those controls cover your needs and the fee is acceptable, staying on OpenRouter is reasonable.</p>
<h2 id="why-teams-look-for-an-alternative">Why teams look for an alternative</h2>
<p>Common reasons, each tied to a documented difference:</p>
<ol>
<li>The gateway has to run inside the company network, or traffic may only go to provider accounts the company owns.</li>
<li>Finance wants budgets attached to a product or cost center. On OpenRouter below Enterprise, budgets attach to members and keys; workspace budgets need Enterprise.</li>
<li>Finance wants prepaid credits that don&#39;t expire, allocated to each project in advance.</li>
<li>Some apps use the Google GenAI SDK, and the team wants a gateway that accepts that format so the apps don&#39;t need rewriting.</li>
</ol>
<p>Each alternative below answers a different subset of these.</p>
<h2 id="the-alternatives-one-by-one">The alternatives, one by one</h2>
<h3 id="litellm-self-hosted-proxy">LiteLLM: self-hosted proxy</h3>
<ul>
<li>Fits: teams that must keep the gateway in their own cloud or VPC and already have provider accounts.</li>
<li>Pricing: the open-source proxy is free; you pay providers directly plus the cost of running it. Some features, such as per-model budgets at the user and key level, need an Enterprise license.</li>
<li>Controls: budgets per key, user, team and customer with reset periods such as <code>30d</code>; model access through access groups.</li>
<li>Watch out for: you own uptime, database, upgrades and security reviews. Anthropic&#39;s Claude Code docs mention enterprises using LiteLLM to track spend per key and note that it is unaffiliated with Anthropic and not audited by them (<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">source</a>).</li>
</ul>
<h3 id="vercel-ai-gateway-hosted-priced-at-provider-list-price">Vercel AI Gateway: hosted, priced at provider list price</h3>
<ul>
<li>Fits: teams already deploying on Vercel, or anyone who wants a hosted gateway without a platform fee on tokens.</li>
<li>Pricing: no markup or platform fee on tokens; payment processing fees may apply; invoicing on Enterprise (<a href="https://vercel.com/docs/ai-gateway/pricing" target="_blank" rel="noopener noreferrer">pricing</a>).</li>
<li>Controls: budgets per team, project, API key or member, resetting daily, weekly, monthly or never; HTTP 402 when exceeded; email alerts at 50, 75 and 100%.</li>
<li>Watch out for: Vercel describes budgets as a soft cap, so the request that crosses the limit still completes. Spend through your own provider keys is not counted in budgets. A team-wide provider allowlist costs $0.10 per 1,000 requests.</li>
</ul>
<h3 id="atp-token-prepaid-project-budgets-and-per-project-model-allowlists">ATP Token: prepaid project budgets and per-project model allowlists</h3>
<ul>
<li>Fits: companies where several teams share one AI budget and finance wants each project funded in advance and limited to a reviewed list of models.</li>
<li>Pricing: usage is metered on input and output tokens at each model&#39;s list rate and paid from credits. 1 credit = USD 0.01, top-ups start at USD 5, and pay-as-you-go credits don&#39;t expire (<a href="/docs/credits/" class="doc-term-def" data-def="The billing unit. 1 USD = 100 credits; usage converts at each model's list rate.">credits</a>, <a href="/docs/topup/" class="doc-term-def" data-def="Adding credits to the wallet. Minimum 5 USD, pay as you go.">top up</a>, <a href="/pricing/">pricing</a>).</li>
<li>Controls: credits flow from organization to workspace to project, and a project can only spend what it was allocated. When the balance is used up, requests return 402. Each project has an allowed-model list; a request for any other model returns 403 before it reaches a provider (<a href="/docs/how-it-works/">how it works</a>).</li>
<li>Formats: official OpenAI, Anthropic and Google GenAI SDKs unchanged, by changing the base URL and key (<a href="/docs/sdk-openai/">OpenAI SDK</a>, <a href="/docs/sdk-google/">Google GenAI SDK</a>).</li>
<li>Watch out for: a smaller catalog than OpenRouter (70+ models from 11 vendors, against 500+). Credits are non-refundable. Request logs are kept for 7 days, so export what you need for monthly reviews.</li>
</ul>
<p>Portkey and Helicone are also common names on &quot;OpenRouter alternatives&quot; lists; they are covered in the <a href="/blog/ai-gateway-comparison-2026/">LLM gateway comparison</a>.</p>

<h2 id="moving-an-openrouter-integration-to-atp-token">Moving an OpenRouter integration to ATP Token</h2>
<p>If your code uses the OpenAI SDK against OpenRouter, the move is a base URL, a key and model ids.</p>
<ol>
<li>In the console, create a project and pick its allowed models, for example <a href="/models/claude-sonnet-4-6/">claude-sonnet-4-6</a> and <a href="/models/deepseek-v4-flash/">deepseek-v4-flash</a> (<a href="/docs/resources/" class="doc-term-def" data-def="The list of models a project may call. Anything outside it returns 403.">workspaces and projects</a>).</li>
<li>Allocate credits to the project. That amount is its ceiling (<a href="/docs/cb-budget-caps/">budget caps recipe</a>).</li>
<li>Create a key for the project. It starts with <code>atp-</code> and is shown once (<a href="/docs/console-keys/" class="doc-term-def" data-def="A key that starts with atp-. It inherits its project's allowed models and credit balance.">managing keys</a>).</li>
<li>Change the client and the model id. OpenRouter ids carry a vendor prefix (<code>vendor/model</code>); ATP ids come from <code>GET /v1/models</code>.</li>
</ol>
<pre><code>from openai import OpenAI

# Before: OpenAI(base_url=&quot;https://openrouter.ai/api/v1&quot;, api_key=&quot;sk-or-...&quot;)
client = OpenAI(base_url=&quot;https://api.atptoken.ai/v1&quot;, api_key=&quot;atp-...&quot;)

r = client.chat.completions.create(
    model=&quot;claude-sonnet-4-6&quot;,
    messages=[{&quot;role&quot;: &quot;user&quot;, &quot;content&quot;: &quot;Summarize this ticket in two lines.&quot;}],
)
print(r.choices[0].message.content)
</code></pre>
<ol start="5">
<li>Send a test request and confirm it appears in Request logs with its input and output tokens (<a href="/docs/monitoring/">usage and logs</a>).</li>
</ol>
<p>Claude Code moves the same way with four environment variables (<a href="/docs/cb-claude-code/">Claude Code on ATP</a>).</p>
