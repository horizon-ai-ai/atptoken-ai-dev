25:T467,<p>The model goes in the <strong>URL</strong>, not in the body. <code>{model}</code> is an id from <code>GET /v1beta/models</code>, which lists what these routes accept — for example <code>gemini-3-5-flash-lite</code>. The full list for your <a class="doc-term" href="/docs/resources/" data-def="The unit that permissions and billing hang off — keys, allowed models, and credit budget all belong to one.">project</a> is <a href="/docs/models/">GET /v1/project/models</a>.</p>
<p>You cannot tell the entry point from a model&#39;s name. <code>gemini-3-5-flash</code> is served on <code>/v1/chat/completions</code>, while <code>gemini-3-5-flash-lite</code> is served here. Call a model on the wrong entry point and you get <code>422</code> with a message that names the right one.</p>
<h2 data-md="h2" id="authentication" class="group">Authentication<a href="#authentication" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>All of these work; use whichever your client sends. See <a href="/docs/auth/">Authentication</a>.</p>26:T795,<p><code>contents</code>, <code>systemInstruction</code> and <code>generationConfig</code> (for example <code>maxOutputTokens</code>, <code>temperature</code>) use the Gemini field names.</p>
<p>Other top-level fields include tools, tool config, safety settings, cached content and labels. The Gateway forwards fields as they are, so one model may accept a field that another rejects.</p>
<h3 data-md="h3" id="files" class="group">Files<a href="#files" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<ul>
<li>Send images, audio and documents inline as <code>inlineData</code> (base64).</li>
<li>Or send <code>fileData</code> with a <code>fileUri</code> the model can read — your own bucket or a Gemini File API URI, forwarded unchanged.</li>
<li>A file uploaded to the Gateway (<code>an_&lt;ulid&gt;</code>) <strong>cannot</strong> be used on this entry point: referencing it returns <code>404 file_unavailable_for_failover</code>. Embed the bytes with <code>inlineData</code> instead.</li>
</ul>
<h3 data-md="h3" id="tool-calls" class="group">Tool calls<a href="#tool-calls" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>Declare tools in <code>tools[].functionDeclarations</code>. The model&#39;s call comes back as a <code>functionCall</code> part, and you return the result as a <code>functionResponse</code> part in a <code>user</code> turn, matched by <strong>name</strong> (there is no id). The assistant role on this entry point is <code>model</code>, not <code>assistant</code>.</p>
