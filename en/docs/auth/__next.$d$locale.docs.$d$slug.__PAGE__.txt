3:T672,<p>The Gateway reads your <a class="doc-term" href="/docs/console-keys/" data-def="A key that starts with atp-. It inherits its project's allowed models and credit balance.">project API key</a> from any of the locations below. <code>Authorization: Bearer</code> and <code>x-api-key</code> both work on every endpoint, so the official OpenAI, Anthropic and Google GenAI SDKs work unchanged — only the base URL changes. The Gateway strips the key before forwarding the request.</p>
<h2 data-md="h2" id="get-a-key-first" class="group">Get a key first<a href="#get-a-key-first" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>Keys are not issued by the API. Sign in at <a href="https://atptoken.ai" target="_blank" rel="noopener noreferrer">atptoken.ai</a>, then pick or create an <a class="doc-term" href="/docs/console-setup/" data-def="The top level of an account. Workspaces and projects sit underneath it.">organization</a> → a <a class="doc-term" href="/docs/resources/" data-def="A grouping inside an organization, used to keep teams or environments apart.">workspace</a> → a project, and create the key inside that project. A key belongs to one project: that project decides which models the key may call and whose balance it uses. See <a href="/docs/console-keys/">Managing API keys</a>.</p>
<h2 data-md="h2" id="where-the-key-goes" class="group">Where the key goes<a href="#where-the-key-goes" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>4:Tea6,<h2 data-md="h2" id="when-authentication-fails" class="group">When authentication fails<a href="#when-authentication-fails" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>A missing, disabled, expired or unknown key returns <code>401</code> with <code>token_revoked</code> — &quot;API key has been revoked or does not exist&quot;. <strong>Sending no key at all returns the same error</strong>, so first check that the header actually went out, then suspect the key.</p>
<p>A <code>403</code> is a different problem: the key is fine, but the model is not on its project&#39;s allowed list. See <a href="/docs/errors/">Error codes</a>.</p>
<h2 data-md="h2" id="signing-in-to-the-console" class="group">Signing in to the console<a href="#signing-in-to-the-console" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>Issuing a key, topping up and reading the Console API all start the same way: a person signs in at <a href="https://atptoken.ai" target="_blank" rel="noopener noreferrer">atptoken.ai</a>. Two rules about that sign-in are worth knowing before you build anything around it.</p>
<h3 data-md="h3" id="sign-in-asks-you-to-prove-you-are-human" class="group">Sign-in asks you to prove you are human<a href="#sign-in-asks-you-to-prove-you-are-human" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>Signing in requires a human-verification check, and a browser is the only thing that can answer it. A request without an answer is refused with <code>400</code> and <code>reason: &quot;captcha_required&quot;</code>; one whose answer does not check out is refused with <code>400</code> and <code>captcha_invalid</code>.</p>
<p>It is there because people were being locked out of their own accounts. Scripts guessed passwords account by account, and the only brake was a per-account attempt limit — which stopped the real holder from signing in and did nothing to the script, since it simply moved to the next account. The check stops that run at its first request. A failed check costs you nothing: your attempt counter moves only when a password is actually wrong.</p>
<p>The check runs on every sign-in. There is no threshold to cross first, and no exemption to apply for.</p>
<h3 data-md="h3" id="linking-a-sign-in-provider-closes-the-password-path" class="group">Linking a sign-in provider closes the password path<a href="#linking-a-sign-in-provider-closes-the-password-path" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>You can attach an external sign-in provider to your account and use it instead of a password. Attaching the first one asks for the same human-verification check, and it changes the account: the account becomes passwordless and the stored password is deleted. The password you remember stops being a way in — not suspended, deleted.</p>
<p>Attaching a second provider later changes nothing further, because the password went with the first one.</p>
<p>Getting the password path back is an administrator&#39;s action: they put the account back into password mode, and you then set a new password through &quot;Forgot password&quot;. Nothing you can do from your own account recovers the old one.</p>
<p>When you sign in with a password and have no provider attached, the console offers to attach one.
