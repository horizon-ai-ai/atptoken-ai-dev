25:T677,<h2 data-md="h2" id="200-with-empty-content" class="group">200 with empty content<a href="#200-with-empty-content" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>A request can return <code>200 OK</code> with an empty message — no error, just no text. This is almost always driven by request parameters, not a failure. The most common cause is a <code>max_tokens</code> that is too low for a reasoning (extended-thinking) model: the entire budget is consumed by internal reasoning before any visible output is produced, so the content comes back empty.</p>
<p>On this platform that request typically reports <strong>zero token usage and deducts no credits</strong> — an empty <code>200</code> with an empty <code>usage</code> object is the signature of this case, not a billing bug. Fix it by raising <code>max_tokens</code> so it covers the model&#39;s thinking budget plus your expected output, or turn extended thinking off. Always check <code>finish_reason</code> / <code>stop_reason</code> and <code>usage</code> before assuming text exists.</p>
<p>A <code>200</code> also does not prove the model saw everything you sent. A request missing a message is still valid and still <code>200</code>, and a message in a format that does not belong to the endpoint (for example OpenAI&#39;s <code>role: &quot;tool&quot;</code> sent to <code>/v1/messages</code>) is forwarded as is — some models read it, others return <code>200</code> and ignore it.
