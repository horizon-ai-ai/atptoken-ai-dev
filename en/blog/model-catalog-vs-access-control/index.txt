26:T2307,<p>A model catalog is the list of model ids a platform can serve, and model access control is the rule that decides which of those ids a given key may call. On ATP Token, <code>GET /v1/models</code> returns the catalog, and the project&#39;s allowed-model list is checked on every request, with a 403 before any provider is contacted. This post shows the request and response, explains what the 403 means, compares OpenAI and OpenRouter, and gives four allowlists with their list rates.</p>
<h2 id="two-different-questions">Two different questions</h2>
<table>
<thead>
<tr>
<th>Question</th>
<th>Where ATP Token answers it</th>
<th>When the answer is no</th>
</tr>
</thead>
<tbody><tr>
<td>Is this key valid?</td>
<td>Authentication</td>
<td>401</td>
</tr>
<tr>
<td>Does this model exist on the platform?</td>
<td><a href="/docs/models/">GET /v1/models</a></td>
<td>The id is missing from the list</td>
</tr>
<tr>
<td>May this key&#39;s project call it?</td>
<td>The project&#39;s allowed models</td>
<td>403, before any provider</td>
</tr>
<tr>
<td>Can the project pay for it?</td>
<td>The project&#39;s credit balance</td>
<td>402</td>
</tr>
</tbody></table>
<p>The order matters. The gateway authenticates the key, checks the model against the project&#39;s allowed list, routes to a provider, then meters tokens against the project balance (<a href="/docs/how-it-works/">how it works</a>). A model can pass the second row and still fail the third.</p>
<h2 id="what-get-v1-models-returns">What GET /v1/models returns</h2>
<p>The request uses your project key and the OpenAI-format base URL:</p>
<pre><code>curl https://api.atptoken.ai/v1/models \
  -H &quot;Authorization: Bearer atp-...&quot;
</code></pre>
<p>The response is an OpenAI-style list. Each <code>id</code> is the exact string to put in the <code>model</code> field of a request:</p>
<pre><code>{
  &quot;object&quot;: &quot;list&quot;,
  &quot;data&quot;: [
    { &quot;id&quot;: &quot;claude-sonnet-4-6&quot;, &quot;object&quot;: &quot;model&quot;, &quot;created&quot;: 1700000000, &quot;owned_by&quot;: &quot;llm-gateway&quot; },
    { &quot;id&quot;: &quot;gpt-5.4&quot;, &quot;object&quot;: &quot;model&quot;, &quot;created&quot;: 1700000000, &quot;owned_by&quot;: &quot;llm-gateway&quot; }
  ]
}
</code></pre>
<p>The <a href="/docs/models/">model discovery docs</a> state that this list is not scoped to your project. Use it to get current ids instead of copying names from a provider dashboard or a blog post. Do not read it as a list of permissions.</p>
<h2 id="what-a-403-means">What a 403 means</h2>
<p>A 403 from ATP Token means the key is valid and the model id is real, but the model is not enabled for the key&#39;s project. The <a href="/docs/errors/">common responses</a> page describes it in one line: the model is not enabled for this project. The request stops at the authorization step and never reaches a provider. Like every ATP error, the response carries a <code>request_id</code> and uses the error format of the SDK you called.</p>
<p>A typical case: a developer sees <code>claude-opus-4-8</code> in the catalog and switches the support bot to it in a feature branch. The support bot&#39;s project allows only claude-haiku-4-5 and gemini-3-5-flash, so staging returns 403 on the first request. That is the allowlist doing its job. At ATP list rates, a 2,000-token prompt with a 300-token reply costs 1.75 <a class="doc-term" href="/docs/credits/" data-def="The billing unit. 1 USD = 100 credits; usage converts at each model's list rate.">credits</a> on <a href="/models/claude-opus-4-8/">claude-opus-4-8</a> (USD 5 input and USD 25 output per million tokens) against 0.35 credits on <a href="/models/claude-haiku-4-5/">claude-haiku-4-5</a> (USD 1 and USD 5), five times more per reply.</p>
<p>Two client rules follow. Do not retry a 403, because it will fail the same way every time. Log it with the request ID and route it to the project owner, who either changes the model in code or asks an Admin to widen the list.</p>
<h2 id="how-openai-and-openrouter-do-the-same-job">How OpenAI and OpenRouter do the same job</h2>
<table>

<p>In OpenAI&#39;s model, the Model usage setting sits next to the project&#39;s monthly spend limit and notification threshold. In OpenRouter&#39;s, the same guardrail can also hold a spending cap and a provider allowlist, and the strictest applicable rule wins. On ATP Token, the allowed list sits next to the project&#39;s credit allocation, and every key in the project inherits both.</p>

<ol>
<li><strong>Start with the cheapest model that passes your evaluation</strong>, then add one alternative from a second vendor. The gateway already fails over between providers for the same model id (<a href="/docs/provider-routing/" class="doc-term-def" data-def="One model id is served by a pool of providers; a degraded one is routed around automatically.">provider routing</a>); the second model is for when you want to switch models in code. For the Gemini or GPT choice, see <a href="/compare/gemini-vs-gpt/">Gemini vs GPT</a>.</li>
<li>Give frontier models their own project with a small allocation. Research gets Opus and GPT-5.5 without the support bot being one config change away from them.</li>
<li>Treat widening a list as a change request. Managing resources is an Admin permission, and the Activity log records resource updates (<a href="/docs/monitoring/">usage and logs</a>).</li>
<li>Pair every allowlist with a budget. An allowed model with an unlimited balance is still a surprise bill (<a href="/blog/ai-spending-caps-that-work/">AI API spending limits compared</a>).</li>
</ol>
<h2 id="setting-this-up-in-atp-token">Setting this up in ATP Token</h2>
<ol>
<li>On the Resources page, create the project and choose its allowed models (<a href="/docs/resources/" class="doc-term-def" data-def="The list of models a project may call. Anything outside it returns 403.">workspaces and projects</a>).</li>
<li>Allocate credits to the project, then issue a key from it (<a href="/docs/console-keys/" class="doc-term-def" data-def="A key that starts with atp-. It inherits its project's allowed models and credit balance.">managing API keys</a>).</li>
<li>Call <code>GET /v1/models</code> to copy exact ids into your configuration.</li>
<li>Send one test request per configured model from staging. A 200 confirms access; a 403 means the model is missing from the project&#39;s list.</li>
<li>In request logs, filter by status to find any 403s after a deploy.</li>
</ol>
