<p>The status code column is the one engineers tend to skip, and it decides what your client does next. A 429 looks like an ordinary rate limit, so most SDKs retry it automatically. Anthropic&#39;s documentation notes that its spend-cap 429 carries no <code>retry-after</code> header and retries fail until access resumes. A 402 or 400 will not succeed on retry either. Your client should read the error body and stop.</p>
<h2 id="how-each-platform-enforces-a-spend-limit">How each platform enforces a spend limit</h2>
<h3 id="openai-project-spend-limits">OpenAI: project spend limits</h3>
<p>OpenAI recommends separate projects for staging and production and lets you <a href="https://developers.openai.com/api/docs/guides/production-best-practices" target="_blank" rel="noopener noreferrer">set custom rate and spend limits per project</a>. In the project&#39;s Limits settings you set a monthly spend limit, a notification threshold and which models the project may use (<a href="https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform" target="_blank" rel="noopener noreferrer">OpenAI Help Center</a>).</p>
<p>A spend alert sends a notification and lets traffic continue. A hard spend limit makes affected requests return 429. Above both sits the usage tier: Tier 1 allows USD 100 a month and Tier 5 allows USD 200,000. The watch-out is the shared status code. A retry loop that handles rate limits will keep hammering a project that is out of budget unless you check the error body.</p>
<h3 id="anthropic-console-workspace-spend-limits">Anthropic Console: workspace spend limits</h3>
<p>Claude Console <a href="https://platform.claude.com/docs/en/manage-claude/workspaces" target="_blank" rel="noopener noreferrer">workspaces</a> each get a monthly spend limit and per-model rate limits, set lower than (never higher than) the organization&#39;s. API keys can be scoped to a single workspace. You cannot set limits on the Default Workspace, so keys you want capped belong in a named workspace.</p>
<p>When a limit you set is reached, requests return HTTP 400 with <code>invalid_request_error</code>, and the message says when access resumes. The tier cap (USD 500 a month on Start, USD 1,000 on Build, USD 200,000 on Scale) returns 429 and pauses usage until 00:00 UTC on the first of the next month. The Claude Code workspace that the Console creates automatically is the only workspace with per-user monthly spend limits.</p>
<h3 id="openrouter-guardrails-and-per-key-credit-limits">OpenRouter: guardrails and per-key credit limits</h3>
<p>OpenRouter has two separate mechanisms. Guardrails are set by organization admins per member or per API key and can carry a USD spending cap that resets daily, weekly or monthly; requests over the cap get 403. A guardrail can also hold a model allowlist and a provider allowlist, and when several guardrails apply, the strictest rule wins.</p>
<p>Per-key credit limits work on every plan. Each key has a <code>limit</code> and a <code>limit_reset</code> of daily, weekly, monthly or none, with resets at midnight UTC. An exhausted key returns 402. Workspace-level budgets are an Enterprise feature (<a href="https://openrouter.ai/blog/insights/governing-team-ai-spend/" target="_blank" rel="noopener noreferrer">OpenRouter blog</a>).</p>
<h3 id="vercel-ai-gateway-stacked-budgets">Vercel AI Gateway: stacked budgets</h3>
<p>Vercel budgets apply at four scopes (team, project, API key and team member) and stack, so a request must pass every budget in scope. Refresh periods are daily, weekly, monthly or none, all in UTC. An exceeded budget returns 402 with <code>quota_for_entity_exceeded</code>, and the message names the scope that ran out.</p>
<p>Vercel calls its budget a soft cap: the check runs at the start of each request, so the request that crosses the limit still completes. Optional email alerts fire at 50, 75 and 100 percent. Two details catch teams out. API key spend never counts toward a project budget (project budgets only see that project&#39;s deployment OIDC tokens), and BYOK spend is not counted in any budget.</p>
<h3 id="atp-token-prepaid-allocation-per-project">ATP Token: prepaid allocation per project</h3>
<p>In ATP Token the cap is the money itself. Credits (1 credit = USD 0.01) flow from organization to workspace to project, and every key spends from its own project&#39;s balance. A project can only spend what it was allocated. When the balance is exhausted, the gateway rejects the request with 402 at the metering step (<a href="/docs/how-it-works/">how it works</a>). A project that spends more than it was allocated is flagged In debt until topped up.</p>
<p>There is no reset period. Pay-as-you-go credits do not expire, so an allocation you do not use carries over to the next month. A monthly budget therefore needs a monthly allocation step, or project auto <a class="doc-term" href="/docs/topup/" data-def="Adding credits to the wallet. Minimum 5 USD, pay as you go.">top-up</a>: a pay-as-you-go project can refill itself when its balance drops below a threshold, limited by a per-charge cap and a monthly charge cap. With auto top-up on, that monthly charge cap is the ceiling that matters.</p>
<h2 id="design-rules-for-limits-teams-will-keep">Design rules for limits teams will keep</h2>
<ol>
<li><strong>Cap each workload separately.</strong> One project per production service, one for staging, one per sandbox. An organization-wide limit stops every product at once, healthy ones included. <a href="/blog/one-project-one-key/">One project, one key</a> covers the key side.</li>
<li>Treat budget errors as final in client code. Map 402, the Anthropic 400 limit error and a spend-limit 429 to &quot;stop and notify the owner&quot;, never to exponential backoff.</li>
<li>Size each cap from unit cost. Tokens per request times the model&#39;s rate times expected volume gives a number you can explain to finance and adjust when traffic changes.</li>
<li>Keep an unallocated reserve at the top. If production runs dry on the 27th, an admin can move credits in minutes without touching staging.</li>
<li>Review Allocated against Consumed weekly. On ATP Token the <a href="/docs/spend/">Usage page</a> shows both at every level of the tree. If you want an automated alarm, poll the real-time project balance from the <a href="/docs/console-api-usage/">Console API</a> and post to your own channel.</li>
</ol>

<p>The support bot. claude-haiku-4-5 has an ATP list rate of USD 1 per million input tokens and USD 5 per million output tokens. A typical reply with 2,000 input tokens and 300 output tokens costs 2,000 × 1 / 1,000,000 + 300 × 5 / 1,000,000 = USD 0.0035, or 0.35 credits. 140,000 credits ÷ 0.35 = 400,000 replies a month, about 13,300 a day.</p>
<p>The staging job that ran all weekend. Suppose a retry bug fires 5 requests a second at the same 0.35 credits each. That burns 1.75 credits a second, so the 10,000-credit staging allocation lasts 10,000 ÷ 1.75 ≈ 5,700 seconds, about 95 minutes. Staging then gets 402 and production keeps answering customers. Without the split, the same loop running from Friday 18:00 to Monday 09:00 (63 hours, 226,800 seconds) would spend 226,800 × 1.75 = 396,900 credits, almost twice the whole monthly budget.</p>
<p>The coding agent. Anthropic puts the average Claude Code cost at <a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">around USD 13 per developer per active day</a>. At that rate, USD 300 covers about 23 developer-days, roughly one developer for a working month. When the sandbox hits 402 mid-afternoon, that is the signal to look at the session before adding credits. The <a href="/blog/what-is-the-agent-tax/">agent tax</a> explains why agent sessions cost more per task than single calls.</p>
<p>On the first of the next month nothing resets. If the support bot used 120,000 credits, it still holds 20,000; allocate another 120,000 to bring it back to 140,000.</p>
<h2 id="setting-this-up-in-atp-token">Setting this up in ATP Token</h2>
<ol>
<li>Create a Team organization, then the workspaces (Production, Pre-production, Engineering) on the Resources page (<a href="/docs/console-setup/" class="doc-term-def" data-def="The top level of an account. Workspaces and projects sit underneath it.">set up your organization</a>).</li>
<li>Create each project and pick its allowed models. Every project needs at least one (<a href="/docs/resources/" class="doc-term-def" data-def="The list of models a project may call. Anything outside it returns 403.">workspaces and projects</a>).</li>
<li>Allocate credits down the tree: organization, then workspace, then project. Leave the reserve unallocated at the organization level.</li>
<li>Issue one key per project. The key inherits the project&#39;s models and balance (<a href="/docs/console-keys/" class="doc-term-def" data-def="A key that starts with atp-. It inherits its project's allowed models and credit balance.">managing API keys</a>).</li>
<li>Handle 402 in your client as &quot;budget exhausted&quot; and alert the project owner (<a href="/docs/errors/">common responses</a>).</li>
