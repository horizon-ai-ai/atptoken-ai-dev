a:T186c,<p>A coding-agent cost control checklist is the set of controls a company applies when developers use Claude Code, Codex, or similar agents against paid model APIs—so long-context loops cannot silently own the AI budget. This guide is for platform leads enabling agents without repeating public overrun stories.</p>
<p>Conclusion first: <strong>treat coding agents like a product surface with its own <a class="doc-term" href="/en/docs/resources" data-def="The unit that permissions and billing hang off — keys, allowed models, and credit budget all belong to one.">project</a>, key, cap, and logs.</strong> Subscription UX can hide API economics; enterprise billing does not. Background: <a href="/en/blog/what-is-the-agent-tax">agent tax</a>, <a href="/en/blog/why-ai-bills-explode-after-go-live">bills after go-live</a>.</p>
<h2 id="the-10-checks">The 10 checks</h2>
<h3 id="1-separate-project-for-agents-not-the-production-key">1. Separate project for agents — not the production key</h3>
<p><a href="/en/blog/one-project-one-key">One project, one key</a>. Agent thrash must not share production credentials (<a href="/en/docs/console-keys" class="doc-term-def" data-def="A key that starts with atp-. It inherits its project's allowed models and credit balance.">console keys</a>).</p>
<h3 id="2-hard-credit-allocation-sandbox-sized-to-burn">2. Hard credit allocation — sandbox sized to burn</h3>
<p><a href="/en/docs/cb-budget-caps">Budget caps</a>. If the cap is “unlimited for DX,” you chose the invoice as your alert system.</p>
<h3 id="3-model-allowlist-frontier-is-opt-in">3. Model allowlist — frontier is opt-in</h3>
<p>Default mid-tier models; unlock frontier per project with a reason (<a href="/en/docs/models">models</a>).</p>
<h3 id="4-step-and-token-budgets-in-the-agent-fail-closed">4. Step and token budgets in the agent — fail closed</h3>
<p>Unbounded loops are <a href="/en/blog/what-is-the-agent-tax">agent tax</a> by design.</p>
<h3 id="5-secrets-never-in-git-or-skill-files">5. Secrets never in git or SKILL files</h3>
<p>Keys in env or secret managers only (<a href="/en/docs/agent-skills">agent skills</a>).</p>
<h3 id="6-no-prod-data-in-agent-context-by-default">6. No prod data in agent context by default</h3>
<p>Classify what may leave the laptop; pair with governance checklist data rules (<a href="/en/blog/ai-governance-checklist">checklist</a>).</p>
<h3 id="7-weekly-spend-review-by-key-and-model">7. Weekly spend review by key and model</h3>
<p><a href="/en/docs/monitoring">Usage and logs</a>, <a href="/en/docs/spend">tracking spend</a>.</p>
<h3 id="8-idle-and-ex-employee-key-revocation">8. Idle and ex-employee key revocation</h3>
<p>Keys follow projects; people follow membership (<a href="/en/docs/team">team</a>).</p>
<h3 id="9-incident-runbook-revoke-trace-reissue">9. Incident runbook — revoke, trace, reissue</h3>
<p>One page, rehearsed once.</p>
<h3 id="10-cost-per-completed-task-not-vanity-request-counts">10. Cost per completed task — not vanity request counts</h3>
<p>Finance-readable metric from request chains (<a href="/en/blog/how-to-read-your-ai-bill">read the bill</a>).</p>
<h2 id="wiring-claude-code-codex-without-bypassing-governance">Wiring Claude Code / Codex without bypassing governance</h2>
<p>Use project keys and gateway base URLs as in <a href="/en/docs/cb-claude-code">Claude Code on ATP</a> and <a href="/en/docs/agents">coding agents</a>. Installing skills must not enable models outside the project allowlist.</p>
<h2 id="by-team-size">By team size</h2>
<p><strong>Startups:</strong> one agent project, weekly credit review.<br><strong>Mid:</strong> per squad projects.<br><strong>Enterprise:</strong> agents under a platform workspace; BU pays allocations (<a href="/en/docs/console-setup" class="doc-term-def" data-def="The top level of an account. Workspaces and projects sit underneath it.">org setup</a>).</p>
<h2 id="a-more-modern-approach">A more modern approach</h2>
<p>Policy slides do not stop a laptop agent at 2 a.m. A governance gateway that enforces allowlists and balances on every request does. ATP Token provides that plane with SDK-compatible routes and hierarchical <a class="doc-term" href="/en/docs/credits" data-def="The billing unit. 1 USD = 100 credits; usage converts at each model's list rate.">credits</a>.</p>

<h2 id="faqs">FAQs</h2>
<h3 id="why-are-coding-agents-expensive-on-api-billing">Why are coding agents expensive on API billing?</h3>
<p>They repeatedly send repository context, run multi-step tool calls, and retry failures, so tokens per completed change far exceed a single chat reply—even when subscription UIs feel flat-rate.</p>
<h3 id="should-claude-code-use-the-same-api-key-as-production-services">Should Claude Code use the same API key as production services?</h3>
<p>No. Give coding agents their own project, key, model allowlist, and credit cap so developer experiments cannot exhaust production budgets.</p>
<h3 id="how-do-i-cap-coding-agent-spend">How do I cap coding agent spend?</h3>
<p>Allocate a fixed project credit ceiling, alert before exhaustion, restrict frontier models on the allowlist, and set max steps or max tokens in the agent configuration where possible.</p>
<h3 id="what-metrics-should-i-track-for-coding-agents">What metrics should I track for coding agents?</h3>
<p>Credits per successful merge or task, requests per task, input vs output tokens, and top models by spend—reviewed weekly from per-request logs.</p>
<h3 id="how-do-i-run-claude-code-through-an-enterprise-gateway">How do I run Claude Code through an enterprise gateway?</h3>
<p>Point the agent base URL at the gateway, use a project key as the auth token, clear conflicting vendor env vars, and enable only allowed models for that project.</p>
