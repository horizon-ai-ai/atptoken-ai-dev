b:T20a9,<p>An OpenAI-compatible API is an endpoint that accepts the same request and response format as OpenAI&#39;s API, so the official OpenAI SDK can call it after you change the base URL and the key. This article covers what OpenAI&#39;s own platform already controls, the point where a gateway starts to pay off, the exact code change, and what the same workload costs on six models.</p>
<h2 id="short-answer">Short answer</h2>
<p>Stay on the OpenAI API directly if one team uses only OpenAI models and OpenAI&#39;s project limits cover your budget rules.</p>
<p>Add an OpenAI-compatible gateway when one of these happens:</p>
<ul>
<li>A second vendor arrives, for example Claude for coding or Gemini Flash for high-volume classification, and finance wants one bill and one set of limits.</li>
<li>Several teams share one AI budget and each needs its own ceiling and model list across vendors.</li>
<li>You want to compare models on your own prompts without wiring up three SDKs.</li>
</ul>
<h2 id="what-openai-39-s-platform-already-gives-you">What OpenAI&#39;s platform already gives you</h2>
<p>OpenAI has added most of the controls that used to justify a gateway for a single vendor:</p>
<ul>
<li>Projects to separate, for example, staging and production, with their own keys, rate limits and spend limits (<a href="https://developers.openai.com/api/docs/guides/production-best-practices" target="_blank" rel="noopener noreferrer">production best practices</a>).</li>
<li>Two kinds of spend control. Spend alerts send a notification and traffic continues. Hard spend limits make affected requests return 429 (<a href="https://developers.openai.com/api/docs/guides/rate-limits" target="_blank" rel="noopener noreferrer">rate limits guide</a>).</li>
<li>A per-project &quot;Model usage&quot; setting that restricts which models a project can call (<a href="https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform" target="_blank" rel="noopener noreferrer">managing projects</a>).</li>
<li>Usage tiers that cap monthly spend until you have paid enough, from $100 a month at Tier 1 to $200,000 at Tier 5.</li>
</ul>
<p>If all your traffic is OpenAI, use these first.</p>
<h2 id="where-direct-access-stops">Where direct access stops</h2>
<p>The limits above apply to OpenAI models only. The moment a team adds Claude, Anthropic&#39;s Console has its own workspaces, spend limits and keys (<a href="https://platform.claude.com/docs/en/manage-claude/workspaces" target="_blank" rel="noopener noreferrer">Anthropic workspaces</a>). Add Gemini and there is a third console. In practice that means:</p>
<ul>
<li>Three sets of keys to issue and revoke when someone leaves.</li>
<li>Three budgets that can&#39;t see each other, so &quot;the support bot may spend $3,000 a month across all vendors&quot; can&#39;t be enforced anywhere.</li>
<li>Three invoices in different formats at month-end.</li>
<li>Code split across the OpenAI, Anthropic and Google SDKs.</li>
</ul>
<p>A gateway puts one set of keys, limits and logs in front of all of them.</p>
<h2 id="the-code-change">The code change</h2>
<p>With ATP Token, the OpenAI SDK stays. You change three values (<a href="/docs/sdk-openai/">OpenAI SDK guide</a>, <a href="/docs/cb-migrate-openai/">migrate from OpenAI</a>):</p>
<pre><code>from openai import OpenAI

# Before: client = OpenAI(api_key=&quot;sk-...&quot;)
client = OpenAI(base_url=&quot;https://api.atptoken.ai/v1&quot;, api_key=&quot;atp-...&quot;)

for model in [&quot;gpt-5.4&quot;, &quot;claude-sonnet-4-6&quot;, &quot;gemini-3-5-flash&quot;]:
    r = client.chat.completions.create(
        model=model,
        messages=[{&quot;role&quot;: &quot;user&quot;, &quot;content&quot;: &quot;Classify this ticket: &#39;Refund not received after 10 days&#39;&quot;}],
        max_tokens=200,
    )
    print(model, r.choices[0].message.content, r.usage.total_tokens)
</code></pre>
<p>What stays the same: the Chat Completions request body, the response body, streaming with <code>stream=True</code> (<a href="/docs/sse-openai/">OpenAI SSE</a>) and tool definitions.</p>
<p>What changes:</p>
<ul>
<li>Model ids come from <code>GET /v1/models</code> (<a href="/docs/models/">model discovery</a>). OpenAI models keep familiar names such as <code>gpt-5.4</code>; others use ids like <code>claude-sonnet-4-6</code> or <code>deepseek-v4-flash</code>.</li>
<li>A model that isn&#39;t on the project&#39;s allowed list returns 403 before it reaches any provider.</li>
<li>When the project&#39;s <a class="doc-term" href="/docs/credits/" data-def="The billing unit. 1 USD = 100 credits; usage converts at each model's list rate.">credits</a> run out, requests return 402 (<a href="/docs/errors/">errors</a>).</li>
<li>ATP&#39;s OpenAI-format surface is <code>/v1/chat/completions</code>, <code>/v1/models</code> and <code>/v1/files</code>. If your code calls other OpenAI endpoints, check the <a href="/docs/chat/">API reference</a> before moving those calls.</li>
</ul>
<p>Teams that use the Anthropic or Google GenAI SDK don&#39;t need to switch to the OpenAI format: the same project key works with those SDKs at <code>https://api.atptoken.ai</code> (<a href="/docs/sdk-anthropic/">Anthropic SDK</a>, <a href="/docs/sdk-google/">Google GenAI SDK</a>).</p>

<p>Price is half of the decision. Run a few hundred of your real tickets through the two or three cheapest models that pass your quality bar before you switch. The side-by-side pages for <a href="/compare/deepseek-vs-claude/">DeepSeek vs Claude</a> and <a href="/compare/gemini-vs-gpt/">Gemini vs GPT</a> are a starting point.</p>
<h2 id="migration-checklist">Migration checklist</h2>
<ol>
<li>List every place your code creates an OpenAI client and which endpoints it calls.</li>
<li>Create one ATP project per service and enable only the models that service needs (<a href="/docs/resources/" class="doc-term-def" data-def="The list of models a project may call. Anything outside it returns 403.">workspaces and projects</a>).</li>
<li>Allocate credits to each project; the allocation is the ceiling (<a href="/docs/cb-budget-caps/">budget caps</a>).</li>
<li>Issue one key per project and store it in your secret manager (<a href="/docs/console-keys/" class="doc-term-def" data-def="A key that starts with atp-. It inherits its project's allowed models and credit balance.">managing keys</a>).</li>
<li>Change base URL, key and model id in staging. Compare outputs and token counts in Request logs (<a href="/docs/monitoring/">usage and logs</a>).</li>
<li>Move production one service at a time, then revoke the old OpenAI keys you no longer use.</li>
</ol>
