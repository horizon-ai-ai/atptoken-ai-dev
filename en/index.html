The platform

Four things you stop worrying about.

Keys, billing, attribution and access — one structure across every provider, not another vendor contract.

01

One key per project

Issue as many keys as you need — each bound to one project, spending only that project's budget — so revoking one ends its access everywhere, with nothing left behind in personal accounts.

02

One wallet, one bill

Every provider draws from the same credit wallet and rolls up into a single monthly bill in one currency — no more stitching together separate invoices, cycles and exchange rates before finance can close the month.

03

Every charge has an owner

Each request is logged with its model, key, tokens and credits, and lands on a project — so the number in front of you already says which team spent it, instead of a total you have to trace backwards.

04

Access lives in the structure

Organization → workspace → project narrows access layer by layer, with model allowlists set on the project — one place answers who can call what, instead of logging into each provider to find out.

Governance

Who can call which model is decided by structure.

A three-tier hierarchy — organization, workspace, project — scopes every key and every model. Access follows structure, not individuals.

  • Three-tier hierarchy

    Organizations, workspaces, and projects each hold their own members, roles, and credit allocations.

  • Model allowlists

    Each project can only call the model IDs enabled for it — enforced before traffic reaches any provider.

  • Scoped keys

    Every key belongs to exactly one project, with its own logs and credit usage — revocable at any time.

Billing

Every request has an owner.

Usage across every provider is metered per request and rolls up into one billing view — one billing point, credits allocated down the hierarchy.

  • Per-request attribution

    Each request logs its model, key, token usage, and credit cost — attributable to a project and a team.

  • Credit allocation

    Credits flow from the organization down to workspaces and projects, so budgets are set before spend happens.

  • One billing point

    Spend across providers consolidates into one billing record — finance deals with a single counterpart.
