3:T643,<p>Gateway 可從下列位置讀取<a class="doc-term" href="/zh-tw/docs/resources/" data-def="權限與帳務的最小單位；金鑰、允許模型、點數預算都掛在 專案 上。">專案</a>（project）<a class="doc-term" href="/zh-tw/docs/console-keys/" data-def="以 atp- 開頭的金鑰，繼承所屬 專案 的允許模型清單與點數餘額。">API 金鑰</a>。<code>Authorization: Bearer</code> 和 <code>x-api-key</code> 在每個端點都有效，所以官方 OpenAI、Anthropic、Google GenAI SDK 都不用改，只要換 base URL。Gateway 會在轉送請求前移除這把金鑰。</p>
<h2 data-md="h2" id="先拿到金鑰" class="group">先拿到金鑰<a href="#先拿到金鑰" aria-label="此段連結" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>金鑰不是從 API 申請的。到 <a href="https://atptoken.ai" target="_blank" rel="noopener noreferrer">atptoken.ai</a> 登入，依序選擇或建立 <a class="doc-term" href="/zh-tw/docs/console-setup/" data-def="帳號的最上層，底下再分 工作區 與 專案。">組織</a> → 工作區 → 專案，再到專案裡建立金鑰。一把金鑰屬於一個專案：能用哪些模型、費用算在誰頭上，都由那個專案決定。見<a href="/zh-tw/docs/console-keys/">管理 API 金鑰</a>。</p>
<h2 data-md="h2" id="金鑰放在哪裡" class="group">金鑰放在哪裡<a href="#金鑰放在哪裡" aria-label="此段連結" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>4:Tdda,<h2 data-md="h2" id="驗證失敗時" class="group">驗證失敗時<a href="#驗證失敗時" aria-label="此段連結" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>沒帶、被停用、過期或不存在的金鑰，都回 <code>401</code>，代碼是 <code>token_revoked</code>，訊息是「API key has been revoked or does not exist」。<strong>完全沒送金鑰也是同一個錯誤</strong>，所以先確認 header 真的有送出去，再懷疑金鑰本身。</p>
<p><code>403</code> 是另一回事：金鑰沒問題，但模型不在這個專案的允許清單上。見<a href="/zh-tw/docs/errors/">錯誤碼</a>。</p>
<h2 data-md="h2" id="登入主控台" class="group">登入主控台<a href="#登入主控台" aria-label="此段連結" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>申請金鑰、<a class="doc-term" href="/zh-tw/docs/topup/" data-def="為錢包加值點數，USD 5 起儲值，用多少付多少。">儲值</a>、讀主控台 API，起點都一樣：有一個人到 <a href="https://atptoken.ai" target="_blank" rel="noopener noreferrer">atptoken.ai</a> 登入。在你依賴登入做任何東西之前，有兩件事要先知道。</p>
<h3 data-md="h3" id="登入要過人機驗證" class="group">登入要過人機驗證<a href="#登入要過人機驗證" aria-label="此段連結" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>登入需要通過人機驗證，而只有瀏覽器答得出來。沒帶答案的請求回 <code>400</code>，<code>reason</code> 是 <code>captcha_required</code>；答案驗不過的回 <code>400</code>，<code>reason</code> 是 <code>captcha_invalid</code>。</p>
<p>它存在的理由是：有人被鎖在自己的帳號外面。腳本一個帳號一個帳號地猜密碼，而唯一的防線是單一帳號的失敗次數上限——那擋住的是真正的持有人，對腳本毫無作用，因為它換下一個帳號就好。人機驗證在第一個請求就擋下整輪。驗證失敗不會讓你付代價：只有密碼真的錯了，失敗次數才會增加。</p>
<p>每一次登入都要過。沒有「失敗幾次之後才開始要求」這種門檻，也沒有可以申請的例外。</p>
<h3 data-md="h3" id="連結外部登入方式之後-密碼就不能用了" class="group">連結外部登入方式之後，密碼就不能用了<a href="#連結外部登入方式之後-密碼就不能用了" aria-label="此段連結" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>你可以把一個外部登入方式連結到帳號上，用它取代密碼。連結第一個時同樣要過人機驗證，而且它會改變這個帳號：帳號變成無密碼，原本的密碼會被刪除。你記得的那組密碼就不再是入口——不是暫停，是刪掉。</p>
<p>之後再連結第二個不會再有變化，因為密碼在第一個就一起走了。</p>
<p>要把密碼這條路拿回來，是管理員的動作：由管理員把帳號改回密碼模式，你再用「忘記密碼」設一組新的。從你自己的帳號裡，沒有任何操作能把原來那組找回來。</p>
