<p>順序很重要。閘道先驗證金鑰，再拿模型比對專案的允許清單，接著路由到供應商，最後依專案餘額計量 token（<a href="/zh-tw/docs/how-it-works/">運作方式</a>）。一個模型可能通過第二列，卻卡在第三列。</p>
<h2 id="get-v1-models-回傳什麼">GET /v1/models 回傳什麼</h2>
<p>請求使用你的專案金鑰與 OpenAI 格式的 base URL：</p>
<pre><code>curl https://api.atptoken.ai/v1/models \
  -H &quot;Authorization: Bearer atp-...&quot;
</code></pre>
<p>回應是 OpenAI 風格的清單。每個 <code>id</code> 就是請求裡 <code>model</code> 欄位要填的字串：</p>
<pre><code>{
  &quot;object&quot;: &quot;list&quot;,
  &quot;data&quot;: [
    { &quot;id&quot;: &quot;claude-sonnet-4-6&quot;, &quot;object&quot;: &quot;model&quot;, &quot;created&quot;: 1700000000, &quot;owned_by&quot;: &quot;llm-gateway&quot; },
    { &quot;id&quot;: &quot;gpt-5.4&quot;, &quot;object&quot;: &quot;model&quot;, &quot;created&quot;: 1700000000, &quot;owned_by&quot;: &quot;llm-gateway&quot; }
  ]
}
</code></pre>
<p><a href="/zh-tw/docs/models/">模型探索文件</a>寫明這份清單不會依你的專案篩選。用它取得最新的 ID，不要從供應商儀表板或部落格文章抄模型名稱。也不要把它當成權限清單來讀。</p>
<h2 id="403-代表什麼">403 代表什麼</h2>
<p>ATP Token 回傳 403，表示金鑰有效、模型 ID 也存在，但這個模型沒有在金鑰所屬的專案啟用。<a href="/zh-tw/docs/errors/">常見回應</a>頁面只用一行描述：模型未在此專案啟用。請求停在授權步驟，不會送到任何供應商。和所有 ATP 錯誤一樣，回應帶有 <code>request_id</code>，並採用你所呼叫 SDK 的錯誤格式。</p>
<p>典型情境：一位開發者在目錄裡看到 <code>claude-opus-4-8</code>，在功能分支把客服機器人換成它。客服機器人的專案只允許 claude-haiku-4-5 與 gemini-3-5-flash，所以 staging 第一筆請求就回傳 403。這正是白名單該做的事。以 ATP 牌價計算，2,000 token 的提示加 300 token 的回覆，在 <a href="/zh-tw/models/claude-opus-4-8/">claude-opus-4-8</a>（每百萬 token 輸入 USD 5、輸出 USD 25）要 1.75 點，在 <a href="/zh-tw/models/claude-haiku-4-5/">claude-haiku-4-5</a>（USD 1 與 USD 5）只要 0.35 點，每則回覆差五倍。</p>
<p>由此得出兩條用戶端規則。不要重試 403，它每次都會以同樣方式失敗。把它連同請求 ID 記錄下來，交給專案負責人，由對方改程式碼裡的模型，或請 Admin 放寬清單。</p>

<li><strong>從通過評測的最便宜模型開始</strong>，再加一個來自第二家廠商的備案。同一個模型 ID 在不同供應商之間的容錯切換，閘道已經處理（<a href="/zh-tw/docs/provider-routing/" class="doc-term-def" data-def="同一個模型 ID 由一組供應商服務，其中一家降級時自動改走另一家。">供應商路由</a>）；第二個模型是給你想在程式碼裡換模型時用的。在 Gemini 與 GPT 之間選擇，請見 <a href="/zh-tw/compare/gemini-vs-gpt/">Gemini vs GPT</a>。</li>
<li>前沿模型放在自己的專案，給小額分配。研究團隊能用 Opus 與 GPT-5.5，客服機器人則不會只差一行設定就換過去。</li>
<li>把放寬清單當成變更申請處理。管理資源是 Admin 的權限，Activity 紀錄會記下資源更新（<a href="/zh-tw/docs/monitoring/">用量與紀錄</a>）。</li>
<li>每份白名單都搭配預算。允許的模型配上無上限的餘額，帳單一樣會嚇人（<a href="/zh-tw/blog/ai-spending-caps-that-work/">AI API 花費上限比較</a>）。</li>
</ol>
<h2 id="在-atp-token-上怎麼設定">在 ATP Token 上怎麼設定</h2>
<ol>
<li>在 Resources 頁面建立專案並選擇允許的模型（<a href="/zh-tw/docs/resources/" class="doc-term-def" data-def="這個 專案 可以呼叫的模型清單；不在清單上的一律回 403。">工作區與專案</a>）。</li>
<li>撥點數給專案，再從專案發金鑰（<a href="/zh-tw/docs/console-keys/" class="doc-term-def" data-def="以 atp- 開頭的金鑰，繼承所屬 專案 的允許模型清單與點數餘額。">管理 API 金鑰</a>）。</li>
<li>呼叫 <code>GET /v1/models</code>，把精確的 ID 複製到設定檔。</li>
<li>在 staging 對每個設定中的模型各送一筆測試請求。200 表示有權限；403 表示專案清單裡沒有這個模型。</li>
<li>部署後在請求紀錄依狀態篩選，找出 403。</li>
</ol>
