<h2 id="需要什麼">需要什麼</h2>
<p><a href="/zh-tw/docs/console-setup" class="doc-term-def" data-def="帳號的最上層，底下再分 workspace 與 project。">組織設定</a>與<a href="/zh-tw/docs/console-keys" class="doc-term-def" data-def="以 atp- 開頭的金鑰，繼承所屬 project 的允許模型清單與點數餘額。">管理金鑰</a>：組織→工作區→專案→金鑰；密文只顯示一次、可立即撤銷、名冊留稽核。</p>

<h2 id="常見問題">常見問題</h2>
<h3 id="一專案一金鑰是什麼意思">一專案一金鑰是什麼意思？</h3>
<p>每個正式工作負載有一把專案級 API 金鑰，繼承該專案的模型白名單與點數餘額，讓花費與存取都有明確主人。</p>
<h3 id="為什麼共用-api-金鑰有風險">為什麼共用 API 金鑰有風險？</h3>
<p>無法知道哪個系統在燒 token、離職時不敢撤銷，外洩時爆炸半徑是全公司。</p>
<h3 id="企業應如何核發-llm-api-金鑰">企業應如何核發 LLM API 金鑰？</h3>
<p>每系統一專案、只開需要的模型、分配預算、金鑰只顯示一次、放進密鑰管理，專案結束即撤銷。</p>
<h3 id="金鑰跟專案走時-人員離職怎麼辦">金鑰跟專案走時，人員離職怎麼辦？</h3>
<p>移除成員或專案存取即可，不必輪替半公司依賴的那把共用 key。</p>
<h3 id="如何從共用金鑰遷移">如何從共用金鑰遷移？</h3>
<p>盤點呼叫端、為每系統建專案金鑰、雙跑、逐系統切流，最後撤銷共用 key 並留稽核。</p>
