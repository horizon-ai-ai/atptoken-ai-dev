<p>Shadow AI 是 Shadow IT 的一個子集。差別在於每一次提示都是一次資料傳輸，而 API 用量按 token 計費，所以一支沒人審過的腳本，可能在同一週同時帶來資料問題與費用問題。</p>
<h2 id="shadow-ai-有多普遍-2025-年數據">Shadow AI 有多普遍：2025 年數據</h2>
<p><a href="https://newsroom.ibm.com/2025-07-30-ibm-report-13-of-organizations-reported-breaches-of-ai-models-or-applications,-97-of-which-reported-lacking-proper-ai-access-controls" target="_blank" rel="noopener noreferrer">IBM 2025 年資料外洩成本報告</a>（2025 年 7 月發布）指出：</p>
<ul>
<li>每五家組織就有一家回報曾因 Shadow AI 發生外洩。</li>
<li>Shadow AI 程度高的組織，外洩成本比程度低或沒有的組織平均高出 67 萬美元。</li>
<li>13% 的組織回報 AI 模型或應用程式遭入侵，其中 97% 缺乏適當的 AI 存取控管。</li>
<li>只有 37% 的組織有管理 AI 或偵測 Shadow AI 的政策。</li>
</ul>
<p><a href="https://www.verizon.com/business/resources/reports/2025-dbir-data-breach-investigations-report.pdf" target="_blank" rel="noopener noreferrer">Verizon 2025 年資料外洩調查報告（DBIR）</a>補上身分這一面：15% 的員工經常在公司裝置上使用生成式 AI；其中 72% 以非公司電子郵件作為帳號識別，17% 使用公司電子郵件但沒有整合身分驗證。</p>
<p>72% 這個數字和離職流程直接相關。用個人信箱註冊的帳號不在你的身分提供者管轄範圍內，停用員工的 SSO 登入並不會關掉它。</p>
<h2 id="五個-shadow-ai-實例">五個 Shadow AI 實例</h2>
<h3 id="1-用個人-chatgpt-或-claude-帳號處理公司資料">1. 用個人 ChatGPT 或 Claude 帳號處理公司資料</h3>
<p>財務分析師把董事會備忘錄草稿貼進個人聊天機器人帳號，請它幫忙潤稿。這份資料從此依照那個人自己註冊的方案條款被處理，資安團隊完全不知道。</p>
<h3 id="2-腳本裡的個人-api-金鑰-刷公司卡">2. 腳本裡的個人 API 金鑰，刷公司卡</h3>
<p>業務營運分析師寫了一支腳本，每晚用 GPT-5.5 摘要 2,000 份通話逐字稿。每份 6,000 個輸入 token、800 個輸出 token，合計 1,200 萬輸入 token（60 美元）與 160 萬輸出 token（48 美元），以 OpenAI <a href="https://developers.openai.com/api/docs/pricing" target="_blank" rel="noopener noreferrer">公告價格</a>每 100 萬 token 輸入 5 美元、輸出 30 美元計算（截至 2026 年 10 月）。一晚約 108 美元，30 天約 3,240 美元，以「軟體」名目報銷，沒有任何上限。</p>
<h3 id="3-已核准-saas-裡被開啟的-ai-功能">3. 已核准 SaaS 裡被開啟的 AI 功能</h3>
<p>CRM 或客服系統推出 AI 助理，某位<a class="doc-term" href="/zh-tw/docs/resources/" data-def="組織 底下的一層分組，用來把不同團隊或環境的 專案 分開。">工作區</a>管理員就把它開了。這家供應商幾年前只針對資料儲存做過審查，新功能卻把同樣的資料送到模型供應商，適用的條款沒有人重新讀過。</p>
<h3 id="4-瀏覽器擴充功能">4. 瀏覽器擴充功能</h3>
<p>一個「AI 幫你摘要這一頁」的擴充功能，需要讀取員工開啟的每一個頁面，包括內部管理後台與人資系統。因為免費，它從來不會出現在採購流程裡。</p>
<h3 id="5-未核准的程式碼-agent">5. 未核准的程式碼 Agent</h3>
<p>外包工程師用個人金鑰讓程式碼 Agent在公司 monorepo 上工作。Agent 把 <code>.env</code> 檔讀進上下文，合約結束後仍能繼續運作，因為金鑰是外包工程師自己的。</p>
<h2 id="shadow-ai-的風險">Shadow AI 的風險</h2>
<h3 id="資料">資料</h3>
<p>提示與上傳的檔案在沒有分級的情況下離開公司。適用的資料保留與訓練條款，是員工個人方案的條款，法務沒有審過。</p>
<h3 id="費用">費用</h3>
<p>刷在個人卡上的 token 計費，沒有上限，也沒有負責人。財務只看到一連串小額報銷，總數要等有人把一季的報銷單加總才會出現。</p>
<h3 id="離職">離職</h3>
<p>綁在個人身上的金鑰與帳號，在人離開後仍然有效。外包工程師離職後，能撤銷那把個人金鑰的只有他自己。</p>
<h3 id="稽核">稽核</h3>
<p>客戶的資安問卷問到「哪些 AI 供應商處理我們的資料」時，你需要一份供應商清單與請求紀錄。影子用量不會留下任何可以拿出來的紀錄。</p>
<h2 id="怎麼偵測-shadow-ai">怎麼偵測 Shadow AI</h2>
<p>以下四個來源與廠商無關，多數公司手上已經有。</p>
<ol>
<li>費用報銷與信用卡帳單。搜尋過去 12 個月 AI 供應商與 AI SaaS 工具的商家名稱。同一位員工每月固定的小額扣款，通常代表有個人 API 金鑰在正式環境裡跑。</li>
<li>SSO 與 OAuth 授權紀錄。列出使用者透過「以某帳號登入」授權過的第三方應用程式，篩出不在核准清單上的 AI 工具與擴充功能。</li>
<li>對外連線與 DNS 紀錄。查看本不該呼叫 AI 供應商 API 網域的伺服器與 CI runner 是否有連線，以及筆電上看起來像腳本在跑的流量。</li>
<li>機密掃描。用你的機密掃描工具掃程式碼庫、CI 變數與 notebook，找 AI 供應商金鑰的格式。每一筆命中既是要輪替的外洩，也是一條要遷移的使用路徑。</li>
</ol>
<p>把結果當成遷移清單來用。如果大家因為掃描結果被懲處，下一次掃到的會變少，實際用量卻一樣在。</p>
<h2 id="怎麼把-shadow-ai-收回管控">怎麼把 Shadow AI 收回管控</h2>
<p>影子路徑大約五分鐘：註冊、綁卡、複製金鑰。核准路徑要接近這個速度，否則大家會繼續走影子路徑。讓核准路徑有競爭力的四件事：</p>
<ul>
<li>幾分鐘內就能拿到專案金鑰，每加一個新模型不必開一張採購單。</li>
<li>每個專案一份模型白名單，存取權限決定一次，每次呼叫都強制執行。</li>
<li>一筆小額沙盒預算，不會長成意外帳單。</li>
<li>逐筆請求紀錄，看得出每次呼叫來自哪個專案、哪把金鑰、哪個模型。</li>
</ul>
<h2 id="在-atp-token-上怎麼設定">在 ATP Token 上怎麼設定</h2>
<p>ATP Token 讓每個團隊用一把專案金鑰，透過 OpenAI、Anthropic 與 Gemini SDK 使用 11 家廠商的 70+ 個模型，上述控管都在閘道層執行。</p>
<h3 id="步驟-1-建立-team-組織與沙盒工作區">步驟 1：建立 Team 組織與沙盒工作區</h3>
<p>建立 Team 組織，才能邀請成員與指派角色；接著在正式工作區旁邊新增一個實驗用工作區。見<a href="/zh-tw/docs/console-setup/" class="doc-term-def" data-def="帳號的最上層，底下再分 工作區 與 專案。">設定組織</a>。</p>
<h3 id="步驟-2-每個團隊建一個專案並選擇允許的模型">步驟 2：每個團隊建一個專案並選擇允許的模型</h3>
<p>在 Resources 頁建立專案，選擇允許的模型（至少一個）。呼叫清單以外的模型，會在送到任何供應商之前就回傳 <code>403</code>，流程見<a href="/zh-tw/docs/how-it-works/">運作方式</a>。想先比較模型的人，可以在寫程式之前先到主控台的 Studio 試用。</p>
<h3 id="步驟-3-分配一筆小額預算">步驟 3：分配一筆小額預算</h3>
<p>例如分配 2,000 <a class="doc-term" href="/zh-tw/docs/credits/" data-def="計費單位。1 點＝USD 0.01；用量依各模型牌價換算成點數扣抵。">點數</a>（20 美元，1 點數 = 0.01 美元）給沙盒專案。專案只能花被分配到的額度，分配額就是上限；餘額用完時請求會回傳 <code>402</code>。操作步驟見<a href="/zh-tw/docs/cb-budget-caps/">團隊預算上限設定</a>，額度怎麼抓可參考<a href="/zh-tw/blog/ai-spending-caps-that-work/">有效的 AI 花費上限</a>。</p>
<h3 id="步驟-4-發一把金鑰-換掉影子腳本裡的那把">步驟 4：發一把金鑰，換掉影子腳本裡的那把</h3>
<p>金鑰以 <code>atp-</code> 開頭，只顯示一次。以實例 2 的逐字稿腳本來說，要改的只有 base URL 與金鑰：</p>
<pre><code class="language-python">import os
from openai import OpenAI

client = OpenAI(
    base_url=&quot;https://api.atptoken.ai/v1&quot;,
    api_key=os.environ[&quot;ATP_API_KEY&quot;],  # 專案金鑰
)
</code></pre>
<p>實例 5 的程式碼 Agent，則用環境變數把 Claude Code 指向閘道，做法見<a href="/zh-tw/docs/cb-claude-code/">在 ATP 上執行 Claude Code</a>：</p>
<pre><code class="language-bash">export ANTHROPIC_BASE_URL=&quot;https://api.atptoken.ai&quot;
export ANTHROPIC_AUTH_TOKEN=&quot;atp-...&quot;
export ANTHROPIC_API_KEY=&quot;&quot;
export ANTHROPIC_MODEL=&quot;claude-sonnet-4-6&quot;
</code></pre>
<p>模型 ID 必須在專案的允許清單上，例如 <a href="/zh-tw/models/claude-sonnet-4-6/">Claude Sonnet 4.6</a>。</p>
<h3 id="步驟-5-用正確的角色加入成員">步驟 5：用正確的角色加入成員</h3>
<p>在工作區或專案層級以 Member 身分邀請同事，他們可以使用預算但不能挪動；Admin 負責管理金鑰與分配。見<a href="/zh-tw/docs/team/">團隊與角色</a>。</p>
<h3 id="步驟-6-檢視用量-離職時撤銷金鑰">步驟 6：檢視用量，離職時撤銷金鑰</h3>
<p>用量頁依模型與金鑰拆分點數與 token。請求紀錄逐筆列出時間、範圍、模型、狀態、請求 ID 與 token 數，保留 7 天，定位是除錯用。活動紀錄則記下登入、邀請與額度變更（<a href="/zh-tw/docs/monitoring/">用量與紀錄</a>）。有人離職時，在 API 金鑰頁撤銷他的專案金鑰：撤銷後立即失效，並留在清冊中供稽核（<a href="/zh-tw/docs/console-keys/" class="doc-term-def" data-def="以 atp- 開頭的金鑰，繼承所屬 專案 的允許模型清單與點數餘額。">管理 API 金鑰</a>）。</p>
<p>ATP 只看得到經過它的流量。聊天機器人帳號、擴充功能與 SaaS 功能仍要靠上面的偵測方法；改變的是，你找到的腳本與 Agent 有了一條核准的路可以搬過去。</p>
