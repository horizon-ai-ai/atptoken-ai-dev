<h2 id="token-成本計算公式">token 成本計算公式</h2>
<p>任何按 token 計價的 API，單次請求的成本都來自同樣三步：</p>
<ol>
<li>輸入成本 = 輸入 token × 輸入單價 ÷ 1,000,000</li>
<li>輸出成本 = 輸出 token × 輸出單價 ÷ 1,000,000</li>
<li>請求成本 = 輸入成本 + 輸出成本</li>
</ol>
<p>在 ATP Token 上，這筆費用會以點數從<a class="doc-term" href="/zh-tw/docs/resources/" data-def="權限與帳務的最小單位；金鑰、允許模型、點數預算都掛在 專案 上。">專案</a>餘額扣除，<a href="/zh-tw/docs/credits/" class="doc-term-def" data-def="計費單位。1 點＝USD 0.01；用量依各模型牌價換算成點數扣抵。">1 點 = 0.01 美元</a>。點數 = 美元成本 × 100。</p>
<h3 id="實算-一則客服機器人回覆">實算：一則客服機器人回覆</h3>
<p>客服機器人送出 1,284 token 的提示（系統提示、檢索到的說明中心段落、客戶訊息）給 claude-sonnet-4-6，單價為每 100 萬 token 輸入 $3、輸出 $15，拿回 412 token 的回答。</p>
<ul>
<li>輸入：1,284 × $3 ÷ 1,000,000 = $0.003852</li>
<li>輸出：412 × $15 ÷ 1,000,000 = $0.00618</li>
<li>合計：$0.010032 = 1.0032 點</li>
</ul>
<p>每月 10 萬則回覆就是 $1,003.20。這筆請求裡輸出只佔 token 數的 24%，卻佔成本的 61.6%。</p>
<h3 id="可以直接貼上的-token-成本計算器">可以直接貼上的 token 成本計算器</h3>
<p>SDK 回傳的內容本來就帶有 token 數。OpenAI 格式的欄位是 <code>usage.prompt_tokens</code> 與 <code>usage.completion_tokens</code>，Anthropic 格式則是 <code>usage.input_tokens</code> 與 <code>usage.output_tokens</code>。</p>
<pre><code class="language-python">RATES = {  # 每 100 萬 token 美元：(輸入, 輸出)，ATP 牌價
    &quot;gpt-5.5&quot;: (5.00, 30.00),
    &quot;claude-sonnet-4-6&quot;: (3.00, 15.00),
    &quot;gemini-3-5-flash&quot;: (1.50, 9.00),
    &quot;deepseek-v4-flash&quot;: (0.20, 0.40),
    &quot;qwen-3-7-flash&quot;: (0.03, 0.13),
}

def token_cost(model, input_tokens, output_tokens):
    rate_in, rate_out = RATES[model]
    usd = (input_tokens * rate_in + output_tokens * rate_out) / 1_000_000
    return usd, usd * 100  # (美元, ATP 點數)

print(token_cost(&quot;claude-sonnet-4-6&quot;, 1284, 412))  # 約 (0.010032, 1.0032)
</code></pre>

<h2 id="快取輸入與推理-token">快取輸入與推理 token</h2>
<p>原廠價目表上有兩種 token，第一次讀帳單的人最容易卡住。</p>
<h3 id="快取輸入是原廠的計價功能">快取輸入是原廠的計價功能</h3>
<p>部分原廠對從快取命中的重複提示前綴另訂較低單價。OpenAI 列出 GPT-5.5 的快取輸入為每 100 萬 token $0.50，一般輸入是 $5（<a href="https://developers.openai.com/api/docs/pricing" target="_blank" rel="noopener noreferrer">OpenAI 定價</a>）。Anthropic 多數模型的快取讀取是基本輸入單價的 0.1 倍，快取寫入為 1.25 倍（5 分鐘）或 2 倍（1 小時）（<a href="https://platform.claude.com/docs/en/about-claude/pricing" target="_blank" rel="noopener noreferrer">Anthropic 定價</a>）。這些是依各原廠快取規則直接呼叫時的原廠單價。ATP Token 依<a href="/zh-tw/docs/pricing-model/">計價模式</a>以輸入與輸出 token 計費，所以 ATP 預算請用輸入與輸出牌價來估。</p>
<h3 id="推理-token-按輸出計費">推理 token 按輸出計費</h3>
<p>推理模型回答前會先思考，這些看不見的 token 也要付費。OpenAI 寫明推理 token 以輸出 token 計費（<a href="https://developers.openai.com/api/docs/guides/reasoning" target="_blank" rel="noopener noreferrer">OpenAI 推理指南</a>），Anthropic 也把 extended thinking 的 token 按輸出計費（<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code 成本</a>）。如果上面那則客服回覆在 claude-sonnet-4-6 上用了 1,500 個 thinking token，就多出 1,500 × $15 ÷ 1,000,000 = $0.0225，單次成本從 $0.010032 變成 $0.032532，約 3.2 倍。</p>
<p>推理預算也能解釋一種令人困惑的紀錄：回傳 <code>200</code> 但內容是空的。<code>max_tokens</code> 設太低時，模型把預算全用在思考，沒有產出文字。在 ATP 上這種請求通常顯示零用量、不扣點數；解法是調高 <code>max_tokens</code>（<a href="/zh-tw/docs/errors/">錯誤代碼</a>）。</p>
<h2 id="單筆請求紀錄告訴你什麼">單筆請求紀錄告訴你什麼</h2>
<p>月總額只說得出花了多少。單筆請求紀錄說得出是哪個專案、哪個模型、用了多少 token。下面是示意用的紀錄，列出計算單次成本需要的欄位，並非 ATP 實際的紀錄格式。</p>
<pre><code class="language-json">{
  &quot;request_id&quot;: &quot;req_example_01&quot;,
  &quot;project&quot;: &quot;support-bot-prod&quot;,
  &quot;model&quot;: &quot;claude-sonnet-4-6&quot;,
  &quot;input_tokens&quot;: 1284,
  &quot;output_tokens&quot;: 412,
  &quot;cost_usd&quot;: 0.010032,
  &quot;cost_credits&quot;: 1.0032
}
</code></pre>
<p>在 ATP Token 裡，這些資訊分在三個地方：</p>
<ul>
<li>請求紀錄，每次呼叫一列：時間、範圍（工作區與專案）、模型、端點、HTTP 狀態、供應商結果、輸入與輸出 token、計費狀態與請求 ID。可依時間範圍、範圍、模型、狀態或請求 ID 篩選（<a href="/zh-tw/docs/monitoring/">用量與紀錄</a>）。保留 7 天，費用異常要在一週內查。</li>
<li>帳務事件，也就是逐筆計費帳本，主控台以 90 天呈現，可依模型、金鑰、計費狀態或請求 ID 篩選（<a href="/zh-tw/docs/console-api-billing/">帳務 API</a>）。計費以這份帳本為準。</li>
<li>用量頁，依模型與 <a class="doc-term" href="/zh-tw/docs/console-keys/" data-def="以 atp- 開頭的金鑰，繼承所屬 專案 的允許模型清單與點數餘額。">API 金鑰</a>彙總一段期間的點數與 token。</li>
</ul>
<p>每個回應也都帶有 <code>x-request-id</code> 標頭，工程師可以把應用程式日誌裡的某次呼叫，對到主控台裡的那一列。</p>
<h2 id="三種帳單異常與查法">三種帳單異常與查法</h2>
<h3 id="某一週費用突然跳升">某一週費用突然跳升</h3>
<p>用量頁按 API 金鑰排序。如果金鑰和專案一對一，跳升馬上落到某個負責人身上。接著在請求紀錄裡篩選該專案，比較跳升前後每次請求的 token 數。輸入從約 1,300 漲到 13,000 token，通常是有人開始每一輪都送整份文件。</p>
<h3 id="單價沒錯-總額卻對不上">單價沒錯，總額卻對不上</h3>
<p>檢查模型組合。把 10 萬則客服回覆中的 20% 從 claude-sonnet-4-6 改到 gpt-5.5，流量不變，那個月就從 $1,003.20 變成 $1,178.16。</p>
<h3 id="請求成功卻沒有文字">請求成功卻沒有文字</h3>
<p>找推理模型上輸出 token 為零的 <code>200</code> 紀錄，把 <code>max_tokens</code> 調到足以涵蓋思考加上回答。</p>
<h2 id="在-atp-token-上怎麼設定">在 ATP Token 上怎麼設定</h2>
<ol>
<li>每個服務、每個環境各建一個專案，各配一把 <code>atp-</code> 金鑰，用量頁「依金鑰」就等於「依負責人」。</li>
<li>為每個專案分配點數。分配額就是專案的上限，餘額用完時呼叫會回傳 <code>402</code>（<a href="/zh-tw/docs/cb-budget-caps/">預算上限設定</a>）。專案也可以開啟自動<a class="doc-term" href="/zh-tw/docs/topup/" data-def="為錢包加值點數，USD 5 起儲值，用多少付多少。">儲值</a>，設定觸發門檻與每月上限。</li>
<li>記錄每個回應的 <code>usage</code> 與模型 ID，每週依專案跑一次上面的計算器。</li>
<li>月底以帳務事件對帳，7 天內的細節用請求紀錄追查。</li>
</ol>
