<h2 id="財務會遇到的三種-ai-計價模式">財務會遇到的三種 AI 計價模式</h2>
<p>截至 2026 年 10 月，<a href="https://claude.com/pricing" target="_blank" rel="noopener noreferrer">Claude 定價頁</a>上同一家原廠就有三種模式：</p>
<ul>
<li>按席次：Claude Team 標準席次月繳每席每月 $25，年繳為 $20。Premium 席次月繳 $125、年繳 $100。</li>
<li>席次加用量：Claude Enterprise 寫的是「席次價 + 依 API 單價計算的用量」，每席每月 $20、年繳，用量成本隨模型與任務增減。</li>
<li>Token 計價：API 依 token 收費。Claude Sonnet 4.6 為每 100 萬輸入 token $3、每 100 萬輸出 token $15（<a href="https://platform.claude.com/docs/en/about-claude/pricing" target="_blank" rel="noopener noreferrer">Anthropic 定價</a>），與 <a href="/zh-tw/models/claude-sonnet-4-6/">claude-sonnet-4-6</a> 的 ATP 牌價相同。</li>
</ul>
<p>多數公司最後是混合使用：整天跟模型對話的人用席次，從程式呼叫模型的應用、自動化與 agent 用 token 計價。</p>
<h2 id="實算對照-40-人團隊">實算對照：40 人團隊</h2>
<p>假設一個月 21 個工作日，所有請求都用 claude-sonnet-4-6（$3 / $15）：</p>
<ul>
<li>一般請求為 3,000 輸入、600 輸出 token：3,000 × $3 ÷ 100 萬 + 600 × $15 ÷ 100 萬 = $0.009 + $0.009 = $0.018。</li>
<li>長文件請求為 20,000 輸入、600 輸出 token：$0.06 + $0.009 = $0.069。</li>
</ul>

<p>同樣 40 人用 Claude Team 標準席次，月繳是 40 × $25 = 每月 $1,000，年繳是 40 × $20 = $800。</p>
<p>財務可以從這張表看出三件事：</p>
<ol>
<li>打平點要逐人看。每次 $0.018 時，使用者每月 $25 ÷ $0.018 = 1,389 次請求才與 $25 席次打平，約每個工作日 66 次。每次 $0.069 時約每月 362 次，也就是每個工作日 17 次。</li>
<li>重度群組每人 token 成本 $57.96，是 $25 席次的兩倍以上；輕度群組每人不到 $1。</li>
<li>這個對照只算模型用量。席次包含原廠的對話 App 與功能；token 用量則需要內部工具或整合來呼叫 API，那也有成本。</li>
</ol>
<p>Agent 類工作的量級完全不同。Anthropic 表示 Claude Code 平均每位開發者每個活躍日約 $13，每月約 $150 到 $250（<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code 成本</a>），是上面對話用量的好幾倍。Coding agent 請獨立編列一行預算。</p>
<h2 id="以專案點數做內部分攤">以專案點數做內部分攤</h2>
<p>席次的內部分攤很單純：各部門席次數 × 單價。Token 的分攤多一步，因為花費落在工作負載上，不直接對應到人。月底結帳時站得住的做法是：</p>
<ul>
<li>每個工作負載是一個專案、有自己的金鑰，各部門一個工作區。</li>
<li>財務為組織儲值，每個專案每月分配一筆點數（1 點 = 0.01 美元）。</li>
<li>各成本中心依實際消耗的點數計費，與分配額無關。</li>
</ul>

<h2 id="token-預算為什麼會失準">Token 預算為什麼會失準</h2>
<ul>
<li>換模型。proposal-drafts 從 gpt-5.5 換到 claude-sonnet-4-6，用量不變，每次成本從 $0.075 變成 $0.0405。換之前與換之後都可以查<a href="/zh-tw/models/compare/">模型比較頁</a>。</li>
<li>上下文變長。support-bot 的提示從 1,284 漲到 4,000 輸入 token，每則回覆成本從 $0.010032 變成 $0.01818。</li>
<li>推理 token。OpenAI 與 Anthropic 都把推理 token 按輸出計費，開啟 extended thinking 可能讓輸出成本成倍增加，回答看起來卻沒變。</li>
<li>Agent。每一步都重送上下文；Anthropic 表示在 plan mode 下，agent teams 的 token 用量約是一般工作階段的 7 倍。</li>
</ul>
<p>每週比對一次已消耗與已分配，四種情況都能在月底前抓到。數字怎麼讀，見 <a href="/zh-tw/blog/how-to-read-your-ai-bill/">LLM token 成本怎麼算</a>。</p>
<h2 id="在-atp-token-上怎麼設定">在 ATP Token 上怎麼設定</h2>
<ol>
<li>建立 Team 組織，每個部門一個工作區、每個工作負載一個專案（<a href="/zh-tw/docs/console-setup/" class="doc-term-def" data-def="帳號的最上層，底下再分 workspace 與 project。">設定組織</a>）。</li>
<li>在帳務頁儲值（最低 5 美元；方案有 5、50、200、1,000 美元），再從組織把點數分配到工作區與專案（<a href="/zh-tw/docs/topup/" class="doc-term-def" data-def="為錢包加值點數，最低 5 美元，用多少付多少。">儲值與錢包</a>）。儲值不可退款。</li>
<li>設定每個專案的可用模型並建立 <code>atp-</code> 金鑰，讓依金鑰的花費等於依專案的花費。</li>
<li>每週在用量頁的分配樹比對 Allocated 與 Consumed（<a href="/zh-tw/docs/spend/">追蹤花費</a>）。</li>
<li>月底用帳務事件結帳，依各成本中心消耗的點數分攤（<a href="/zh-tw/docs/credits/" class="doc-term-def" data-def="計費單位。1 美元 = 100 點；用量依各模型牌價換算成點數扣抵。">點數怎麼運作</a>）。</li>
</ol>
