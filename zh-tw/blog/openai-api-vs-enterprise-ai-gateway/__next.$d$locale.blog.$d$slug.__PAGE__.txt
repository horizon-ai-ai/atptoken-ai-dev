<h2 id="何時直連夠用">何時直連夠用</h2>
<p>一產品、一供應商、少數金鑰、財務暫可接受原廠後台。</p>
<h2 id="何時控制層划算">何時控制層划算</h2>
<p>第二供應商或模態、coding agent 與正式共用預算、財務要問哪個團隊、資安要撤銷與白名單預設。</p>
<h2 id="遷移形狀">遷移形狀</h2>
<p>本體不變；改 base URL 與 key；對齊模型 id；開白名單；分配點數；在<a href="/zh-tw/docs/monitoring">紀錄</a>驗證。</p>
<h2 id="更現代的做法">更現代的做法</h2>
<p>Horizon AI 導入常以閘道為標準，讓 PoC 第一天就有權限與計量。ATP Token 實作階層、白名單、點數 cap 與請求 log，並相容三大格式。</p>

<h2 id="常見問題">常見問題</h2>
<h3 id="openai-api-與-ai-閘道有何不同">OpenAI API 與 AI 閘道有何不同？</h3>
<p>OpenAI API 是模型供應商介面。企業 AI 閘道位於客戶端與一家或多家供應商之間，負責金鑰、模型授權、路由、計量與紀錄。</p>
<h3 id="公司何時不該再只直連-openai">公司何時不該再只直連 OpenAI？</h3>
<p>當多團隊共用花費、導入第二家供應商、財務要專案歸屬，或資安要集中撤銷與白名單時。</p>
<h3 id="ai-閘道會取代-openai-嗎">AI 閘道會取代 OpenAI 嗎？</h3>
<p>不會。閘道不取代模型品質或訓練，而是增加治理與帳務整合。</p>
<h3 id="從-openai-遷到相容閘道有多難">從 OpenAI 遷到相容閘道有多難？</h3>
<p>通常改 base URL 與 API 金鑰；模型 id 需對齊目錄與白名單。</p>
<h3 id="能否在同一企業閘道使用-anthropic-與-gemini">能否在同一企業閘道使用 Anthropic 與 Gemini？</h3>
<p>支援多格式的閘道可以，並以專案金鑰約束。</p>
