<p>工程師最常略過的是狀態碼那一欄，而它決定了用戶端接下來怎麼做。429 看起來像一般的速率限制，多數 SDK 會自動重試。Anthropic 文件特別註明，花費等級上限的 429 不帶 <code>retry-after</code> 標頭，在恢復之前重試都會失敗。402 或 400 重試也不會成功。用戶端應該讀錯誤內容，然後停下來。</p>
<h2 id="各平台怎麼執行花費上限">各平台怎麼執行花費上限</h2>
<h3 id="openai-專案花費上限">OpenAI：專案花費上限</h3>
<p>OpenAI 建議把 staging 與正式環境分成不同專案，並且可以<a href="https://developers.openai.com/api/docs/guides/production-best-practices" target="_blank" rel="noopener noreferrer">替每個專案設定自訂的速率與花費上限</a>。在專案的 Limits 設定裡，可以設定每月花費上限、通知門檻，以及這個專案能用哪些模型（<a href="https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform" target="_blank" rel="noopener noreferrer">OpenAI Help Center</a>）。</p>
<p>花費提醒會發通知，流量照常。硬性花費上限會讓受影響的請求回傳 429。兩者之上還有用量等級：Tier 1 每月 USD 100，Tier 5 每月 USD 200,000。要注意的是狀態碼共用。處理速率限制的重試迴圈，如果不檢查錯誤內容，會一直打一個預算已經用完的專案。</p>
<h3 id="anthropic-console-工作區花費上限">Anthropic Console：工作區花費上限</h3>
<p>Claude Console 的<a href="https://platform.claude.com/docs/en/manage-claude/workspaces" target="_blank" rel="noopener noreferrer">工作區</a>各自有每月花費上限與速率上限，只能設得比組織低，不能更高。API 金鑰可以限定在單一工作區。Default Workspace 無法設定上限，所以想被管住的金鑰要放在具名的工作區。</p>
<p>到達你自己設定的上限時，請求回傳 HTTP 400（<code>invalid_request_error</code>），訊息會寫何時恢復。等級上限（Start 每月 USD 500、Build USD 1,000、Scale USD 200,000）則回傳 429，用量暫停到下個月 1 日 00:00 UTC。Console 自動建立的 Claude Code 工作區，是唯一支援每位使用者每月花費上限的工作區。</p>
<h3 id="openrouter-guardrails-與單一金鑰點數上限">OpenRouter：guardrails 與單一金鑰點數上限</h3>
<p>OpenRouter 有兩套機制。Guardrails 由組織管理員針對成員或金鑰設定，可帶一個每日、每週或每月重置的美元花費上限；超過的請求收到 403。Guardrail 也能放模型白名單與供應商白名單，多個 guardrail 同時適用時，以最嚴格的規則為準。</p>
<p>單一金鑰點數上限所有方案都能用。每把金鑰有 <code>limit</code> 與 <code>limit_reset</code>（每日、每週、每月或不重置），在 UTC 午夜重置。額度用完的金鑰回傳 402。工作區層級預算則是 Enterprise 功能（<a href="https://openrouter.ai/blog/insights/governing-team-ai-spend/" target="_blank" rel="noopener noreferrer">OpenRouter 部落格</a>）。</p>
<h3 id="vercel-ai-gateway-疊加的預算">Vercel AI Gateway：疊加的預算</h3>
<p>Vercel 的預算有四種範圍（團隊、專案、API 金鑰、團隊成員），而且會疊加，一筆請求必須通過範圍內的每一個預算。重置週期可選每日、每週、每月或不重置，皆以 UTC 計。超過預算回傳 402 與 <code>quota_for_entity_exceeded</code>，訊息會寫出是哪個範圍用完。</p>
<p>Vercel 把預算定位為軟上限：檢查發生在每筆請求開始時，所以跨過上限的那一筆仍會完成。可選的 email 提醒在 50%、75%、100% 觸發。有兩個細節容易踩到：API 金鑰的花費永遠不會算進專案預算（專案預算只看該專案部署的 OIDC token），BYOK 的花費也不計入任何預算。</p>
<h3 id="atp-token-每個專案的預付分配">ATP Token：每個專案的預付分配</h3>
<p>在 ATP Token，上限就是錢本身。點數（1 點 = USD 0.01）由組織撥到工作區、再撥到專案，每把金鑰都從自己專案的餘額扣。專案只能花掉分配給它的額度。餘額用盡時，閘道在計量階段以 402 拒絕請求（<a href="/zh-tw/docs/how-it-works/">運作方式</a>）。花超過分配額度的專案會被標示為 In debt，直到補足為止。</p>
<p>這裡沒有重置週期。隨用隨付點數不會過期，沒用完的分配會留到下個月。所以月預算需要每月做一次分配，或使用專案自動<a class="doc-term" href="/zh-tw/docs/topup/" data-def="為錢包加值點數，最低 5 美元，用多少付多少。">儲值</a>：隨用隨付的專案在餘額低於門檻時自動補點，受單次扣款上限與每月扣款上限約束。開啟自動儲值後，真正的天花板是那個每月扣款上限。</p>
<h2 id="團隊願意遵守的上限設計原則">團隊願意遵守的上限設計原則</h2>
<ol>
<li><strong>每個工作負載分開設上限。</strong> 每個正式服務一個專案，staging 一個，每個沙盒一個。組織層級的總上限一觸發，所有產品會一起停，包括正常運作的那些。金鑰的部分請見<a href="/zh-tw/blog/one-project-one-key/">一專案一金鑰</a>。</li>
<li>在用戶端程式裡把預算錯誤當成終止狀態。402、Anthropic 的 400 上限錯誤、花費上限造成的 429，都對應到「停止並通知負責人」，不要套用指數退避重試。</li>
<li>每個上限都從單位成本推算。每筆請求的 token 數乘上模型費率，再乘上預估量，得到一個能向財務說明、流量變了也能調整的數字。</li>
<li>在最上層保留未分配的備用額度。正式環境如果在 27 號見底，管理員幾分鐘內就能撥點過去，不必動到 staging。</li>
<li>每週對照一次 Allocated 與 Consumed。ATP Token 的<a href="/zh-tw/docs/spend/">用量頁面</a>在每一層都同時顯示兩者。想要自動警示的話，可以從 <a href="/zh-tw/docs/console-api-usage/">Console API</a> 輪詢專案即時餘額，發到你自己的頻道。</li>
</ol>
<h2 id="實際算一次-每月-usd-2-000-的-ai-預算換成點數">實際算一次：每月 USD 2,000 的 AI 預算換成點數</h2>
<p>USD 2,000 等於 200,000 點。以下是拆給三個工作負載加一筆備用額度的一種做法。</p>

<p>客服機器人。claude-haiku-4-5 的 ATP 牌價是每百萬輸入 token USD 1、每百萬輸出 token USD 5。一則典型回覆用 2,000 個輸入 token、300 個輸出 token，成本是 2,000 × 1 / 1,000,000 + 300 × 5 / 1,000,000 = USD 0.0035，也就是 0.35 點。140,000 點 ÷ 0.35 = 每月 400,000 則回覆，約每天 13,300 則。</p>
<p>整個週末都在跑的 staging 任務。假設一個重試 bug 每秒打 5 次請求，每次一樣 0.35 點，等於每秒燒掉 1.75 點，10,000 點的 staging 分配大約撐 10,000 ÷ 1.75 ≈ 5,700 秒，約 95 分鐘。接著 staging 收到 402，正式環境照常回覆客戶。如果沒有拆開，同一個迴圈從週五 18:00 跑到週一 09:00（63 小時，226,800 秒），會花掉 226,800 × 1.75 = 396,900 點，幾乎是整個月預算的兩倍。</p>
<p>Coding agent。Anthropic 公布的 Claude Code 平均成本是<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">每位開發者每個活躍日約 USD 13</a>。照這個平均，USD 300 約可支撐 23 個開發者工作天，大約是一位開發者一個月的工作日。沙盒在下午撞到 402 時，先看那個 session 在做什麼，再決定要不要補點。為什麼 agent 每項任務比單次呼叫貴，請見<a href="/zh-tw/blog/what-is-the-agent-tax/">什麼是 agent 稅</a>。</p>
<p>下個月 1 日不會重置任何東西。如果客服機器人用掉 120,000 點，它還有 20,000 點；再撥 120,000 點就回到 140,000。</p>
<h2 id="在-atp-token-上怎麼設定">在 ATP Token 上怎麼設定</h2>
<ol>
<li>建立 Team 組織，再到 Resources 頁面建立工作區（Production、Pre-production、Engineering）（<a href="/zh-tw/docs/console-setup/" class="doc-term-def" data-def="帳號的最上層，底下再分 workspace 與 project。">設定組織</a>）。</li>
<li>建立每個專案並選擇允許的模型，每個專案至少一個（<a href="/zh-tw/docs/resources/" class="doc-term-def" data-def="這個 project 可以呼叫的模型清單；不在清單上的一律回 403。">工作區與專案</a>）。</li>
<li>沿著樹狀結構分配點數：組織、工作區、專案。備用額度留在組織層，不要分出去。</li>
<li>每個專案發一把金鑰，金鑰繼承該專案的模型與餘額（<a href="/zh-tw/docs/console-keys/" class="doc-term-def" data-def="以 atp- 開頭的金鑰，繼承所屬 project 的允許模型清單與點數餘額。">管理 API 金鑰</a>）。</li>
<li>在用戶端把 402 視為「預算用盡」，並通知專案負責人（<a href="/zh-tw/docs/errors/">常見回應</a>）。</li>
</ol>
