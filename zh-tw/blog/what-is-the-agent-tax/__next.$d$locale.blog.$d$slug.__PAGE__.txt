<h2 id="ai-agent-成本怎麼累加-20-步範例">AI agent 成本怎麼累加：20 步範例</h2>
<p>假設一個 agent 每項任務從 8,000 token 的基礎上下文開始（系統提示、工具定義、任務內容）。每一步附加約 2,000 token 的工具結果與模型輸出，每一步寫出 500 個輸出 token。因此第 <em>i</em> 步讀入 8,000 + 2,000 × (i − 1) 個輸入 token。</p>
<p>20 步的輸入 token：</p>
<p>Σ = 20 × 8,000 + 2,000 × (0 + 1 + … + 19) = 160,000 + 2,000 × 190 = <strong>540,000 token</strong></p>
<p>輸出 token：20 × 500 = 10,000。</p>
<p>基礎上下文只占輸入的 30%（540,000 中的 160,000），另外 70% 是同一批工具結果在後面的步驟中被重複讀入。光是最後 8 步就讀了 312,000 token，比前 12 步加起來（228,000）還多。</p>

<p>同樣的基礎上下文若用單輪回答，在 claude-sonnet-4-6 上是 8,000 × 3/M + 500 × 15/M = 0.024 + 0.0075 = 0.0315 美元。Agent 任務約是它的 56 倍。這個倍數就是 agent tax：費率沒變，變的是 token 數量。</p>
<p>Anthropic 公布過一個實際數字：在 Claude Code 中，隊友以 plan 模式執行時，agent teams 的 token 用量約為一般工作階段的 7 倍，因為每個隊友都有自己的上下文視窗（<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code 費用說明</a>）。</p>
<h2 id="降低-agent-tax-的五個做法">降低 agent tax 的五個做法</h2>
<h3 id="1-限制步數">1. 限制步數</h3>
<p>輸入大致隨步數的平方成長，貴的是後段的步驟。設定硬性上限，達到時回傳明確的失敗。如果同一項任務 12 步就能完成，輸入降到 12 × 8,000 + 2,000 × 66 = 228,000 token，每項任務從 1.77 美元降為 0.77 美元。</p>
<h3 id="2-工具輸出進入上下文前先摘要">2. 工具輸出進入上下文前先摘要</h3>
<p>把完整檔案內容與完整 API 回應換成簡短摘要，或只留關鍵的幾行。若每步增量從 2,000 降到 500 token，輸入變成 160,000 + 500 × 190 = 255,000 token：0.765 + 0.15 = 每項任務 0.92 美元，少 48%。</p>
<h3 id="3-子步驟改用較便宜的模型">3. 子步驟改用較便宜的模型</h3>
<p>很多步驟只是讀一段工具結果，再決定下一個要呼叫什麼。決策步驟留在 claude-sonnet-4-6，其餘交給 deepseek-v4-flash。以 6 個決策步驟、14 個子步驟、每步平均 27,000 個輸入 token 計：</p>
<ul>
<li>Sonnet：162,000 × 3/M + 3,000 × 15/M = 0.486 + 0.045 = 0.531 美元</li>
<li>Flash：378,000 × 0.2/M + 7,000 × 0.4/M = 0.0756 + 0.0028 = 0.078 美元</li>
<li>合計：每項任務約 0.61 美元，比全用 Sonnet 少 66%</li>
</ul>
<p>切換前先用自己的任務測試品質；<a href="/zh-tw/compare/deepseek-vs-claude/">DeepSeek 與 Claude 比較</a>可以當起點。</p>
<h3 id="4-在供應商支援時使用-prompt-caching">4. 在供應商支援時使用 prompt caching</h3>
<p>Agent 的大部分輸入，是上一步已經送過的前綴。在 Anthropic 自家 API 上，快取讀取的費率是基本輸入的 0.1 倍，5 分鐘快取寫入是 1.25 倍（<a href="https://platform.claude.com/docs/en/about-claude/pricing" target="_blank" rel="noopener noreferrer">Anthropic 定價</a>）。在 20 步範例中，540,000 個輸入 token 有 494,000 個是重複內容。以 Anthropic 的 Sonnet 4.6 費率計，是 494,000 × 0.30/M + 46,000 × 3.75/M + 0.15 美元輸出 = 0.148 + 0.173 + 0.15，每項任務約 0.47 美元。快取有存活時間，等待慢速工具的步驟可能錯過快取。要依賴這個做法前，先確認你的供應商如何計算快取 token。</p>
<h3 id="5-給每個-agent-獨立的預算">5. 給每個 agent 獨立的預算</h3>
<p>把每個 agent 放進自己的<a class="doc-term" href="/zh-tw/docs/resources/" data-def="權限與帳務的最小單位；金鑰、允許模型、點數預算都掛在 專案 上。">專案</a>，並分配<a class="doc-term" href="/zh-tw/docs/credits/" data-def="計費單位。1 點＝USD 0.01；用量依各模型牌價換算成點數扣抵。">點數</a>給它。專案只能花被分配到的額度，餘額用完後請求會回傳 <code>402</code>，卡住的迴圈會停在上限，而不是拖到月底才被發現。每月 10,000 項 Sonnet 任務，分配額度就是 1,770,000 點（1 點 = 0.01 美元）。設定方式見<a href="/zh-tw/docs/cb-budget-caps/">設定有預算上限的團隊</a>。</p>
<h2 id="如何衡量每項完成任務的成本">如何衡量每項完成任務的成本</h2>
<p>閘道看得到請求，但只有你的應用程式知道哪些請求屬於同一項任務。ATP 的每個回應都帶有 <code>x-request-id</code> 標頭。把它和你自己的任務或工作階段 ID、步驟編號，以及任務最後是否成功一起記錄。</p>
<p>接著：</p>
<ol>
<li>從請求紀錄取出這些 request ID 對應的列，每列顯示模型、狀態與輸入／輸出 token（<a href="/zh-tw/docs/monitoring/">用量與紀錄</a>）。紀錄保留 7 天，請每週用<a href="/zh-tw/docs/console-api-logs/">請求紀錄 API</a> 匯出。</li>
<li>把 token 乘上模型牌價，依任務加總。</li>
<li>用總成本（包含失敗與中途放棄的任務）除以完成的任務數。</li>
</ol>
<p>失敗的任務要算進分子。成功率 80%、每次嘗試 1.77 美元的 agent，每項完成任務的成本是 1.77 / 0.8 = 2.21 美元。</p>
<p>紀錄裡要留意一種模式：內容為空的 <code>200</code>。在推理模型上，這通常代表 <code>max_tokens</code> 不足以涵蓋思考預算。ATP 通常會回報零用量、不扣點數，但沒有調高 <code>max_tokens</code> 就重試的 agent，會一直重複這個空回應（<a href="/zh-tw/docs/errors/">錯誤</a>）。</p>
