</ol>

<h2 id="怎麼選-六個問題">怎麼選：六個問題</h2>
<h3 id="1-閘道必須跑在哪裡">1. 閘道必須跑在哪裡？</h3>
<p>如果流量不能經過第三方，候選名單就是自架：LiteLLM proxy、Helicone 開源閘道，或 Portkey 的開源與 VPC 選項。本文其他選項都是代管。</p>
<h3 id="2-想怎麼付錢">2. 想怎麼付錢？</h3>
<p>有三種模式：</p>
<ul>
<li>供應商價格加上儲值手續費。OpenRouter：Standard 刷卡 5.5%（最低 0.80 美元）、Business 8%（<a href="https://openrouter.ai/docs/faq" target="_blank" rel="noopener noreferrer">FAQ</a>）。</li>
<li>照供應商定價、token 不加價。Vercel AI Gateway，可能有金流手續費（<a href="https://vercel.com/docs/ai-gateway/pricing" target="_blank" rel="noopener noreferrer">定價</a>）。</li>
<li>預付點數，依各模型定價扣抵。ATP Token：1 點 = 0.01 美元，按量付費點數不會過期，儲值 5 美元起（<a href="/zh-tw/docs/credits/" class="doc-term-def" data-def="計費單位。1 點＝USD 0.01；用量依各模型牌價換算成點數扣抵。">點數</a>）。各模型費率見<a href="/zh-tw/pricing/">定價頁</a>。</li>
</ul>
<p>自架閘道沒有平台費，成本在供應商帳單與工程時間。</p>
<h3 id="3-預算綁在什麼上面-是硬上限嗎">3. 預算綁在什麼上面？是硬上限嗎？</h3>
<p>這是各閘道差最多的地方。</p>
<ul>
<li>OpenRouter：guardrails 裡的預算掛在成員或金鑰上，按日、週、月重置；工作區預算需 Enterprise（<a href="https://openrouter.ai/docs/guides/features/guardrails" target="_blank" rel="noopener noreferrer">guardrails</a>）。</li>
<li>Vercel：團隊、專案、金鑰、成員四種預算。Vercel 稱之為軟上限：跨過上限的那一筆仍會完成，之後的請求回傳 402（<a href="https://vercel.com/docs/ai-gateway/observability-and-spend/budgets" target="_blank" rel="noopener noreferrer">預算</a>）。</li>
<li>LiteLLM：依金鑰、使用者、團隊或客戶設預算，重置週期如 <code>30d</code>。</li>
<li>ATP Token：點數沿組織 → 工作區 → 專案往下撥，專案只能花自己的額度。沒有重置週期，專案用到餘額為零就回傳 402，直到有人再撥款（<a href="/zh-tw/docs/cb-budget-caps/">預算上限設定</a>）。</li>
</ul>
<p>週期重置的預算適合「這把金鑰每月不超過 500 美元」；預付額度適合「這條產品線這一季有 5,000 美元」。</p>
<h3 id="4-應用現在用哪些-sdk-格式">4. 應用現在用哪些 SDK 格式？</h3>
<p>多數閘道支援 OpenAI 格式。如果有服務用 Anthropic SDK（Claude Code 就是）或 Google GenAI SDK，要確認是否原生支援：OpenRouter 與 Vercel 有 Anthropic Messages 文件；ATP Token 可直接使用 OpenAI、Anthropic、Google GenAI 三種官方 SDK（<a href="/zh-tw/docs/sdk-openai/">OpenAI SDK</a>、<a href="/zh-tw/docs/sdk-anthropic/">Anthropic SDK</a>、<a href="/zh-tw/docs/sdk-google/">Google GenAI SDK</a>）。</p>
<h3 id="5-需要哪些模型與模態">5. 需要哪些模型與模態？</h3>
<p>OpenRouter 列出 80+ 家供應商、500+ 個模型。ATP Token 有 11 家供應商、70+ 個模型，包含 <a href="/zh-tw/models/seedance-2-0/">Seedance 2.0</a>、<a href="/zh-tw/models/kling-v3-pro/">Kling v3 Pro</a> 等影片模型，以及 <a href="/zh-tw/models/nano-banana-pro/">Nano Banana Pro</a> 等圖像模型（<a href="/zh-tw/docs/media/">媒體模型</a>）。如果只需要幾個前沿 LLM，目錄大小沒有其他問題重要。</p>
<h3 id="6-紀錄保留什麼-保留多久">6. 紀錄保留什麼、保留多久？</h3>
<p>Portkey 公布各方案的保留期：免費方案紀錄 3 天，Production 30 天。ATP Token 的請求紀錄保留 7 天，定位是除錯視圖，帳務以帳務事件為準（<a href="/zh-tw/docs/console-api-logs/">請求紀錄 API</a>）。如果每月檢討花費，請每週匯出或彙整。</p>
<h2 id="各閘道細看">各閘道細看</h2>
<h3 id="openrouter">OpenRouter</h3>
<ul>
<li>適合：需要最大的代管模型目錄、要快速評估模型。</li>
<li>控管：組織、工作區、含預算與模型及供應商白名單的 guardrails、ZDR 規則；所有方案都能對單把金鑰設點數上限。</li>
<li>要注意：購買點數的手續費、點數可能在一年後失效、開立發票只有 Enterprise。完整說明見 <a href="/zh-tw/blog/openrouter-vs-enterprise-governance/">OpenRouter 替代方案（團隊版）</a>。</li>
</ul>
<h3 id="vercel-ai-gateway">Vercel AI Gateway</h3>
<ul>
<li>適合：部署在 Vercel 的團隊，或想要照供應商定價計費的代管閘道。</li>
<li>控管：四種預算範圍、50/75/100% 花費通知、請求紀錄、供應商與模型容錯。</li>
<li>要注意：預算是軟上限；用自帶供應商金鑰的花費不計入預算；部分控管是付費加購。</li>
</ul>
<h3 id="litellm">LiteLLM</h3>
<ul>
<li>適合：想完全掌控、本來就在維運基礎設施的平台團隊。</li>
<li>控管：虛擬金鑰、多層預算、用 access group 管模型。</li>
<li>要注意：要自己維運。使用者與金鑰層級的依模型預算需要 Enterprise 授權。</li>
</ul>
<h3 id="portkey">Portkey</h3>
<ul>
<li>適合：希望閘道、觀測與 guardrails 在同一個產品裡的團隊。</li>
<li>控管：對供應商或虛擬金鑰設預算上限，可設通知門檻、每週或每月重置，適用 Enterprise 與部分 Pro 方案（<a href="https://portkey.ai/docs/product/ai-gateway/virtual-keys/budget-limits" target="_blank" rel="noopener noreferrer">預算上限</a>）。每月 49 美元的 Production 方案起有角色權限控管。</li>
<li>要注意：各方案有紀錄額度（免費每月 1 萬筆，Production 10 萬筆）。</li>
</ul>
<h3 id="helicone">Helicone</h3>
<ul>
<li>適合：以觀測為主的團隊；閘道開源，以 Rust 撰寫。</li>
<li>控管：記錄每筆請求的 token 與費用，支援 100+ 個模型的路由、容錯與快取。</li>
<li>要注意：預算與存取控管功能請依需求向廠商確認，閘道總覽文件中沒有看到。</li>
</ul>
<h3 id="atp-token">ATP Token</h3>
<ul>
<li>適合：多個團隊共用一筆 AI 預算，每個專案要有撥好的額度與審核過的模型清單。</li>
<li>控管：組織 → 工作區 → 專案的階層、綁專案的金鑰、每個專案的允許模型、以點數額度作為上限、逐筆請求紀錄、Owner／Admin／Member 角色（<a href="/zh-tw/docs/team/">團隊與角色</a>）。</li>
<li>要注意：模型目錄比 OpenRouter 小；點數不可退款；請求紀錄保留 7 天。</li>
</ul>
<h2 id="同時用兩個閘道">同時用兩個閘道</h2>
<p>很多團隊最後會有兩個：一個大目錄閘道做研究與評估，一個有治理的閘道跑正式環境。讓這種配置不出事的規則是：正式環境的金鑰不放在研究帳號裡，每個正式服務各有自己的金鑰與預算。參考<a href="/zh-tw/blog/one-project-one-key/">一專案一金鑰</a>。</p>
<h2 id="在-atp-token-上實際比一次">在 ATP Token 上實際比一次</h2>
<ol>
<li>建立一個專案，啟用兩三個想比較的模型，例如 <a href="/zh-tw/models/claude-sonnet-4-6/">claude-sonnet-4-6</a>、<a href="/zh-tw/models/gemini-3-5-flash/">gemini-3-5-flash</a> 與 <a href="/zh-tw/models/deepseek-v4-flash/">deepseek-v4-flash</a>。</li>
<li>撥少量點數當作這次測試的上限，例如 500 點（5 美元）。</li>
<li>把現有的 OpenAI、Anthropic 或 Google GenAI client 指向閘道，用同一組提示詞跑每個模型。</li>
<li>在請求紀錄裡比較每筆請求的 token 與點數（<a href="/zh-tw/docs/monitoring/">用量與紀錄</a>）。模型並排比較頁見 <a href="/zh-tw/compare/gemini-vs-gpt/">/compare</a>。</li>
</ol>
