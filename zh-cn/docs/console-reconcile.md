# 从一笔请求到月底对账

> Source: https://atptoken.ai/zh-cn/docs/console-reconcile/

用控制台把一笔请求一路追到账单：请求记录、点数扣款明细、可用天数，以及月底对账 CSV。

## 开始之前

- 一把已经送出过请求的项目 API 密钥。还没有的话，先照[快速开始](https://atptoken.ai/zh-cn/docs/quickstart/)做。
- 你要追的那笔请求的 request ID。每个回应的 `x-request-id` 标头都带着它，回应 body 里的 `id` 也是同一个值。
- 这四个画面都在控制台左栏的「用量」底下，是同一页的分页：用量、请求记录、点数扣款明细、对账。用量页顶端的工作区与项目筛选决定所有分页的范围。

## 1. 在请求记录找到这一笔

开「用量」→「请求记录」。控制台总览「最近请求」旁的「查看全部」也会开到这个分页。

可依时间范围（默认最近 24 小时；记录保留 7 天）、「状态」、「模型」或「Request ID」筛选——贴上完整的 Request ID。条件一改就立即套用。

| 栏位 | 显示什么 |
|---|---|
| Request ID | 这笔请求的 request ID，旁边有复制钮；联络支持时附上它 |
| 时间 | 依你的当地时区显示 |
| 模型 | 这笔请求呼叫的模型 ID |
| 调用身份 | 以密钥呼叫时显示密钥标签；从工作台发出的呼叫显示登录者 |
| 状态 | HTTP 状态码；400 以上会连到[错误码](https://atptoken.ai/zh-cn/docs/errors/)里对应的那一列 |
| 点数 | 这笔请求扣的点数，或它的扣款状态 |
| 请求用量 | 这笔请求回报的用量 |

宽萤幕另外显示「模态」与「端点」栏。同一个媒体任务的多次轮询会收成一列，可以展开。

> **请求记录不是扣款依据**
>
> 请求记录用来排查 API，保留 7 天，不作为最终扣款依据。帐务请看点数扣款明细与对账。

## 2. 在点数扣款明细确认扣款

请求记录的「点数」栏已经会显示扣款状态。要看某个账单月份的扣款明细，开「用量」→「点数扣款明细」。

| 状态 | `billing_status` | 「点数」栏显示 |
|---|---|---|
| 已扣款 | `billed` | 扣掉的点数，到小数 4 位 |
| 结算中 | `pending` | 结算中 |
| 未扣款 | `unbilled` | 未扣款 |
| 不收费 | `not_billable` | 不收费；状态码 400 以上且 0 点的请求，请求记录也显示不收费 |

点数扣款明细的栏位是 Request ID、时间、模型、模态、计费用量、状态、点数，可依账单月份、模态与状态筛选。用 Request ID 就能和请求记录对上同一笔。

列表仅含你本人的活动（你的密钥与你的控制台身份）；上方的本期合计是整个范围的全量。这里的账单月份以 UTC 计。

## 3. 看用量与可用天数

「用量」→「用量」显示所选范围的用量与消耗；「汇出 CSV」下载 UTC 月份的 `usage-{period}.csv`。

控制台总览的「今天」一列有「可用天数」：照最近的消耗速度，可用点数还能撑几天。

- 可用天数＝（可用余额 − 未结算保留）÷ 你本人密钥的日均消耗，无条件舍去。
- 日均取今天以前最多 7 个完整 UTC 日，不含今天。
- 完整日不足 3 天时，卡片显示需满 3 个完整日，不显示天数。
- 可用天数低于 7 天、而且没有自动充值在顾时，总览会出现提醒并写出剩几天。

团队组织的可用天数，是用组织余额除以你本人密钥的日均。

## 4. 汇出月底对账 CSV

开「用量」→「对账」，选月份。月份以台湾时间（UTC+8）计，可选最近 15 个月。

表格把计费帐本的小时数据按「台湾日 × 模型 × 模态」加总，栏位是日期（台湾）、模型、模态、请求数、点数。同一天有多列时收成「当日小计」，上方卡片是本月各模态合计。金额单位是点数。

「汇出 CSV」下载 `atp-reconcile-{YYYY-MM}.csv`；选了项目时档名结尾加 `-project`，只选工作区时加 `-workspace`。

```text
date,model,modality,requests,credits_charged
YYYY-MM-DD,"<model>",<modality>,<requests>,<credits>
YYYY-MM TOTAL,,,<requests>,<credits>
```

CSV 的点数到小数 6 位。文件是带 BOM 的 UTF-8、CRLF 换行，用 Excel 开繁体中文不会乱码。

> **结算前请再确认**
>
> 还有媒体任务未落帐时，对账会显示尚有几笔——总额仍可能变动。

## 确认成功

- 回应里的 Request ID 在请求记录与点数扣款明细都找得到。
- CSV 的 `TOTAL` 列等于对账分页的「本月合计」。
- 对账是你本人的用量（你的密钥＋控制台身份）；整个组织的月合计看点数扣款明细的本期合计。
- 点数扣款明细与用量 CSV 用 UTC 月份，对账用台湾月份。台湾月份的前 8 小时落在上一个 UTC 月，所以两边的月合计在月界附近可能不同。
