3:T643,<p>Gateway 可从下列位置读取<a class="doc-term" href="/zh-cn/docs/resources/" data-def="权限与帐务的最小单位；密钥、允许模型、点数预算都挂在 项目 上。">项目</a>（project）<a class="doc-term" href="/zh-cn/docs/console-keys/" data-def="以 atp- 开头的密钥，继承所属 项目 的允许模型清单与点数余额。">API 密钥</a>。<code>Authorization: Bearer</code> 和 <code>x-api-key</code> 在每个端点都有效，所以官方 OpenAI、Anthropic、Google GenAI SDK 都不用改，只要换 base URL。Gateway 会在转送请求前移除这把密钥。</p>
<h2 data-md="h2" id="先拿到密钥" class="group">先拿到密钥<a href="#先拿到密钥" aria-label="此段链接" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>密钥不是从 API 申请的。到 <a href="https://atptoken.ai" target="_blank" rel="noopener noreferrer">atptoken.ai</a> 登录，依序选择或建立 <a class="doc-term" href="/zh-cn/docs/console-setup/" data-def="账号的最上层，底下再分 工作区 与 项目。">组织</a> → 工作区 → 项目，再到项目里建立密钥。一把密钥属于一个项目：能用哪些模型、费用算在谁头上，都由那个项目决定。见<a href="/zh-cn/docs/console-keys/">管理 API 密钥</a>。</p>
<h2 data-md="h2" id="密钥放在哪里" class="group">密钥放在哪里<a href="#密钥放在哪里" aria-label="此段链接" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>4:Tdda,<h2 data-md="h2" id="验证失败时" class="group">验证失败时<a href="#验证失败时" aria-label="此段链接" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>没带、被停用、过期或不存在的密钥，都回 <code>401</code>，代码是 <code>token_revoked</code>，消息是「API key has been revoked or does not exist」。<strong>完全没送密钥也是同一个错误</strong>，所以先确认 header 真的有送出去，再怀疑密钥本身。</p>
<p><code>403</code> 是另一回事：密钥没问题，但模型不在这个项目的允许清单上。见<a href="/zh-cn/docs/errors/">错误码</a>。</p>
<h2 data-md="h2" id="登录控制台" class="group">登录控制台<a href="#登录控制台" aria-label="此段链接" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<p>申请密钥、<a class="doc-term" href="/zh-cn/docs/topup/" data-def="为钱包加值点数，USD 5 起充值，用多少付多少。">充值</a>、读控制台 API，起点都一样：有一个人到 <a href="https://atptoken.ai" target="_blank" rel="noopener noreferrer">atptoken.ai</a> 登录。在你依赖登录做任何东西之前，有两件事要先知道。</p>
<h3 data-md="h3" id="登录要过人机验证" class="group">登录要过人机验证<a href="#登录要过人机验证" aria-label="此段链接" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>登录需要通过人机验证，而只有浏览器答得出来。没带答案的请求回 <code>400</code>，<code>reason</code> 是 <code>captcha_required</code>；答案验不过的回 <code>400</code>，<code>reason</code> 是 <code>captcha_invalid</code>。</p>
<p>它存在的理由是：有人被锁在自己的账号外面。脚本一个账号一个账号地猜密码，而唯一的防线是单一账号的失败次数上限——那挡住的是真正的持有人，对脚本毫无作用，因为它换下一个账号就好。人机验证在第一个请求就挡下整轮。验证失败不会让你付代价：只有密码真的错了，失败次数才会增加。</p>
<p>每一次登录都要过。没有「失败几次之后才开始要求」这种门槛，也没有可以申请的例外。</p>
<h3 data-md="h3" id="连结外部登录方式之后-密码就不能用了" class="group">连结外部登录方式之后，密码就不能用了<a href="#连结外部登录方式之后-密码就不能用了" aria-label="此段链接" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>你可以把一个外部登录方式连结到账号上，用它取代密码。连结第一个时同样要过人机验证，而且它会改变这个账号：账号变成无密码，原本的密码会被删除。你记得的那组密码就不再是入口——不是暂停，是删掉。</p>
<p>之后再连结第二个不会再有变化，因为密码在第一个就一起走了。</p>
<p>要把密码这条路拿回来，是管理员的动作：由管理员把账号改回密码模式，你再用「忘记密码」设一组新的。从你自己的账号里，没有任何操作能把原来那组找回来。</p>
