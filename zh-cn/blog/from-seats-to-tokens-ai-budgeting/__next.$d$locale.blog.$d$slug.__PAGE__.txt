<h2 id="财务会遇到的三种-ai-计价模式">财务会遇到的三种 AI 计价模式</h2>
<p>截至 2026 年 10 月，<a href="https://claude.com/pricing" target="_blank" rel="noopener noreferrer">Claude 定价页</a>上同一家厂商就有三种模式：</p>
<ul>
<li>按席位：Claude Team 标准席位按月付费为每席每月 $25，按年付费为 $20。Premium 席位按月 $125、按年 $100。</li>
<li>席位加用量：Claude Enterprise 写的是「席位价 + 按 API 单价计算的用量」，每席每月 $20、按年付费，用量成本随模型与任务变化。</li>
<li>Token 计价：API 按 token 收费。Claude Sonnet 4.6 为每 100 万输入 token $3、每 100 万输出 token $15（<a href="https://platform.claude.com/docs/en/about-claude/pricing" target="_blank" rel="noopener noreferrer">Anthropic 定价</a>），与 <a href="/zh-cn/models/claude-sonnet-4-6/">claude-sonnet-4-6</a> 的 ATP 标价相同。</li>
</ul>
<p>多数公司最后是混合使用：整天和模型对话的人用席位，从代码调用模型的应用、自动化与 agent 用 token 计价。</p>
<h2 id="实算对比-40-人团队">实算对比：40 人团队</h2>
<p>假设一个月 21 个工作日，所有请求都使用 claude-sonnet-4-6（$3 / $15）：</p>
<ul>
<li>普通请求为 3,000 输入、600 输出 token：3,000 × $3 ÷ 100 万 + 600 × $15 ÷ 100 万 = $0.009 + $0.009 = $0.018。</li>
<li>长文档请求为 20,000 输入、600 输出 token：$0.06 + $0.009 = $0.069。</li>
</ul>

<p>同样 40 人使用 Claude Team 标准席位，按月付费是 40 × $25 = 每月 $1,000，按年付费是 40 × $20 = $800。</p>
<p>财务可以从这张表看出三点：</p>
<ol>
<li>持平点要逐人看。每次 $0.018 时，用户每月 $25 ÷ $0.018 = 1,389 次请求才与 $25 席位持平，约每个工作日 66 次。每次 $0.069 时约每月 362 次，即每个工作日 17 次。</li>
<li>重度分组每人 token 成本 $57.96，是 $25 席位的两倍以上；轻度分组每人不到 $1。</li>
<li>这个对比只计算模型用量。席位包含厂商的对话应用与功能；token 用量则需要内部工具或集成来调用 API，这部分也有成本。</li>
</ol>
<p>Agent 类工作的量级完全不同。Anthropic 表示 Claude Code 平均每位开发者每个活跃日约 $13，每月约 $150 到 $250（<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code 成本</a>），是上面对话用量的好几倍。编程 agent 请单独列一行预算。</p>
<h2 id="以项目点数做内部分摊">以项目点数做内部分摊</h2>
<p>席位的内部分摊很简单：各部门席位数 × 单价。Token 的分摊多一步，因为花费落在工作负载上，不直接对应到人。月底结账时站得住的做法是：</p>
<ul>
<li>每个工作负载是一个项目、有自己的密钥，每个部门一个工作区。</li>
<li>财务为组织充值，每个项目每月分配一笔点数（1 点 = 0.01 美元）。</li>
<li>各成本中心按实际消耗的点数结算，与分配额无关。</li>
</ul>

<h2 id="token-预算为什么会失准">Token 预算为什么会失准</h2>
<ul>
<li>换模型。proposal-drafts 从 gpt-5.5 换到 claude-sonnet-4-6，用量不变，每次成本从 $0.075 变成 $0.0405。换之前与换之后都可以查看<a href="/zh-cn/models/compare/">模型对比页</a>。</li>
<li>上下文变长。support-bot 的提示从 1,284 涨到 4,000 输入 token，每条回复成本从 $0.010032 变成 $0.01818。</li>
<li>推理 token。OpenAI 与 Anthropic 都把推理 token 按输出计费，开启 extended thinking 可能让输出成本成倍增加，回答看起来却没变。</li>
<li>Agent。每一步都重发上下文；Anthropic 表示在 plan mode 下，agent teams 的 token 用量约为普通会话的 7 倍。</li>
</ul>
<p>每周对比一次已消耗与已分配，四种情况都能在月底前发现。数字怎么读，见 <a href="/zh-cn/blog/how-to-read-your-ai-bill/">LLM token 成本怎么算</a>。</p>
<h2 id="在-atp-token-上怎么设置">在 ATP Token 上怎么设置</h2>
<ol>
<li>创建 Team 组织，每个部门一个工作区、每个工作负载一个项目（<a href="/zh-cn/docs/console-setup/" class="doc-term-def" data-def="账号的最上层，底下再分 工作区 与 项目。">设置组织</a>）。</li>
<li>在账务页充值（最低 5 美元；套餐有 5、50、200、1,000 美元），再从组织把点数分配到工作区与项目（<a href="/zh-cn/docs/topup/" class="doc-term-def" data-def="为钱包加值点数，USD 5 起充值，用多少付多少。">充值与钱包</a>）。充值不可退款。</li>
<li>设置每个项目的可用模型并创建 <code>atp-</code> 密钥，让按密钥的花费等于按项目的花费。</li>
<li>每周在用量页的分配树对比 Allocated 与 Consumed（<a href="/zh-cn/docs/spend/">跟踪花费</a>）。</li>
<li>月底用账务事件结账，按各成本中心消耗的点数分摊（<a href="/zh-cn/docs/credits/" class="doc-term-def" data-def="计费单位。1 点＝USD 0.01；用量依各模型牌价换算成点数扣抵。">点数如何运作</a>）。</li>
</ol>
