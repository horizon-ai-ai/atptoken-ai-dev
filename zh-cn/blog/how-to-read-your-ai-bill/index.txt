<h2 id="token-成本计算公式">token 成本计算公式</h2>
<p>任何按 token 计价的 API，单次请求的成本都来自同样三步：</p>
<ol>
<li>输入成本 = 输入 token × 输入单价 ÷ 1,000,000</li>
<li>输出成本 = 输出 token × 输出单价 ÷ 1,000,000</li>
<li>请求成本 = 输入成本 + 输出成本</li>
</ol>
<p>在 ATP Token 上，这笔费用会以点数从<a class="doc-term" href="/zh-cn/docs/resources/" data-def="权限与帐务的最小单位；金钥、允许模型、点数预算都挂在 project 上。">项目</a>余额中扣除，<a href="/zh-cn/docs/credits/" class="doc-term-def" data-def="计费单位。1 美元 = 100 点；用量依各模型牌价换算成点数扣抵。">1 点 = 0.01 美元</a>。点数 = 美元成本 × 100。</p>
<h3 id="实算-一条客服机器人回复">实算：一条客服机器人回复</h3>
<p>客服机器人发送 1,284 token 的提示（系统提示、检索到的帮助中心片段、客户消息）给 claude-sonnet-4-6，单价为每 100 万 token 输入 $3、输出 $15，拿回 412 token 的回答。</p>
<ul>
<li>输入：1,284 × $3 ÷ 1,000,000 = $0.003852</li>
<li>输出：412 × $15 ÷ 1,000,000 = $0.00618</li>
<li>合计：$0.010032 = 1.0032 点</li>
</ul>
<p>每月 10 万条回复就是 $1,003.20。这笔请求里输出只占 token 数的 24%，却占成本的 61.6%。</p>
<h3 id="可以直接粘贴的-token-成本计算器">可以直接粘贴的 token 成本计算器</h3>
<p>SDK 返回的内容本身就带有 token 数。OpenAI 格式的字段是 <code>usage.prompt_tokens</code> 与 <code>usage.completion_tokens</code>，Anthropic 格式则是 <code>usage.input_tokens</code> 与 <code>usage.output_tokens</code>。</p>
<pre><code class="language-python">RATES = {  # 每 100 万 token 美元：(输入, 输出)，ATP 标价
    &quot;gpt-5.5&quot;: (5.00, 30.00),
    &quot;claude-sonnet-4-6&quot;: (3.00, 15.00),
    &quot;gemini-3-5-flash&quot;: (1.50, 9.00),
    &quot;deepseek-v4-flash&quot;: (0.20, 0.40),
    &quot;qwen-3-7-flash&quot;: (0.03, 0.13),
}

def token_cost(model, input_tokens, output_tokens):
    rate_in, rate_out = RATES[model]
    usd = (input_tokens * rate_in + output_tokens * rate_out) / 1_000_000
    return usd, usd * 100  # (美元, ATP 点数)

print(token_cost(&quot;claude-sonnet-4-6&quot;, 1284, 412))  # 约 (0.010032, 1.0032)
</code></pre>

<h2 id="缓存输入与推理-token">缓存输入与推理 token</h2>
<p>厂商价目表上有两种 token，第一次读账单的人最容易卡住。</p>
<h3 id="缓存输入是厂商的计价功能">缓存输入是厂商的计价功能</h3>
<p>部分厂商对命中缓存的重复提示前缀另定较低单价。OpenAI 列出 GPT-5.5 的缓存输入为每 100 万 token $0.50，普通输入是 $5（<a href="https://developers.openai.com/api/docs/pricing" target="_blank" rel="noopener noreferrer">OpenAI 定价</a>）。Anthropic 多数模型的缓存读取是基础输入单价的 0.1 倍，缓存写入为 1.25 倍（5 分钟）或 2 倍（1 小时）（<a href="https://platform.claude.com/docs/en/about-claude/pricing" target="_blank" rel="noopener noreferrer">Anthropic 定价</a>）。这些是按各厂商缓存规则直接调用时的厂商单价。ATP Token 按<a href="/zh-cn/docs/pricing-model/">计价模式</a>以输入与输出 token 计费，所以 ATP 预算请按输入与输出标价来估算。</p>
<h3 id="推理-token-按输出计费">推理 token 按输出计费</h3>
<p>推理模型回答前会先思考，这些看不见的 token 也要付费。OpenAI 写明推理 token 按输出 token 计费（<a href="https://developers.openai.com/api/docs/guides/reasoning" target="_blank" rel="noopener noreferrer">OpenAI 推理指南</a>），Anthropic 也把 extended thinking 的 token 按输出计费（<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code 成本</a>）。如果上面那条客服回复在 claude-sonnet-4-6 上用了 1,500 个 thinking token，就多出 1,500 × $15 ÷ 1,000,000 = $0.0225，单次成本从 $0.010032 变成 $0.032532，约 3.2 倍。</p>
<p>推理预算也能解释一种让人困惑的日志：返回 <code>200</code> 但内容为空。<code>max_tokens</code> 设得太低时，模型把预算全用在思考上，没有产出文本。在 ATP 上这类请求通常显示零用量、不扣点数；解决方法是调高 <code>max_tokens</code>（<a href="/zh-cn/docs/errors/">错误码</a>）。</p>
<h2 id="单笔请求记录告诉你什么">单笔请求记录告诉你什么</h2>
<p>月度总额只说得出花了多少。单笔请求记录说得出是哪个项目、哪个模型、用了多少 token。下面是示意用的记录，列出计算单次成本需要的字段，并不是 ATP 实际的日志格式。</p>
<pre><code class="language-json">{
  &quot;request_id&quot;: &quot;req_example_01&quot;,
  &quot;project&quot;: &quot;support-bot-prod&quot;,
  &quot;model&quot;: &quot;claude-sonnet-4-6&quot;,
  &quot;input_tokens&quot;: 1284,
  &quot;output_tokens&quot;: 412,
  &quot;cost_usd&quot;: 0.010032,
  &quot;cost_credits&quot;: 1.0032
}
</code></pre>
<p>在 ATP Token 里，这些信息分布在三个地方：</p>
<ul>
<li>请求日志，每次调用一行：时间、范围（工作区与项目）、模型、端点、HTTP 状态、供应商结果、输入与输出 token、计费状态与请求 ID。可按时间范围、范围、模型、状态或请求 ID 筛选（<a href="/zh-cn/docs/monitoring/">用量与日志</a>）。保留 7 天，费用异常要在一周内查。</li>
<li>账务事件，即逐笔计费账本，控制台以 90 天呈现，可按模型、密钥、计费状态或请求 ID 筛选（<a href="/zh-cn/docs/console-api-billing/">账务 API</a>）。计费以这份账本为准。</li>
<li>用量页，按模型与 API 密钥汇总一段时间内的点数与 token。</li>
</ul>
<p>每个响应还带有 <code>x-request-id</code> 头，工程师可以把应用日志里的某次调用，对应到控制台里的那一行。</p>
<h2 id="三种账单异常与排查方法">三种账单异常与排查方法</h2>
<h3 id="某一周费用突然跳升">某一周费用突然跳升</h3>
<p>在用量页按 API 密钥排序。如果密钥和项目一一对应，跳升会立刻落到某个负责人身上。接着在请求日志里筛选该项目，比较跳升前后每次请求的 token 数。输入从约 1,300 涨到 13,000 token，通常是有人开始每一轮都发送整份文档。</p>
<h3 id="单价没错-总额却对不上">单价没错，总额却对不上</h3>
<p>检查模型组合。把 10 万条客服回复中的 20% 从 claude-sonnet-4-6 改到 gpt-5.5，流量不变，当月就从 $1,003.20 变成 $1,178.16。</p>
<h3 id="请求成功却没有文本">请求成功却没有文本</h3>
<p>查找推理模型上输出 token 为零的 <code>200</code> 记录，把 <code>max_tokens</code> 调到足以覆盖思考加回答。</p>
<h2 id="在-atp-token-上怎么设置">在 ATP Token 上怎么设置</h2>
<ol>
<li>每个服务、每个环境各建一个项目，各配一把 <code>atp-</code> 密钥，用量页的「按密钥」就等于「按负责人」。</li>
<li>为每个项目分配点数。分配额就是项目的上限，余额用完时调用会返回 <code>402</code>（<a href="/zh-cn/docs/cb-budget-caps/">预算上限设置</a>）。项目也可以开启自动<a class="doc-term" href="/zh-cn/docs/topup/" data-def="为钱包加值点数，最低 5 美元，用多少付多少。">充值</a>，设置触发阈值与每月上限。</li>
<li>记录每个响应的 <code>usage</code> 与模型 ID，每周按项目运行一次上面的计算器。</li>
<li>月底以账务事件对账，7 天内的细节用请求日志追查。</li>
</ol>
