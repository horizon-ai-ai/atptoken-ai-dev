3:T1128,<p>Agent tax 是多步 AI agent 为完成一项工作，因重送上下文、呼叫工具与重试而产生的额外 token 成本。这份指南写给账单爬升快于纯聊天的工程与财务。</p>
<p>先给答案：单价可跌、agent 账单仍升，因为单位从「一次 completion」变成「一项完成的任务」。量测<strong>每次 agent 任务成本</strong>，设步数与预算天花板，保留逐请求纪录。见<a href="/zh-cn/blog/why-ai-bills-explode-after-go-live">上线后账单为何炸</a>、<a href="/zh-cn/blog/how-to-read-your-ai-bill">读懂 AI 账单</a>。</p>
<h2 id="定义">定义</h2>
<p>单轮聊天付一块输入与输出；agent 可能每轮重读逐字稿、吞工具结果、重试、复制上下文给子 agent。多出来的 token 即 agent tax——架构税，不是供应商加价。</p>
<h2 id="单价跌-账单升">单价跌、账单升</h2>
<p>缺的变数是工作形态。没有上限与归属，形态变成不透明月底总额（<a href="/zh-cn/blog/why-ai-bills-explode-after-go-live">五个缺口</a>）。</p>

<h2 id="常见问题">常见问题</h2>
<h3 id="什么是-ai-的-agent-tax">什么是 AI 的 agent tax？</h3>
<p>Agent tax 是多步 agent 因重送上下文、工具呼叫与重试，超出单次模型回复的额外 token 支出。</p>
<h3 id="为什么-ai-agent-比一般聊天更贵">为什么 AI agent 比一般聊天更贵？</h3>
<p>Agent 可能为同一目标发起多次呼叫，每次带历史与工具结果，任务级 token 会倍增。</p>
<h3 id="怎么量测-agent-tax">怎么量测 agent tax？</h3>
<p>依任务汇总整条链路的 token 与点数，再与单轮基准比；用完成任务成本做共同语言。</p>
<h3 id="如何降低-agent-token-成本">如何降低 agent token 成本？</h3>
<p>限制步数、摘要上下文、子任务用小模型、项目上限，并每周查请求纪录。</p>
<h3 id="agent-tax-等于模型加价吗">Agent tax 等于模型加价吗？</h3>
<p>不是。加价是费率差；agent tax 是架构让同一费率消耗更多 token。</p>
