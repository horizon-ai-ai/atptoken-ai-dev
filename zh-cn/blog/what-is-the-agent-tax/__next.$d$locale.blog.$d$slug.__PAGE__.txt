<h2 id="ai-agent-成本怎么累加-20-步示例">AI agent 成本怎么累加：20 步示例</h2>
<p>假设一个 agent 每项任务从 8,000 token 的基础上下文开始（系统提示、工具定义、任务内容）。每一步附加约 2,000 token 的工具结果和模型输出，每一步写出 500 个输出 token。因此第 <em>i</em> 步读入 8,000 + 2,000 × (i − 1) 个输入 token。</p>
<p>20 步的输入 token：</p>
<p>Σ = 20 × 8,000 + 2,000 × (0 + 1 + … + 19) = 160,000 + 2,000 × 190 = <strong>540,000 token</strong></p>
<p>输出 token：20 × 500 = 10,000。</p>
<p>基础上下文只占输入的 30%（540,000 中的 160,000），另外 70% 是同一批工具结果在后续步骤中被重复读入。仅最后 8 步就读了 312,000 token，比前 12 步加起来（228,000）还多。</p>

<p>同样的基础上下文如果单轮回答，在 claude-sonnet-4-6 上是 8,000 × 3/M + 500 × 15/M = 0.024 + 0.0075 = 0.0315 美元。Agent 任务约是它的 56 倍。这个倍数就是 agent tax：费率没变，变的是 token 数量。</p>
<p>Anthropic 公布过一个实际数据：在 Claude Code 中，队友以 plan 模式运行时，agent teams 的 token 用量约为普通会话的 7 倍，因为每个队友都有自己的上下文窗口（<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code 费用说明</a>）。</p>
<h2 id="降低-agent-tax-的五个做法">降低 agent tax 的五个做法</h2>
<h3 id="1-限制步数">1. 限制步数</h3>
<p>输入大致随步数的平方增长，贵的是后段的步骤。设置硬性上限，达到时返回明确的失败。如果同一项任务 12 步就能完成，输入降到 12 × 8,000 + 2,000 × 66 = 228,000 token，每项任务从 1.77 美元降到 0.77 美元。</p>
<h3 id="2-工具输出进入上下文前先做摘要">2. 工具输出进入上下文前先做摘要</h3>
<p>把完整文件内容和完整 API 响应换成简短摘要，或只保留关键的几行。如果每步增量从 2,000 降到 500 token，输入变成 160,000 + 500 × 190 = 255,000 token：0.765 + 0.15 = 每项任务 0.92 美元，少 48%。</p>
<h3 id="3-子步骤改用更便宜的模型">3. 子步骤改用更便宜的模型</h3>
<p>很多步骤只是读一段工具结果，再决定下一个调用什么。决策步骤留在 claude-sonnet-4-6，其余交给 deepseek-v4-flash。以 6 个决策步骤、14 个子步骤、每步平均 27,000 个输入 token 计：</p>
<ul>
<li>Sonnet：162,000 × 3/M + 3,000 × 15/M = 0.486 + 0.045 = 0.531 美元</li>
<li>Flash：378,000 × 0.2/M + 7,000 × 0.4/M = 0.0756 + 0.0028 = 0.078 美元</li>
<li>合计：每项任务约 0.61 美元，比全用 Sonnet 少 66%</li>
</ul>
<p>切换前先用自己的任务测试质量；<a href="/zh-cn/compare/deepseek-vs-claude/">DeepSeek 与 Claude 对比</a>可以作为起点。</p>
<h3 id="4-在供应商支持时使用-prompt-caching">4. 在供应商支持时使用 prompt caching</h3>
<p>Agent 的大部分输入，是上一步已经发过的前缀。在 Anthropic 自家 API 上，缓存读取的费率是基础输入的 0.1 倍，5 分钟缓存写入是 1.25 倍（<a href="https://platform.claude.com/docs/en/about-claude/pricing" target="_blank" rel="noopener noreferrer">Anthropic 定价</a>）。在 20 步示例中，540,000 个输入 token 有 494,000 个是重复内容。按 Anthropic 的 Sonnet 4.6 费率，是 494,000 × 0.30/M + 46,000 × 3.75/M + 0.15 美元输出 = 0.148 + 0.173 + 0.15，每项任务约 0.47 美元。缓存有存活时间，等待慢速工具的步骤可能错过缓存。依赖这个做法之前，先确认你的供应商如何计算缓存 token。</p>
<h3 id="5-给每个-agent-独立的预算">5. 给每个 agent 独立的预算</h3>
<p>把每个 agent 放进自己的<a class="doc-term" href="/zh-cn/docs/resources/" data-def="权限与帐务的最小单位；密钥、允许模型、点数预算都挂在 项目 上。">项目</a>，并为它分配<a class="doc-term" href="/zh-cn/docs/credits/" data-def="计费单位。1 点＝USD 0.01；用量依各模型牌价换算成点数扣抵。">点数</a>。项目只能花被分配到的额度，余额用完后请求会返回 <code>402</code>，卡住的循环会停在上限，而不是拖到月底才被发现。每月 10,000 项 Sonnet 任务，分配额度就是 1,770,000 点（1 点 = 0.01 美元）。设置方式见<a href="/zh-cn/docs/cb-budget-caps/">设置有预算上限的团队</a>。</p>
<h2 id="如何衡量每项完成任务的成本">如何衡量每项完成任务的成本</h2>
<p>网关看得到请求，但只有你的应用知道哪些请求属于同一项任务。ATP 的每个响应都带有 <code>x-request-id</code> 响应头。把它和你自己的任务或会话 ID、步骤编号，以及任务最终是否成功一起记录。</p>
<p>然后：</p>
<ol>
<li>从请求日志取出这些 request ID 对应的行，每行显示模型、状态和输入／输出 token（<a href="/zh-cn/docs/monitoring/">用量与日志</a>）。日志保留 7 天，请每周用<a href="/zh-cn/docs/console-api-logs/">请求日志 API</a> 导出。</li>
<li>把 token 乘以模型牌价，按任务汇总。</li>
<li>用总成本（包括失败和中途放弃的任务）除以完成的任务数。</li>
</ol>
<p>失败的任务要算进分子。成功率 80%、每次尝试 1.77 美元的 agent，每项完成任务的成本是 1.77 / 0.8 = 2.21 美元。</p>
<p>日志里要留意一种模式：内容为空的 <code>200</code>。在推理模型上，这通常说明 <code>max_tokens</code> 不足以覆盖思考预算。ATP 通常会报告零用量、不扣点数，但不调高 <code>max_tokens</code> 就重试的 agent，会一直重复这个空响应（<a href="/zh-cn/docs/errors/">错误</a>）。</p>
