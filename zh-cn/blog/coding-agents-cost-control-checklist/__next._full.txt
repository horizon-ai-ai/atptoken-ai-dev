<h2 id="claude-code-怎么计费">Claude Code 怎么计费</h2>
<p>截至 2026 年 10 月，Anthropic 的 <a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">Claude Code 费用说明页</a>指出，在企业部署中，平均费用约为每位开发者每个活跃日 13 美元、每月 150–250 美元，且 90% 用户每个活跃日低于 30 美元。Anthropic 建议先用小规模试点团队建立自己的基准，再扩大推广。</p>
<p>费用如何落到你头上，取决于开发者用什么方式登录。Pro 与 Max 订阅已包含用量。Team 与 Enterprise 方案的每位成员使用每个席位的额度，按滚动 5 小时和每周两个窗口重置，并与 Claude 对话共用；只有管理员开启 usage <a class="doc-term" href="/zh-cn/docs/credits/" data-def="计费单位。1 点＝USD 0.01；用量依各模型牌价换算成点数扣抵。">credits</a> 后，成员才能超出额度继续使用。通过 Claude Console、云服务商，或 ATP Token 这类网关使用时，Claude Code 按 token 向<a class="doc-term" href="/zh-cn/docs/console-setup/" data-def="账号的最上层，底下再分 工作区 与 项目。">组织</a>计费。</p>
<p>本文讨论的是按 token 计费的情况：除了你自己设的上限，没有任何东西会让会话停下来。</p>
<h2 id="25-人团队的-claude-code-费用测算">25 人团队的 Claude Code 费用测算</h2>
<p>假设 25 位开发者每月 20 个工作日都使用 Claude Code，按 Anthropic 的平均 13 美元计算：</p>
<p>25 位开发者 × 20 个活跃日 × 13 美元 = <strong>每月 6,500 美元</strong></p>
<p>折合每人 260 美元，略高于 Anthropic 的每月 150–250 美元区间，因为 20 个活跃日假设每个人每个工作日都在用。</p>
<p>平均值会掩盖长尾。假设其中 5 位开发者经常开长会话或同时运行多个实例，费用是平均的 2 倍（每个活跃日 26 美元）：</p>

<h2 id="管控-claude-code-花费的-10-项做法">管控 Claude Code 花费的 10 项做法</h2>
<h3 id="1-给-coding-agent-独立的项目">1. 给 coding agent 独立的项目</h3>
<p>建立一个只给 Claude Code（以及其他 coding agent）使用的<a class="doc-term" href="/zh-cn/docs/resources/" data-def="权限与帐务的最小单位；密钥、允许模型、点数预算都挂在 项目 上。">项目</a>，与生产服务的项目分开。同一项目内的每个密钥都从该项目余额扣费，所以整晚跑循环的 agent 不会把面向客户服务的预算用光。做法见<a href="/zh-cn/blog/one-project-one-key/">一个项目，一个密钥</a>。</p>
<h3 id="2-项目内每位开发者一个密钥">2. 项目内每位开发者一个密钥</h3>
<p>密钥只属于一个项目，并继承该项目的允许模型与余额。每人一个密钥，用量页就能按密钥显示点数与 token，不用另外接工具就看得到每个人的花费。密钥以 <code>atp-</code> 开头，完整密钥只显示一次（<a href="/zh-cn/docs/console-keys/" class="doc-term-def" data-def="以 atp- 开头的密钥，继承所属 项目 的允许模型清单与点数余额。">管理 API 密钥</a>）。</p>
<h3 id="3-把分配额度当作每月上限">3. 把分配额度当作每月上限</h3>
<p>把上表中含重度用户的数字，也就是 780,000 点，分配给这个项目。项目只能花被分配到的额度；余额用完后，请求会返回 <code>402</code>，直到管理员再次分配。如果开启了项目自动充值，也要设置每月上限，否则上限就不再是上限。设置步骤见<a href="/zh-cn/docs/cb-budget-caps/">设置有预算上限的团队</a>。</p>
<h3 id="4-白名单只开-claude-sonnet-4-6-opus-放到另一个项目">4. 白名单只开 claude-sonnet-4-6，Opus 放到另一个项目</h3>
<p>主要的 coding 项目只启用 <a href="/zh-cn/models/claude-sonnet-4-6/">claude-sonnet-4-6</a>。按 ATP 牌价，它是每百万 token 输入 3 美元、输出 15 美元；<a href="/zh-cn/models/claude-opus-4-8/">claude-opus-4-8</a> 则是 5 美元和 25 美元，每个 token 约贵 1.67 倍。如果有人切换到项目未允许的模型，网关会在请求到达任何供应商之前返回 <code>403</code>。需要用 Opus 做架构设计的开发者，另开第二个项目并给较小的额度，例如 50,000 点。</p>
<h3 id="5-固定-anthropic_model">5. 固定 ANTHROPIC_MODEL</h3>
<p>在每位开发者的环境变量，或 <code>~/.claude/settings.json</code> 的 <code>env</code> 区块中设置 <code>ANTHROPIC_MODEL=&quot;claude-sonnet-4-6&quot;</code>。<code>--model</code> 参数会在单个会话中覆盖 <code>ANTHROPIC_MODEL</code>，所以固定模型只决定默认值，真正的限制靠第 4 项的白名单。</p>
<h3 id="6-养成-usage-与-clear-的习惯">6. 养成 /usage 与 /clear 的习惯</h3>
<p><code>/usage</code> 的 Session 区块会显示 token 用量，以及 Claude Code 在本地按牌价估算的金额；项目实际被扣多少，以 ATP 用量页为准。Anthropic 建议的省钱习惯：</p>
<ul>
<li>切换到不相关的工作时执行 <code>/clear</code>。旧的上下文会随每条消息重发，而 <code>/clear</code> 本身不花钱。</li>
<li>简单任务用 <code>/effort</code> 调低思考强度。思考 token 按输出 token 计费。</li>
<li>让 <code>CLAUDE.md</code> 保持精简，把专门的指令移到按需加载的 skills。</li>
</ul>
<h3 id="7-无人值守的运行用-max-budget-usd-与-max-turns-设限">7. 无人值守的运行用 --max-budget-usd 与 --max-turns 设限</h3>
<p>针对 CI 和脚本，Claude Code 的 <a href="https://code.claude.com/docs/en/cli-reference" target="_blank" rel="noopener noreferrer">CLI 参考文档</a>列出两个 print 模式参数：<code>--max-budget-usd</code> 会在估算花费（含 subagent）达到金额时停止；<code>--max-turns</code> 在固定的 agent 轮数后退出。</p>
<pre><code>claude -p --max-budget-usd 5.00 --max-turns 30 &quot;fix the failing tests in src/auth&quot;
</code></pre>
<p>这是客户端的单次停止点。对那种整晚重试修 flaky test 的任务，项目分配额度仍是服务端的上限。</p>
<h3 id="8-agent-teams-改为申请制">8. Agent teams 改为申请制</h3>
<p>Agent teams 默认关闭，用 <code>CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1</code> 开启。在 plan 模式下 token 用量约为普通会话的 7 倍，一位开发者跑 agent team 的花费，约等于七位开发者的普通用量。把它放在有独立额度的另一个项目，并请团队让队友使用 Sonnet、任务完成就关闭队友。</p>
<h3 id="9-每周从请求日志检查花费">9. 每周从请求日志检查花费</h3>
<p>每周一打开用量页，按密钥和模型排序，再看同一周的请求日志。每一行显示时间、范围、模型、状态、request ID 以及输入／输出 token。请求日志保留 7 天，所以每周检查是不漏掉任何请求的最长间隔；要保存历史，可以用<a href="/zh-cn/docs/console-api-logs/">请求日志 API</a> 导出。重点看用量超过团队中位数 2 倍的密钥、计划外的模型，以及连续出现的 <code>4xx</code> 或 <code>5xx</code>。</p>
<h3 id="10-离职时吊销密钥">10. 离职时吊销密钥</h3>
<p>外包人员离开时，在 API 密钥页吊销他的密钥。被吊销的密钥立即失效，并保留在列表中供审计；因为每人一个密钥，其他人的会话不受影响。</p>
<p>第 6 到第 8 项背后的成本结构，见<a href="/zh-cn/blog/what-is-the-agent-tax/">什么是 agent tax</a>；哪类工作该开哪个模型，见<a href="/zh-cn/guides/best-llm-for-coding/">最适合写代码的 LLM 指南</a>。</p>
<h2 id="在-atp-token-上配置-claude-code">在 ATP Token 上配置 Claude Code</h2>
<h3 id="步骤-1-建立项目与分配额度">步骤 1：建立项目与分配额度</h3>
<p>在控制台建立工作区，以及以团队命名的项目（例如 <code>claude-code-platform</code>），只启用 <code>claude-sonnet-4-6</code>，并分配每月点数。</p>
<h3 id="步骤-2-每位开发者发一个密钥">步骤 2：每位开发者发一个密钥</h3>
<p>从项目为每个人创建一个密钥，通过密码管理工具交给本人。完整密钥只会显示一次。</p>
<h3 id="步骤-3-把-claude-code-指向网关">步骤 3：把 Claude Code 指向网关</h3>
<p>Base URL 不加 <code>/v1</code>，因为 Claude Code 会自己补上 <code>/v1/messages</code>。把 <code>ANTHROPIC_API_KEY</code> 清空，避免它优先生效。</p>
<pre><code>export ANTHROPIC_BASE_URL=&quot;https://api.atptoken.ai&quot;
export ANTHROPIC_AUTH_TOKEN=&quot;atp-...&quot;
export ANTHROPIC_API_KEY=&quot;&quot;
export ANTHROPIC_MODEL=&quot;claude-sonnet-4-6&quot;   # any model from GET /v1/models
claude
</code></pre>
<p>同样的值也可以写在 <code>~/.claude/settings.json</code> 的 <code>env</code> 区块。</p>
<h3 id="步骤-4-验证">步骤 4：验证</h3>
<p>运行一次提示，再打开控制台：请求会出现在请求日志里，花掉的点数会出现在用量页。完整步骤见<a href="/zh-cn/docs/cb-claude-code/">在 ATP 上运行 Claude Code</a>。</p>
