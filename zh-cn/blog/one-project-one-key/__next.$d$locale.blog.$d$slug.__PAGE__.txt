<h2 id="需要什么">需要什么</h2>
<p><a href="/zh-cn/docs/console-setup" class="doc-term-def" data-def="帐号的最上层，底下再分 workspace 与 project。">组织设定</a>与<a href="/zh-cn/docs/console-keys" class="doc-term-def" data-def="以 atp- 开头的金钥，继承所属 project 的允许模型清单与点数余额。">管理密钥</a>：组织→工作区→项目→密钥；密文只显示一次、可立即撤销、名册留稽核。</p>
<h2 id="依环境">依环境</h2>

<h2 id="常见问题">常见问题</h2>
<h3 id="一项目一密钥是什么意思">一项目一密钥是什么意思？</h3>
<p>每个正式工作负载有一把项目级 API 密钥，继承该项目的模型白名单与点数余额，让花费与存取都有明确主人。</p>
<h3 id="为什么共用-api-密钥有风险">为什么共用 API 密钥有风险？</h3>
<p>无法知道哪个系统在烧 token、离职时不敢撤销，外泄时爆炸半径是全公司。</p>
<h3 id="企业应如何核发-llm-api-密钥">企业应如何核发 LLM API 密钥？</h3>
<p>每系统一项目、只开需要的模型、分配预算、密钥只显示一次、放进密钥管理，项目结束即撤销。</p>
<h3 id="密钥跟项目走时-人员离职怎么办">密钥跟项目走时，人员离职怎么办？</h3>
<p>移除成员或项目存取即可，不必轮替半公司依赖的那把共用 key。</p>
<h3 id="如何从共用密钥迁移">如何从共用密钥迁移？</h3>
<p>盘点呼叫端、为每系统建项目密钥、双跑、逐系统切流，最后撤销共用 key 并留稽核。</p>
