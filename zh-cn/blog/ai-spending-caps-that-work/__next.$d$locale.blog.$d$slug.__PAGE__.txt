<p>工程师最容易忽略的是状态码这一列，而它决定了客户端接下来怎么做。429 看起来像普通的速率限制，多数 SDK 会自动重试。Anthropic 文档特别说明，花费等级上限的 429 不带 <code>retry-after</code> 头，在恢复之前重试都会失败。402 或 400 重试也不会成功。客户端应该读取错误内容，然后停下来。</p>
<h2 id="各平台如何执行花费上限">各平台如何执行花费上限</h2>
<h3 id="openai-项目花费上限">OpenAI：项目花费上限</h3>
<p>OpenAI 建议把 staging 与生产环境分成不同项目，并且可以<a href="https://developers.openai.com/api/docs/guides/production-best-practices" target="_blank" rel="noopener noreferrer">为每个项目设置自定义的速率与花费上限</a>。在项目的 Limits 设置中，可以设置每月花费上限、通知阈值，以及该项目能用哪些模型（<a href="https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform" target="_blank" rel="noopener noreferrer">OpenAI Help Center</a>）。</p>
<p>花费提醒会发通知，流量照常。硬性花费上限会让受影响的请求返回 429。两者之上还有用量等级：Tier 1 每月 USD 100，Tier 5 每月 USD 200,000。需要注意的是状态码共用。处理速率限制的重试循环，如果不检查错误内容，会一直调用一个预算已经用完的项目。</p>
<h3 id="anthropic-console-工作区花费上限">Anthropic Console：工作区花费上限</h3>
<p>Claude Console 的<a href="https://platform.claude.com/docs/en/manage-claude/workspaces" target="_blank" rel="noopener noreferrer">工作区</a>各自有每月花费上限与速率上限，只能设得比组织低，不能更高。API 密钥可以限定在单个工作区。Default Workspace 无法设置上限，所以需要被管住的密钥要放在具名的工作区。</p>
<p>达到你自己设置的上限时，请求返回 HTTP 400（<code>invalid_request_error</code>），信息里会写明何时恢复。等级上限（Start 每月 USD 500、Build USD 1,000、Scale USD 200,000）则返回 429，用量暂停到下个月 1 日 00:00 UTC。Console 自动创建的 Claude Code 工作区，是唯一支持每位用户每月花费上限的工作区。</p>
<h3 id="openrouter-guardrails-与单个密钥点数上限">OpenRouter：guardrails 与单个密钥点数上限</h3>
<p>OpenRouter 有两套机制。Guardrails 由组织管理员针对成员或密钥设置，可以带一个每日、每周或每月重置的美元花费上限；超出的请求收到 403。Guardrail 也能放模型白名单与供应商白名单，多个 guardrail 同时适用时，以最严格的规则为准。</p>
<p>单个密钥点数上限所有套餐都能用。每个密钥有 <code>limit</code> 与 <code>limit_reset</code>（每日、每周、每月或不重置），在 UTC 午夜重置。额度用完的密钥返回 402。工作区级别预算则是 Enterprise 功能（<a href="https://openrouter.ai/blog/insights/governing-team-ai-spend/" target="_blank" rel="noopener noreferrer">OpenRouter 博客</a>）。</p>
<h3 id="vercel-ai-gateway-叠加的预算">Vercel AI Gateway：叠加的预算</h3>
<p>Vercel 的预算有四种范围（团队、项目、API 密钥、团队成员），并且会叠加，一笔请求必须通过范围内的每一个预算。重置周期可选每日、每周、每月或不重置，均以 UTC 计。超出预算返回 402 与 <code>quota_for_entity_exceeded</code>，信息会写出是哪个范围用完。</p>
<p>Vercel 把预算定位为软上限：检查发生在每笔请求开始时，所以跨过上限的那一笔仍会完成。可选的邮件提醒在 50%、75%、100% 触发。有两个细节容易踩坑：API 密钥的花费永远不会计入项目预算（项目预算只看该项目部署的 OIDC token），BYOK 的花费也不计入任何预算。</p>
<h3 id="atp-token-每个项目的预付分配">ATP Token：每个项目的预付分配</h3>
<p>在 ATP Token，上限就是钱本身。点数（1 点 = USD 0.01）由组织拨到工作区、再拨到项目，每个密钥都从自己项目的余额扣。项目只能花掉分配给它的额度。余额用尽时，网关在计量阶段以 402 拒绝请求（<a href="/zh-cn/docs/how-it-works/">工作原理</a>）。花费超过分配额度的项目会被标记为 In debt，直到补足为止。</p>
<p>这里没有重置周期。按量付费点数不会过期，没用完的分配会留到下个月。所以月度预算需要每月做一次分配，或使用项目自动<a class="doc-term" href="/zh-cn/docs/topup/" data-def="为钱包加值点数，USD 5 起充值，用多少付多少。">充值</a>：按量付费的项目在余额低于阈值时自动补点，受单次扣款上限与每月扣款上限约束。开启自动充值后，真正的天花板是那个每月扣款上限。</p>
<h2 id="团队愿意遵守的上限设计原则">团队愿意遵守的上限设计原则</h2>
<ol>
<li><strong>每个工作负载分开设上限。</strong> 每个生产服务一个项目，staging 一个，每个沙箱一个。组织级别的总上限一触发，所有产品会一起停，包括正常运行的那些。密钥部分见<a href="/zh-cn/blog/one-project-one-key/">一项目一密钥</a>。</li>
<li>在客户端代码里把预算错误当作终止状态。402、Anthropic 的 400 上限错误、花费上限导致的 429，都对应到“停止并通知负责人”，不要套用指数退避重试。</li>
<li>每个上限都从单位成本推算。每笔请求的 token 数乘以模型费率，再乘以预估量，得到一个能向财务解释、流量变化时也能调整的数字。</li>
<li>在最上层保留未分配的备用额度。生产环境如果在 27 号见底，管理员几分钟内就能拨点过去，不必动 staging。</li>
<li>每周对照一次 Allocated 与 Consumed。ATP Token 的<a href="/zh-cn/docs/spend/">用量页面</a>在每一层都同时显示两者。想要自动告警的话，可以通过 <a href="/zh-cn/docs/console-api-usage/">Console API</a> 轮询项目实时余额，推送到你自己的频道。</li>
</ol>
<h2 id="实际算一次-每月-usd-2-000-的-ai-预算换成点数">实际算一次：每月 USD 2,000 的 AI 预算换成点数</h2>

<p>客服机器人。claude-haiku-4-5 的 ATP 标价是每百万输入 token USD 1、每百万输出 token USD 5。一条典型回复用 2,000 个输入 token、300 个输出 token，成本是 2,000 × 1 / 1,000,000 + 300 × 5 / 1,000,000 = USD 0.0035，也就是 0.35 点。140,000 点 ÷ 0.35 = 每月 400,000 条回复，约每天 13,300 条。</p>
<p>整个周末都在跑的 staging 任务。假设一个重试 bug 每秒发 5 次请求，每次同样 0.35 点，相当于每秒烧掉 1.75 点，10,000 点的 staging 分配大约撑 10,000 ÷ 1.75 ≈ 5,700 秒，约 95 分钟。之后 staging 收到 402，生产环境照常回复客户。如果没有拆开，同一个循环从周五 18:00 跑到周一 09:00（63 小时，226,800 秒），会花掉 226,800 × 1.75 = 396,900 点，几乎是整月预算的两倍。</p>
<p>Coding agent。Anthropic 公布的 Claude Code 平均成本是<a href="https://code.claude.com/docs/en/costs" target="_blank" rel="noopener noreferrer">每位开发者每个活跃日约 USD 13</a>。按这个平均值，USD 300 约可支撑 23 个开发者工作日，大约是一位开发者一个月的工作日。沙箱在下午撞到 402 时，先看那个 session 在做什么，再决定要不要补点。为什么 agent 每项任务比单次调用贵，见<a href="/zh-cn/blog/what-is-the-agent-tax/">什么是 agent 税</a>。</p>
<p>下个月 1 日不会重置任何东西。如果客服机器人用掉 120,000 点，它还剩 20,000 点；再拨 120,000 点就回到 140,000。</p>
<h2 id="在-atp-token-上怎么设置">在 ATP Token 上怎么设置</h2>
<ol>
<li>创建 Team 组织，再到 Resources 页面创建工作区（Production、Pre-production、Engineering）（<a href="/zh-cn/docs/console-setup/" class="doc-term-def" data-def="账号的最上层，底下再分 工作区 与 项目。">设置组织</a>）。</li>
<li>创建每个项目并选择允许的模型，每个项目至少一个（<a href="/zh-cn/docs/resources/" class="doc-term-def" data-def="这个 项目 可以呼叫的模型清单；不在清单上的一律回 403。">工作区与项目</a>）。</li>
<li>沿着树状结构分配点数：组织、工作区、项目。备用额度留在组织层，不要分出去。</li>
<li>每个项目发一个密钥，密钥继承该项目的模型与余额（<a href="/zh-cn/docs/console-keys/" class="doc-term-def" data-def="以 atp- 开头的密钥，继承所属 项目 的允许模型清单与点数余额。">管理 API 密钥</a>）。</li>
<li>在客户端把 402 视为“预算用尽”，并通知项目负责人（<a href="/zh-cn/docs/errors/">常见响应</a>）。</li>
</ol>
