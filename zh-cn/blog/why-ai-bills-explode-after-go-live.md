# 为什么 LLM 成本在上线后暴涨：五个控制缺口与一个测算示例（2026）

> 来源: https://atptoken.ai/zh-cn/blog/why-ai-bills-explode-after-go-live/
> 发表于: 2026-07-29 · 作者: hung-chien (AI 增长与品牌经理)

LLM 成本常在上线后跳涨，因为提示变长。RAG 客服机器人的输入从 2k 增加到 9k token，每月就多 25,200 美元。五个控制缺口与五天修补计划。

## 重点摘要

- 上线后 LLM 成本上升，是因为真实用户改变了每个请求的 token 形态，而密钥与花费上限仍停留在试点阶段的设置。
- 测算：每天 40,000 个请求的客服机器人，平均输入从 2,000 增加到 9,000 token，在 claude-sonnet-4-6 上每月从 14,400 美元变成 39,600 美元。
- 用五个工作日补上五个缺口：盘点密钥、拆分项目、分配上限、收窄白名单，最后记录 request ID 并每周检查。

LLM 成本在上线后暴涨，是因为生产流量改变了每个请求携带的 token 数，而能控制它的密钥、上限和模型限制，仍停留在试点阶段的设置。费率表很少变动。本文先测算一次真实的上线后暴涨，再逐一说明五个控制缺口的症状、修法，以及五天内补齐的计划。

| 缺口 | 上线后的症状 | 修法 |
|---|---|---|
| 1. 共用密钥 | 一个密钥占了大部分花费，吊销它会让好几个服务中断 | 每个系统一个项目、一个密钥 |
| 2. 没有上限 | 第一个警报是账单 | 以项目分配额度作为上限 |
| 3. 没有逐请求记录 | 没人说得清账单为何接近三倍 | 每次调用记录 request ID 和 token |
| 4. 没有模型白名单 | 生产环境出现昂贵模型 | 每个项目的允许模型列表 |
| 5. 没有检查节奏 | 问题拖到月底才暴露 | 在日志保留期内每周检查 |

## 上线后 LLM 成本暴涨的测算

一个客服机器人在 [claude-sonnet-4-6](https://atptoken.ai/zh-cn/models/claude-sonnet-4-6/) 上用检索增强生成（RAG）回答问题；截至 2026 年 10 月，ATP 牌价为每百万 token 输入 3 美元、输出 15 美元。它每天处理 40,000 个请求，每条回答约写出 400 个输出 token。

试点期间，平均每个请求带 2,000 个输入 token。上线后，用户把合同和整串邮件粘贴进对话，检索也为了回答更长的问题加入更多片段。平均输入增加到 9,000 token。

| | 上线前 | 上线后 |
|---|---|---|
| 每日输入 token | 40,000 × 2,000 = 80M | 40,000 × 9,000 = 360M |
| 每日输入成本 | 80 × 3 = 240 美元 | 360 × 3 = 1,080 美元 |
| 每日输出成本 | 16M × 15/M = 240 美元 | 16M × 15/M = 240 美元 |
| 每日合计 | 480 美元 | 1,320 美元 |
| 每月（30 天） | 14,400 美元 | 39,600 美元 |
| 每月 ATP 点数 | 1,440,000 | 3,960,000 |

每月差额是 25,200 美元，账单变成 2.75 倍。模型、价格和请求数都没有变化，任何价格表都不会提醒你。唯一的信号是每个请求的平均输入 token，而只有逐次记录 token，你才看得到它。

## 缺口 1：共用密钥，花费没有归属

症状：用量页显示当月大部分 token 都来自同一个密钥。三个服务、一个定时任务，还有一位外包人员的 notebook 都在用它。外包人员离开时，吊销这个密钥会让生产环境当天下午就中断，所以没人动手。

上线后为何更糟：试点期流量小，共用的代价不明显。上线后任何一个调用方都可能突增，而唯一的手段是给所有人关掉这个密钥。

修法：以项目作为归属单位，每个生产系统一个项目、一个自己的密钥。密钥只属于一个项目，并继承该项目的允许模型和余额；API 密钥页会列出所有工作区和项目中的每个密钥（[管理 API 密钥](https://atptoken.ai/zh-cn/docs/console-keys)）。被吊销的密钥立即失效，并保留在列表中供审计。

## 缺口 2：没有上限，账单就是警报

症状：那个跑了整个周末的 staging 任务。一个重试循环每秒发出 2 个请求，持续 48 小时：345,600 个请求，每个在 claude-sonnet-4-6 上带 3,000 个输入和 300 个输出 token。每个请求 0.009 + 0.0045 = 0.0135 美元，整个周末花了 4,665.60 美元，周一才被发现。

上线后为何更糟：批处理任务、agent 和重试都在无人看管时运行。每个工作负载没有上限，一条热路径就会动用整个组织的余额。

修法：沿着组织、工作区、项目的层级分配点数，把每个项目的分配额度当作上限。项目只能花被分配到的额度；余额用完时，请求会返回 `402`。如果 staging 只分配 50,000 点（500 美元），同一个循环约在 37,000 个请求、大约 5 小时后就会停下。步骤见[设置有预算上限的团队](https://atptoken.ai/zh-cn/docs/cb-budget-caps)。每一层的已分配与已消耗都显示在用量页（[点数如何运作](https://atptoken.ai/zh-cn/docs/credits)）。

## 缺口 3：没有逐请求记录，月账单无法自我解释

症状：财务看到机器人从 14,400 美元变成 39,600 美元。工程团队说什么都没变：同一个模型、同一个价格。会议结束时仍找不到原因。

上线后为何更糟：上线同时带来很多变化：更长的提示、新的检索设置、重试策略、更多用户。月度总额无法把它们区分开。

修法：每次调用都记录项目、密钥、模型、状态和输入／输出 token。ATP 的请求日志正是逐请求显示这些字段，可按时间范围、范围、模型、状态和 request ID 筛选（[用量与日志](https://atptoken.ai/zh-cn/docs/monitoring)）。以上面的例子来说，把请求日志筛选到机器人的项目，会看到每行约带 9,000 个输入 token。对照试点期记下的 2,000，几分钟内就能回答问题，前提是有人把试点期的数字记了下来。请把“每个项目每个请求的平均输入 token”作为每周跟踪的数字。

## 缺口 4：没有模型白名单，昂贵路径变成默认

症状：政策写着默认用中档模型。接着某位开发者为了处理一条语气投诉，把机器人换成更强的模型，然后就上线了。

上线后为何更糟：流量会放大模型之间的价差。同样的上线后流量（每天 40,000 个请求、输入 9,000 和输出 400 token），成本差异很大：

| 模型（ATP 牌价） | 每日 | 每月 |
|---|---|---|
| [claude-haiku-4-5](https://atptoken.ai/zh-cn/models/claude-haiku-4-5/)（1／5 美元） | 360 + 80 = 440 美元 | 13,200 美元 |
| claude-sonnet-4-6（3／15 美元） | 1,080 + 240 = 1,320 美元 | 39,600 美元 |
| claude-opus-4-8（5／25 美元） | 1,800 + 400 = 2,200 美元 | 66,000 美元 |

修法：每个项目维护一份允许模型列表。列表外的模型请求会在到达任何供应商之前被以 `403` 拒绝（[工作原理](https://atptoken.ai/zh-cn/docs/how-it-works)）。`GET /v1/models` 会列出密钥可以调用的模型。这样一来，更换机器人的模型就成为由管理员在项目上做的变更，而不是一行代码的修改。

## 缺口 5：没有检查节奏，问题等到账单才出现

症状：两次账单之间没人打开用量页。为一次性迁移调高的上限一直没有调回，已结束试点的闲置密钥仍然有效。

上线后为何更糟：上线前检查过一次的控制，之后会慢慢偏移：新的密钥、更宽的白名单、更大的分配额度。

修法：建立轻量、固定的节奏：

| 频率 | 检查什么 | 负责人 |
|---|---|---|
| 每周 | 按项目、模型、密钥看用量；在过期前看请求日志（保留 7 天）；每个请求的平均输入 token | 平台团队 |
| 每月 | 每个项目的已分配与已消耗；被标为 In debt 的项目；没有流量的密钥 | 财务与平台 |
| 每季度 | 每个项目的角色与成员；白名单；没有负责人的项目 | 安全与平台 |

活动日志会记录登录、邀请、额度变更和资源更新，覆盖每季度检查的大部分内容。

## 五个工作日补上五个缺口

### 第 1 天（周一）：盘点

打开 API 密钥页，它会列出所有工作区和项目中的每个密钥。逐一记下每个密钥被哪些系统使用、负责人是谁，并标出被多个系统共用的密钥。

### 第 2 天（周二）：拆分

为每个生产系统建立一个项目并发放新密钥。先迁移花费最高的服务，并为每个共用密钥定好吊销日期。

### 第 3 天（周三）：分配上限

取每个项目过去 30 天的消耗量，加上预计增长的余量，分配为每月上限。以上线后的客服机器人为例，至少是 3,960,000 点。staging 和实验项目只给小额分配。

### 第 4 天（周四）：收窄白名单

每个项目只启用需要的模型。从每个项目调用一次不在列表上的模型，确认会得到 `403`。

### 第 5 天（周五）：埋点与排期

把每个响应的 `x-request-id` 响应头，和你自己的功能或租户 ID 一起记录。把每周检查排进日历，并完整演练一次密钥吊销：吊销、查日志、重新发放。

同一个问题在每一步层面的版本，见[什么是 agent tax](https://atptoken.ai/zh-cn/blog/what-is-the-agent-tax)。要建立第一个项目和密钥，请按照[快速开始](https://atptoken.ai/zh-cn/docs/quickstart)。

## 常见问题

### 为什么 LLM API 成本在上线后增加？

单价通常没变，变的是每个请求的 token 数。用户粘贴文档、对话越来越长、重试与 agent 步骤让调用次数成倍增加，更多团队开始共用同一个密钥，于是同一张费率表作用在多得多的 token 上。

### 怎么估算每月 LLM 成本？

每日请求数 ×（平均输入 token × 输入费率 + 平均输出 token × 输出费率）÷ 1,000,000，再乘以 30。每天 40,000 个请求、输入 9,000 和输出 400 token、费率 3／15 美元的模型，就是每天 1,320 美元、每月 39,600 美元。

### 企业应该在哪一层设 AI 花费上限？

设在项目或工作负载层，让每个系统有自己的上限。整个组织只有一个上限，只能告诉你钱用完了，却无法告诉你该放慢哪个系统、吊销哪个密钥。

### 不用网关也能补上这些缺口吗？

能补上一部分。你可以用表格盘点密钥、使用各原厂的项目上限，并把请求日志接入现有的监控系统。网关则把多家供应商的密钥、白名单与上限集中在一处，让它们默认就开启，而不是靠人工维护。
