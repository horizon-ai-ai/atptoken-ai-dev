03 / 选用

什么时候选哪个

按厂商文档整理各家族更适合的场景。价格以外的事实都列在下方资料来源。

选 Kimi，如果你要

  • 把工作并行分派出去的智能体群。Moonshot 表示 Kimi K2.6 可扩展到 300 个子智能体、执行 4,000 个协同步骤。
  • 以开放权重模型运行的长程编程智能体：Kimi K2.7 Code 是 Moonshot 以 K2.6 为基础的编程专用版，思考始终开启、上下文 256K；Moonshot 自报 Kimi Code Bench v2 得分 62.0（K2.6 为 50.9）。
  • 希望模型组合里有开放权重选项的团队：K2.6 与 K2.7 Code 以 Modified MIT 许可发布，之后也能自行部署同一个模型。
  • 快速的文本＋工具调用：ATP 上的 K2.6 不开思考模式，对应 Moonshot 的 instant 模式。
全部 Kimi 模型

选 Claude，如果你要

  • 需要 1M Token 窗口的智能体式编程：Anthropic 文档记载 Sonnet 5、Sonnet 4.6、Opus 4.7、Opus 4.8 与 Fable 5 都是 1M 上下文。
  • 智能体执行中需要图片与截图输入——ATP 目录中这里的每个 Claude 模型都标示视觉能力。
  • 电脑操作——操作浏览器、终端与实际软件——是 Sonnet 4.6、Sonnet 5 与 Opus 4.8 文档明列的重点。
  • 重复前缀的智能体循环：Claude 在 ATP 上同时列出缓存读与缓存写入（5 分钟、1 小时）费率，长的共享上下文在命中时会便宜很多。

04 / 治理

一个密钥，两个都用

通常不必只选一个。在 ATP 上两个家族都在同一个端点、同一个项目密钥后面——每个任务送到最适合的模型，依然只有一份预算、一份允许清单、一份记录。

  • 一个项目密钥——用量与撤销都绑定在单一项目
  • 模型允许清单——只有你开启的模型代号能被调用，其余返回 403
  • 项目预算——点数由组织 → 工作区 → 项目往下配额，配额就是上限
  • 逐请求记录、一张账单——两家厂商的每次调用都记下模型、密钥、项目与点数
two_models.py · OpenAI SDK
from openai import OpenAI

# one project key; both ids must be on the project's allowlist
client = OpenAI(base_url="https://api.atptoken.ai/v1", api_key="atp-•••")

def ask(model, prompt):
    r = client.chat.completions.create(
        model=model, messages=[{"role": "user", "content": prompt}]
    )
    return r.choices[0].message.content

draft = ask("kimi-k2.7-code", "Summarize this ticket…")
final = ask("claude-sonnet-5", "Review: " + draft)

# both calls: same log, same credit balance, same budget

Kimi 和 Claude 哪个更便宜？
按 ATP 价格（USD／每百万 Token）计，Kimi 从 kimi-k2.6 的 $0.95 / $4.00 到 kimi-k3 的 $3.00 / $15.00；Claude 从 claude-haiku-4-5 的 $1.00 / $5.00 到 claude-fable-5 的 $10.00 / $50.00。实际谁更便宜，取决于你的输入／输出比例与需要哪一档模型——本页的试算器会用同一份工作量把每个模型都算一遍。
Kimi 和 Claude 哪个上下文更长？
有文档记载的上下文长度——Kimi：Kimi K2.6 262K。Claude：Claude Opus 5 1M、Claude Opus 4.8 1M、Claude Opus 4.7 1M、Claude Sonnet 5 1M、Claude Haiku 4.5 200K。—：原厂未公布。
Kimi 是开源的吗？
Kimi K2.6 与 K2.7 Code 是开放权重：Moonshot 在 Hugging Face 以 Modified MIT 许可公开权重。在 ATP 上，你用项目密钥把它们当托管 API 调用，跟调用 Claude 一样，不用自己部署。
Kimi 和 Claude 可以用同一个 API 密钥吗？
可以。在 ATP 上两个家族都在同一个 OpenAI 兼容端点（https://api.atptoken.ai/v1）后面，Anthropic 格式的客户端也能走 /v1/messages。一个项目密钥可以调用该项目模型允许清单上的任何模型；每笔请求都写进同一份逐请求记录、从同一个点数余额扣款。
怎么让团队只用我们批准的模型？
用项目的模型允许清单：只开启批准过的模型代号，调用其他代号会被拒绝（403）。再给项目一笔独立的点数配额，预算就是上限；每个模型花了多少，逐请求记录里都看得到。
