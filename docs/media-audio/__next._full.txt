23:T57f,<p>Text-to-speech is <strong>asynchronous</strong> — there is no synchronous version. Like image and video, it takes three steps: create a task (<code>202</code> + an <code>aud_…</code> task id), poll until the status is terminal, then download the <strong>top-level <code>audio_url</code></strong> within 24 hours. Same base URL and <code>atp-</code> key as image generation.</p>
<ul>
<li><strong>Output is a signed URL (<code>https://media-&lt;env&gt;.atptoken.ai/v/...</code>) valid for 24 hours</strong> — never inline base64. Download it if you need to keep it.</li>
<li>Requests are refused with <code>402 insufficient_quota</code> when the <a class="doc-term" href="/docs/resources/" data-def="The unit that permissions and billing hang off — keys, allowed models, and credit budget all belong to one.">project</a> balance is ≤ 0.</li>
<li><code>callback_url</code> is accepted but <strong>no webhook is ever sent</strong>. You must poll.</li>
</ul>
<p>Why it&#39;s asynchronous: speech sends no bytes until the whole clip is synthesized, so long text can&#39;t survive the connection&#39;s idle timeout. Queue-and-poll is what makes long text possible.</p>
