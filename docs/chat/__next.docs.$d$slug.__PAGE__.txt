<p><code>POST /v1/responses</code> is the same SDK&#39;s other entry point (the OpenAI Responses API), not a different model family. The body differs from chat completions:</p>
<ul>
<li><code>input</code> instead of <code>messages</code>.</li>
<li><code>instructions</code> for the system prompt.</li>
<li><code>max_output_tokens</code> for the output limit.</li>
<li>Flat function tools: <code>{type:&quot;function&quot;, name, parameters}</code>.</li>
<li>Stateless: <code>store</code> and <code>previous_response_id</code> are ignored, so send the full <code>input</code> every turn.</li>
</ul>
<p><code>stream</code> defaults to <strong><code>false</code></strong> on <code>/v1/responses</code> — the opposite of <code>/v1/chat/completions</code>. Moving code between the two silently flips streaming, so send <code>stream</code> explicitly on both.</p>
