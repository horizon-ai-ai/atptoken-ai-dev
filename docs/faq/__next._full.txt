25:T1f66,<p>Short answers to common questions about connecting to the Gateway, which models you can call, and how usage is billed.</p>
<h2 data-md="h2" id="connecting-to-the-gateway" class="group">Connecting to the Gateway<a href="#connecting-to-the-gateway" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<h3 data-md="h3" id="is-there-an-mcp-server" class="group">Is there an MCP server?<a href="#is-there-an-mcp-server" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>Yes: <code>atptoken-api-docs</code> at <code>https://mcp.atptoken.ai/mcp</code>. It gives Claude Code, Codex and other agents the API guide, a live model check and a video-request checker. Adding it needs no key; only the live model check asks for your key. Setup for each tool is in <a href="/docs/mcp/">Add the ATP MCP server</a>.</p>
<h3 data-md="h3" id="do-i-need-a-special-sdk" class="group">Do I need a special SDK?<a href="#do-i-need-a-special-sdk" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>No. The official OpenAI, Anthropic, and Google GenAI (<code>google-genai</code>) SDKs work unchanged — point them at the Gateway base URL and use a <a class="doc-term" href="/docs/console-keys/" data-def="A key that starts with atp-. It inherits its project's allowed models and credit balance.">project API key</a>. The older <code>google-generativeai</code> package is deprecated. Each model is served through one SDK and one entrypoint; call the wrong one and you get <code>422</code> naming the right one. See <a href="/docs/agents/">Integrations</a>.</p>
<h3 data-md="h3" id="what-is-the-base-url" class="group">What is the base URL?<a href="#what-is-the-base-url" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p><code>https://api.atptoken.ai</code> for the Anthropic and Gemini formats (Gemini also needs <code>apiVersion: &quot;v1beta&quot;</code>), and <code>https://api.atptoken.ai/v1</code> for the OpenAI format. Each SDK page shows the exact value. The domain serves only <code>/v1*</code> and <code>/omni/*</code>; any other path, such as <code>/api</code>, returns <code>404</code>.</p>
<h3 data-md="h3" id="can-i-stream-responses" class="group">Can I stream responses?<a href="#can-i-stream-responses" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>Yes, and always set <code>stream</code> explicitly. On <code>/v1/chat/completions</code> and <code>/v1/messages</code> it defaults to <code>true</code> (the opposite of OpenAI&#39;s and Anthropic&#39;s own APIs); on <code>/v1/responses</code> it defaults to <code>false</code>. Gemini has no <code>stream</code> field — switch to the <code>:streamGenerateContent</code> endpoint. See <a href="/docs/sse-openai/">OpenAI SSE</a> and <a href="/docs/sse-anthropic/">Anthropic SSE</a>.</p>
<h2 data-md="h2" id="models-and-availability" class="group">Models and availability<a href="#models-and-availability" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<h3 data-md="h3" id="which-models-can-my-key-call" class="group">Which models can my key call?<a href="#which-models-can-my-key-call" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>Only the models on its project&#39;s allowed list. <code>GET /v1/project/models</code> with the same key returns that full list — chat, media and embedding models together. <code>GET /v1/models</code> is only OpenAI&#39;s list: it shows the chat models served on <code>/v1/chat/completions</code> and <code>/v1/responses</code>, so most <code>claude-*</code> models (on <code>/v1/messages</code>), Gemini models (on <code>/v1beta/models</code>), and media and embedding models are not on it. A model missing from a list is not necessarily unusable; if the project really isn&#39;t allowed to call it, the create request returns <code>403</code> and nothing is billed. See <a href="/docs/models/">Model discovery</a>.</p>
<h3 data-md="h3" id="what-happens-if-a-provider-is-down" class="group">What happens if a provider is down?<a href="#what-happens-if-a-provider-is-down" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>Each model is served by a pool of providers and the Gateway fails over automatically. If every provider for a model is unavailable you get a <code>503</code> with <code>Retry-After</code>. See <a href="/docs/provider-routing/">Provider routing</a>.</p>
<h3 data-md="h3" id="why-did-a-reasoning-model-return-200-with-an-empty-message" class="group">Why did a reasoning model return 200 with an empty message?<a href="#why-did-a-reasoning-model-return-200-with-an-empty-message" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p><code>max_tokens</code> was too low. Reasoning (extended-thinking) models spend their thinking inside that budget; when it runs out before any visible output, you get an empty <code>200</code> — typically with zero usage and no <a class="doc-term" href="/docs/credits/" data-def="The billing unit. 1 USD = 100 credits; usage converts at each model's list rate.">credits</a> deducted. Raise <code>max_tokens</code> to cover thinking plus your expected output. See <a href="/docs/errors/">Common responses</a>.</p>
<h3 data-md="h3" id="does-atp-token-only-serve-text-models" class="group">Does ATP Token only serve text models?<a href="#does-atp-token-only-serve-text-models" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>No. The catalog also includes image, video, audio (TTS) and embedding models. Media is asynchronous only: create a task, poll it, then download from a signed URL within 24 hours. See <a href="/docs/media/">Media models</a> for what each modality does and how it is billed.</p>
<h2 data-md="h2" id="billing-and-usage" class="group">Billing and usage<a href="#billing-and-usage" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h2>
<h3 data-md="h3" id="how-am-i-billed-and-are-credits-refundable" class="group">How am I billed, and are credits refundable?<a href="#how-am-i-billed-and-are-credits-refundable" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>Usage is metered on input + output tokens and paid in credits (1 credit = USD 0.01). <a class="doc-term" href="/docs/topup/" data-def="Adding credits to the wallet. Minimum 5 USD, pay as you go.">Top-ups</a> and credits are non-refundable. See <a href="/docs/credits/">How credits work</a> and <a href="/docs/topup/">Top up &amp; wallet</a>.</p>
<h3 data-md="h3" id="how-do-i-see-what-i-spent" class="group">How do I see what I spent?<a href="#how-do-i-see-what-i-spent" aria-label="Link to this section" class="ml-2 text-sand opacity-0 group-hover:opacity-100 focus-visible:opacity-100 touch:opacity-60">#</a></h3>
<p>The Usage page summarizes credits and tokens by model and by key; request logs give a per-request audit trail. Billing is per request, not per attempt: one request can show up as several rows in your records, so don&#39;t add them up.
